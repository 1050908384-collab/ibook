## 2.1 最简命令：`nvidia-smi`

在 Linux 终端里，输入下面这行命令，然后按回车：

```bash
nvidia-smi
```

就这么简单。执行后，屏幕上会输出一个表格，里面显示了当前 GPU 的状态信息。

**这个表格里你能看到什么？**

- **显存占用**：当前用了多少显存、还剩多少。这能帮你提前判断会不会遇到 OOM（显存溢出）。
- **GPU 利用率**：GPU 是在认真干活，还是闲着没事干。
- **温度与功耗**：防止硬件过热，也能看看能耗情况。
- **进程绑定**：哪个程序（PID）占用了 GPU？占了多少显存？一目了然。

**注意**：`nvidia-smi` 只有在安装了 NVIDIA GPU 驱动后才能使用。如果你的机器没有 NVIDIA 显卡（比如纯 CPU 环境），命令会提示找不到。不过别担心，CPU 推理和不带 GPU 的基础学习仍然可以进行。

### 2.2 关键指标解读

运行 `nvidia-smi` 后，你会看到一张表格。别被密密麻麻的数字吓到，我们只看最核心的几项：

*   **顶部信息**：这里告诉你工具、驱动和 CUDA 的版本号，先不用管。
*   **GPU 列表**：这是重点。你会看到你的显卡型号（比如 `Name` 字段），以及：
    *   `Temp`：显卡温度，越高越危险。

*   **进程区**：显示是哪个程序（`Process name`）占用了显存（`GPU Memory Usage`）。

> **对你最重要的两个数字**：`Memory-Usage`（显存占用）和 `GPU-Util`（利用率）。训练时如果显存快满了，就要调小 batch size；如果利用率长期很低，说明数据加载太慢，GPU 在空等。

## nvidia-smi 显存监控 > 四、进阶查询：精准获取信息（①+④） > 4.1 查看显存详情（①）

## 4.1 查看显存详情（①）

你的拯救者Y7000P上跑深度学习时，最常遇到的就是显存不够。先学会快速查看显存使用情况：

```bash
nvidia-smi -q -d MEMORY
```

这条命令只显示显存相关信息，输出包括：**总显存、已用显存、空闲显存、显存类型**（比如GDDR6）。不用在满屏输出里找重点，一眼就能看清。

## 4.2 精准查询特定字段（①+④）

如果只想看某几个数据，用 `--query-gpu` 配合 `--format=csv`，输出成表格，方便阅读或写脚本处理：

```bash
nvidia-smi --query-gpu=name,temperature.gpu,memory.used,memory.total,utilization.gpu --format=csv
```

输出示例：

```
name, temperature.gpu, memory.used [MiB], memory.total [MiB], utilization.gpu [%]
Tesla V100-PCIE-32GB, 33, 128 MiB, 32510 MiB, 0 %
```

常用字段：

| 字段名 | 说明 |
|---|---|
| `name` | GPU 型号 |
| `temperature.gpu` | GPU 温度 |
| `memory.used` | 已用显存 |
| `memory.total` | 总显存 |
| `utilization.gpu` | GPU 利用率 |
| `power.draw` | 当前功耗 |
| `power.limit` | 功耗上限 |
| `pcie.link.gen.current` | 当前 PCIe 版本 |
| `ecc.mode.current` | ECC 内存模式 |

## 5.1 查看 GPU 进程（①+④）

运行 `nvidia-smi` 后，屏幕底部的 **Processes** 区域会列出当前占用 GPU 的进程。这个区域长这样：

```bash
+-----------------------------------------------------------------------------+
| Processes:                                                                  |
|  GPU   GI   CI        PID   Type   Process name                  GPU Memory |
|        ID   ID                                                   Usage      |
|=============================================================================|
|    0   N/A  N/A      12345    C   python3                         10240MiB |
+-----------------------------------------------------------------------------+
```

表格里每一行代表一个进程，你需要重点看四个字段：

- **PID**：进程的唯一编号。后面要释放显存时，杀进程就靠它。
- **Type**：进程类型。`C` 表示计算进程（比如 PyTorch 训练），`G` 表示图形进程。
- **Process name**：进程的名字，比如 `python3`。
- **GPU Memory Usage**：这个进程占了多少显存，单位是 MiB。

简单说：**先看 Type 确认是不是计算任务，再看 PID 记住编号，最后看显存占用判断谁吃得多。**

### 5.2 杀死僵尸进程，释放显存

训练脚本崩溃后，有时进程没退干净，还占着显存（俗称“僵尸进程”）。这时手动杀掉它：

```bash
# 1. 先用 nvidia-smi 找到 PID（比如 12345）
nvidia-smi

# 2. 杀死进程
kill 12345

# 3. 如果进程顽固不死，强制终止
kill -9 12345
```

> **安全提醒**：`kill -9` 是强制终止，进程立刻消失，未保存的数据会丢。优先用 `kill PID`，不行再用 `kill -9`。

### 5.3 OOM 预防思路

OOM（显存溢出）是大模型训练常见报错。用 `nvidia-smi` 提前防：

1. **训练前**：看空闲显存，估算 batch size
2. **训练中**：用 `watch -n 1 nvidia-smi` 或 `nvitop` 观察显存增长

## nvidia-smi 显存监控 > 六、日志记录与自动化（①+④） > 6.1 导出监控日志（①）

## 6.1 导出监控日志（①）

你的联想拯救者Y7000P上如果有NVIDIA显卡，就可以把刚才看到的监控信息保存成文件，方便事后分析。

**方法一：直接保存屏幕输出**

```bash
# 每 2 秒采样一次，输出到 gpu_log.txt，按 Ctrl+C 停止
nvidia-smi -l 2 > gpu_log.txt
```

这条命令会一直运行，把每次采样的结果写入 `gpu_log.txt`。想停止就按 `Ctrl+C`。

**方法二：导出 CSV 格式（更适合分析）**

```bash
nvidia-smi --query-gpu=timestamp,name,memory.used,memory.total,utilization.gpu --format=csv -l 1 > gpu_log.csv
```

CSV 是表格格式，每列有明确的字段名（时间戳、显卡名、已用显存、总显存、GPU利用率），之后可以用 Excel 或 Python 打开做分析。

> **小提示**：`-l 1` 表示每秒采样一次，`-l 5` 就是每5秒一次。采样越频繁，文件越大，但数据越细。

## 6.2 后台持续监控（④）

如果你要跑一个很久的训练任务，不想一直盯着终端，可以用后台模式：

```bash
nohup nvidia-smi --query-gpu=timestamp,memory.used,utilization.gpu --format=csv -l 5 > ~/gpu_monitor.csv 2>&1 &
```

这条命令的意思是：把监控放到后台运行，即使你关掉终端，它也会继续记录。数据会写到 `~/gpu_monitor.csv`（即你的主目录下）。训练结束后，再来看这个文件，就能分析整个训练期间的显存波动和利用率变化。
