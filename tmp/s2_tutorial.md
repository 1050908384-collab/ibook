## 2.1 最简命令：先学会“看一眼”GPU

你的联想拯救者Y7000P上，如果安装了NVIDIA显卡驱动，就可以在终端里输入下面这条命令，来查看GPU的实时状态：

```bash
nvidia-smi
```

**这条命令是做什么的？**

它是NVIDIA官方提供的系统管理工具，全称是 **NVIDIA System Management Interface**。简单说，它就是你和GPU之间的“仪表盘”——输入这条命令，GPU就会把当前的工作状态以表格形式汇报给你。

**你会看到什么？**

执行后，终端会输出一个表格，里面包含几类关键信息：

| 表格内容 | 通俗理解 |
|---|---|
| **显存占用** | GPU“内存”用了多少、还剩多少——这能帮你提前发现显存不够用（OOM）的风险 |
| **GPU利用率** | GPU是在认真干活，还是在“摸鱼”空转 |
| **温度与功耗** | 硬件是否过热、耗电情况如何 |
| **进程绑定** | 是哪个程序（PID）占用了GPU，占了多少显存 |

**为什么这对你很重要？**

你现在的学习目标是掌握Linux，而GPU监控是后续模型训练中几乎每天都要用到的技能。学会这一条命令，你就拿到了排查“显存不够”“程序卡死”等问题的第一把钥匙。

**一个提醒**

`nvidia-smi` 只有在安装了NVIDIA GPU驱动的机器上才能使用。如果你的环境没有NVIDIA显卡（比如纯CPU环境），命令会提示找不到——这并不影响你继续学习Linux基础，但后续涉及GPU的实训就需要NVIDIA环境了。

### 4.1 查看显存详情（①）

现在你已经知道 `nvidia-smi` 能显示 GPU 的整体状态，但有时你只想看显存这一项，不想被其他信息干扰。这时可以用 `-q -d MEMORY` 参数，把输出精简到只和显存相关的内容：

```bash
nvidia-smi -q -d MEMORY
```

运行后，你会看到这几项关键数据：**总显存**（Total）、**已用显存**（Used）、**空闲显存**（Free），以及**显存类型**（比如 GDDR6）。在你的联想拯救者 Y7000P 上，显存类型通常是 GDDR6，这决定了显卡的数据吞吐速度。

### 5.1 查看 GPU 进程

`nvidia-smi` 命令的底部有一个 **Processes** 区域，它会列出当前正在占用 GPU 的进程。这个区域长这样：

```bash
+-----------------------------------------------------------------------------+
| Processes:                                                                  |
|  GPU   GI   CI        PID   Type   Process name                  GPU Memory |
|        ID   ID                                                   Usage      |
|=============================================================================|
|    0   N/A  N/A      12345    C   python3                         10240MiB |
+-----------------------------------------------------------------------------+
```

每一列的含义如下：

- **PID**：进程的唯一编号。记住它，因为后面释放显存时要用它来结束进程。
- **Type**：进程类型。`C` 表示计算进程（比如 PyTorch 训练），`G` 表示图形进程。
- **Process name**：进程的名称，比如 `python3`。
- **GPU Memory Usage**：这个进程占用了多少显存，单位是 MiB。

**学习检查**：请你在终端运行 `nvidia-smi`，找到 Processes 区域，看看有没有进程在占用 GPU。如果有，试着说出它的 PID、Type 和显存占用分别是多少。

## 5.2 杀死残留进程，释放显存

训练脚本崩溃后，有时进程没有彻底退出，还在悄悄占着显存——这就是“残留进程”。你的拯救者Y7000P上如果遇到这种情况，需要手动清理：

**第一步：找到进程ID（PID）**
```bash
nvidia-smi
```
运行后，在输出里找到占用显存的进程，记下它的PID（比如12345）。

**第二步：尝试正常终止**
```bash
kill 12345
```
这是“礼貌”的终止方式，给进程机会保存数据、正常退出。

**第三步：必要时强制终止**
```bash
kill -9 12345
```
如果上一步没效果，用这个“暴力”方式立刻结束进程。

**第四步：确认进程已退出**
```bash
nvidia-smi
```
再次运行，确认刚才的进程已消失、显存已释放

## 6.1 导出监控日志——把显存数据“存下来”

你之前已经学会了在终端里实时查看 GPU 状态，但那些数据一闪而过，没法回头分析。这一节解决一个问题：**如何把监控结果保存成文件**，方便训练结束后复盘。

### 方法一：直接保存屏幕输出

```bash
# 每 2 秒采样一次，输出到 gpu_log.txt，按 Ctrl+C 停止
nvidia-smi -l 2 > gpu_log.txt
```

这条命令会每 2 秒把一次 `nvidia-smi` 的完整输出写入 `gpu_log.txt`。注意：

- `-l 2` 表示间隔 2 秒采样一次，数字可以改
- `>` 将输出重定向到文件
- 它会一直运行，直到你按 `Ctrl+C` 手动停止

### 方法二：导出 CSV 格式（更适合分析）

```bash
nvidia-smi --query-gpu=timestamp,name,memory.used,memory.total,utilization.gpu --format=csv -l 1 > gpu_log.csv
```

这条命令更“讲究”：

- `--query-gpu` 指定要查询哪些字段：时间戳、显卡名称、已用显存、总显存、GPU 利用率
- `--format=csv` 输出成表格格式，之后可以用 Excel 或 Python 打开做分析
- `-l 1` 每 1 秒采样一次
- `>` 将输出重定向到 `gpu_log.csv`

**对比一下**：方法一保存的是“人看的”完整信息，方法二保存的是“机器分析的”结构化数据。做长时间监控时，CSV 更实用。

### 进阶：后台持续监控

上面的命令都需要你开着终端。如果训练要跑好几个小时，你不想一直盯着，可以用：

```bash
nohup nvidia-smi --query-gpu=timestamp,memory.used,utilization.gpu --format=csv -l 5 > ~/gpu_monitor.csv 2>&1 &
```
