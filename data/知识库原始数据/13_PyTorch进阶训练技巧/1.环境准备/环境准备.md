### 1.3 GPU 架构兼容性检查

AMP 的加速效果严重依赖 GPU 的 **Tensor Cores**（张量核心）。并非所有 NVIDIA GPU 都能从 AMP 中获得显著收益：（①）

| GPU 架构 | 代表型号 | Tensor Cores | AMP 效果 |
|---------|---------|-------------|---------|
| Pascal | GTX 1080 Ti, GTX 1070 | ❌ 无 | 支持 FP16，但无硬件加速，效果有限 |
| Volta | V100 | ✅ 有 | 显著加速 |
| Turing | RTX 2080 Ti, T4 | ✅ 有 | 显著加速 |

| Ada Lovelace | RTX 4090, L40 | ✅ 有 | 显著加速 |
| Hopper | H100, H200 | ✅ 有 | 显著加速，支持 FP8 |

## 二、AMP 核心机制速览

在正式进入后续章节前，你需要理解 AMP 的三个核心机制。这不仅能帮你正确编写代码，还能在训练出现 NaN 时快速定位问题。（①+②）

### 2.1 FP16 计算 + FP32 参数保存

AMP 的核心思想是**分工**：

- **FP16（半精度，2 字节）**：用于前向传播和反向传播中的计算密集型操作（如矩阵乘法、卷积）。FP16 的显存占用是 FP32 的一半，且 Tensor Cores 对 FP16 有专门的硬件优化。
- **FP32（单精度，4 字节）**：用于保存模型参数和优化器状态。FP32 的动态范围更大，能避免参数更新时的数值精度损失。（①）

### 2.2 autocast：自动选择精度

`autocast` 是一个上下文管理器，它会自动判断哪些操作适合 FP16，哪些必须保留 FP32：（②）

```python
with autocast():
    output = model(input)      # 卷积/线性层自动转 FP16
    loss = criterion(output, target)  # 损失函数自动保留 FP32
```

PyTorch 内部维护了一份"操作-精度映射表"：（②）
- **自动 FP16**：`nn.Linear`、`nn.Conv2d`、`nn.ReLU` 等计算密集型操作
- **自动 FP32**：`nn.Softmax`、`nn.CrossEntropyLoss`、`nn.LayerNorm`、`nn.BatchNorm` 等数值敏感操作

这意味着绝大多数情况下，你**不需要手动指定每一层的精度**——`autocast` 会自动帮你做出最优选择。

### 2.3 GradScaler：动态损失缩放

FP16 的动态范围有限（约 $6 \times 10^{-8}$ 到 $65504$），反向传播时小梯度容易**下溢**（underflow）为 0，导致参数无法更新。GradScaler 通过**损失缩放**解决这一问题：（②）

1. **放大损失**：将损失乘以一个缩放因子（默认初始值 $2^{16} = 65536$）
2. **反向传播**：基于放大后的损失计算梯度（梯度也被同步放大，避免下溢）
3. **参数更新**：优化器用 FP32 参数和"已放大但合法的"梯度更新参数
4. **动态调整**：
   - 若连续多次（默认 2000 次）未出现溢出，缩放因子乘以 `growth_factor`（默认 1.0001）逐步增大
   - 若检测到梯度为 `inf` 或 `NaN`，缩放因子乘以 `backoff_factor`（默认 0.5）回退，并**跳过本次参数更新**

```python
scaler = GradScaler()  # 初始化缩放器

with autocast():
    loss = model(input)
    
scaler.scale(loss).backward()   # 缩放损失后反向传播
scaler.step(optimizer)          # 内部检查梯度合法性，合法才更新
scaler.update()                 # 调整缩放因子
```

> **关键理解**：`scaler.step(optimizer)` 不是简单的 `optimizer.step()`——它会先检查所有梯度是否包含 `inf`/`NaN`。如果有，就跳过本次更新并降低缩放因子；如果没有，才执行真正的参数更新。这是 AMP 训练稳定性的核心保障。（②）

## 三、一键验证脚本

将上述所有检查整合为一个脚本，运行后即可确认环境是否就绪：

```python
import torch
from torch.cuda.amp import autocast, GradScaler

def check_amp_environment():
    """全面检查 AMP 运行环境"""
    print("=" * 50)
    print("PyTorch AMP 环境检查报告")
    print("=" * 50)
    
    # 1. PyTorch 版本
    print(f"\n[1] PyTorch 版本: {torch.__version__}")
    if torch.__version__ < '1.6.0':
        print("    ❌ 版本过低，请升级到 1.6+")
        return False
    print("    ✅ 版本支持 AMP")
    
    # 2. CUDA 可用性
    print(f"\n[2] CUDA 可用: {torch.cuda.is_available()}")
    if not torch.cuda.is_available():
        print("    ⚠️ 无 GPU，AMP 代码可运行但无加速效果")
        print("    💡 建议：安装 CUDA 版 PyTorch 并在 GPU 上运行")
        return True  # CPU 仍可运行，不算失败
    
    # 3. GPU 信息
    device_name = torch.cuda.get_device_name(0)
    capability = torch.cuda.get_device_capability(0)
    print(f"\n[3] GPU 设备: {device_name}")
    print(f"    计算能力: {capability[0]}.{capability[1]}")
    
    if capability[0] >= 7:
        print("    ✅ 支持 Tensor Cores，AMP 可充分发挥")
    else:
        print("    ⚠️ 不支持 Tensor Cores，AMP 加速效果有限")
    
    # 4. AMP 模块测试
    print(f"\n[4] AMP 模块测试")
    try:
        scaler = GradScaler()
        print("    ✅ GradScaler 初始化成功")
        
        # 构造一个最小化训练步骤验证全流程
        model = torch.nn.Linear(10, 2).cuda()
        optimizer = torch.optim.SGD(model.parameters(), lr=0.01)
        x = torch.randn(4, 10).cuda()
        target = torch.randint(0, 2, (4,)).cuda()
        
        with autocast():
            out = model(x)
            loss = torch.nn.functional.cross_entropy(out, target)
        
        scaler.scale(loss).backward()
        scaler.step(optimizer)
        scaler.update()
        
        print("    ✅ autocast + GradScaler 全流程通过")
        print(f"    当前缩放因子: {scaler.get_scale()}")
        
    except Exception as e:
        print(f"    ❌ AMP 测试失败: {e}")
        return False
    
    print("\n" + "=" * 50)
    print("结论：环境已就绪，可以开始 AMP 训练")
    print("=" * 50)
    return True

if __name__ == "__main__":
    check_amp_environment()
```

> **本地运行配置要求**：上述代码在 CPU 或单卡 GPU 上均可运行，内存 ≥ 4GB。如有 GPU，需确保驱动支持 CUDA。

## 四、常见问题与解决（①+②）

| 问题 | 可能原因 | 解决方案 |
|------|---------|---------|
| `torch.cuda.amp` 导入失败 | PyTorch 版本 < 1.6 | 升级 PyTorch：`pip install torch --upgrade`（①） |
| AMP 开启后速度反而变慢 | GPU 为 Pascal 或更早架构，无 Tensor Cores | 正常现象，建议换用 Volta 以后架构的 GPU（①） |
| Loss 突然变为 NaN | 缩放因子过大导致梯度爆炸，或数据中有异常值 | 降低初始缩放因子：`GradScaler(init_scale=2.**10)`；检查输入数据；添加梯度裁剪（②） |
| BatchNorm/LayerNorm 输出异常 | FP16 下统计量精度不足 | 强制归一化层使用 FP32：`for m in model.modules(): if isinstance(m, (nn.BatchNorm2d, nn.LayerNorm)): m.float()`（②） |
| 显存没有明显减少 | 模型过小或 batch size 太小，激活值占主导 | AMP 对大型模型（如 Transformer）效果更明显；尝试增大 batch size（①） |
| `scaler.step()` 频繁跳过更新 | 学习率过大或模型初始化不当 | 降低学习率至 FP32 训练的 1/2 ~ 1/10；检查模型初始化（②） |
