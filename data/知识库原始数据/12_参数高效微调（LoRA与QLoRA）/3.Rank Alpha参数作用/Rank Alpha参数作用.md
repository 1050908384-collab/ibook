# 一、回顾LoRA基本公式（①②）

上一节已经学习：

LoRA不会直接更新原模型参数：

```text
W
```

而是在原权重基础上增加：

```text
ΔW
```

最终：

```text
W' = W + ΔW
```

其中：

```text
ΔW = B × A
```

两个低秩矩阵：

```text
A

B
```

共同组成LoRA参数。

---

# 二、Rank（r）是什么？（②③）

## 2.1 Rank表示什么？

Rank：

中文：

> 矩阵的秩。

在LoRA中：

rank表示低秩矩阵中间维度大小。

例如：

原始权重：

```text
W:

4096 × 4096
```

如果设置：

```python
r=8
```

那么：

A：

```text
8 × 4096
```

B：

```text
4096 × 8
```

最终：

```text
ΔW = B × A
```

恢复：

```text
4096 × 4096
```

---

## 2.2 Rank控制什么？

简单理解：

> Rank决定LoRA能够学习多少种变化方向。

低rank：

例如：

```python
r=4
```

表示：

模型只能学习较少的变化模式。

优点：

* 参数少；
* 显存低；
* 训练快。

缺点：

* 表达能力有限。

---

高rank：

例如：

```python
r=64
```

表示：

LoRA拥有更多自由度。

优点：

* 能学习更复杂任务；
* 适应能力更强。

缺点：

* 参数更多；
* 显存增加；
* 训练成本提高。

---

# 三、Rank对参数量的影响（重点）（②）

假设：

模型某层：

```text
4096 × 4096
```

---

## 3.1 不使用LoRA

完整参数：

```text
4096 × 4096

=16777216
```

约：

1677万参数。

---

## 3.2 使用LoRA

公式：

```text
参数量=r×(输入维度+输出维度)
```

---

### r=8

参数：

```text
8×(4096+4096)
```

=

```text
65536
```

---

### r=64

参数：

```text
64×8192
```

=

```text
524288
```

---

对比：

| 方式        |   参数量 |
| --------- | ----: |
| 完整训练      | 1677万 |
| LoRA r=8  |  6.5万 |
| LoRA r=64 |   52万 |

可以看到：

即使提高rank：

仍远低于全参数训练。

# 四、Rank如何影响模型效果？（②③）

## 4.1 Rank太小的问题

例如：

```python
r=2
```

可能导致：

* 学习能力不足；
* 欠拟合；
* 新任务知识无法充分表达。

表现：

```text
训练loss下降慢

效果提升有限
```

---

## 4.2 Rank太大的问题

例如：

```python
r=256
```

可能：

* 参数增加；
* 显存增加；
* 训练速度下降。

同时：

LoRA优势降低。

因为：

rank过大时：

参数高效优势进一步下降。

> 说明：这里不宜说成"接近学习完整矩阵"。以文中 `4096 × 4096` 的权重为例，其完整秩为 4096，而 `r=256` 仍**明显小于** 4096，远没有"接近完整矩阵"；只是相对小 rank，`r=256` 的参数量、显存和训练成本都更高，**参数高效的优势被削弱**。
>
> **用参数效率公式和真实比例看清楚（避免"接近完整矩阵"的直觉误解）**：对一个 `d_out × d_in` 的权重，
> - 完整矩阵参数量：`d_out × d_in`；
> - LoRA 增量参数量：`r × (d_in + d_out)`；
> - 两者比例（LoRA 占完整矩阵的比例）：`r × (d_in + d_out) / (d_out × d_in)`。
>
> 代入本文 `d_in = d_out = 4096`：
>
> | rank r | LoRA 参数量 `r×(4096+4096)` | 完整矩阵 `4096×4096` | 占比 |
> | ---: | ---: | ---: | ---: |
> | 8 | 65,536 | 16,777,216 | ≈ 0.39% |
> | 64 | 524,288 | 16,777,216 | ≈ 3.13% |
> | 256 | 2,097,152 | 16,777,216 | ≈ 12.5% |
>
> 可以看到：即便 `r=256`，LoRA 参数也**只占完整矩阵的约 1/8**，谈不上"接近完整矩阵"。之所以说它"参数高效优势下降"，是相对 `r=8`（0.39%）而言占比明显变大、显存与成本升高，而**不是**因为它逼近了满秩。

---

## 4.3 常见rank选择

经验（下面仅为**经验起始范围**，不是自动调参标准）：

| 任务类型   | rank（起点参考） |
| ------ | ------ |
| 简单分类   | 约 4~8    |
| 文本风格调整 | 约 8~16   |
| 指令微调   | 约 16~64  |
| 复杂领域任务 | 约 64以上   |

实际项目需要根据：

* 数据量；
* 模型大小；
* 序列长度；
* batch 大小（含梯度累积后的有效 batch）；
* 目标模块（`target_modules`）的选择与数量；
* GPU显存；
* 验证集/基准任务上的表现；

调整。不要把上表当作可以直接照搬或自动套用的固定配置——同一个 `r` 在不同模型规模、不同序列长度/batch、不同目标模块下的显存与效果都可能差别很大。

# 五、Alpha（lora_alpha）是什么？（①②）

## 5.1 Alpha作用

LoRA除了：

```text
ΔW = BA
```

还会进行缩放：

公式：

```text
W' = W + (α/r)BA
```

其中：

* α：

  * lora_alpha；
* r：

  * rank。

---

因此：

真正加入模型的变化量：

不是：

```text
BA
```

而是：

```text
(α/r)BA
```

---

# 六、为什么需要Alpha缩放？（②③）

## 6.1 控制LoRA影响强度

假设：

rank：

```python
r=8
```

alpha：

```python
alpha=16
```

缩放：

```text
16/8=2
```

表示：

LoRA更新：

放大2倍。

---

如果：

```python
alpha=8
```

那么：

```text
8/8=1
```

保持原始比例。

---

如果：

```python
alpha=4
```

那么：

```text
4/8=0.5
```

LoRA影响减弱。

---

# 七、Alpha与Rank的关系（重点）

LoRA 加入模型的更新量会被 `α/r` 缩放：

```text
alpha/r
```

因此 `α/r` 是影响 LoRA 更新"强度"的一个**关键缩放系数**。

> 说明：不宜说"LoRA 实际强度**仅**由 `α/r` 决定"。`α/r` 只是**缩放系数**；实际落到权重上的更新量还取决于训练得到的 `A`、`B` 参数值、其初始化方式、学习率、优化器、训练步数与数据，以及不同 LoRA 变体/实现的处理方式（例如 RS-LoRA 会用 `α/√r` 的缩放）。相同 `α/r` 只代表缩放比例一致，并不保证"更新强度"完全相同。
>
> **`α/r` 之外，还有哪些因素共同决定"实际更新强度"**：
> - **学习率（learning rate）**：直接决定每步对 `A`、`B` 的更新步长。学习率与 `α/r` 会**叠加**影响有效更新幅度——例如把 `α/r` 调大又不下调学习率，容易一起放大更新导致震荡；很多实践中甚至通过调学习率而非频繁改 `α` 来控制强度。
> - **初始化**：常见实现里 `A` 用小随机值、`B` 初始化为 0，使训练开始时 `ΔW = BA = 0`（不扰动原模型），之后再逐步学习。初始化方式会影响早期训练动态，因此"当前更新量"并不只由 `α/r` 决定。
> - **训练状态（训练步数/数据/是否收敛）**：`ΔW` 是训练**逐步累积**出来的。同样的 `α/r`，训练早期与收敛后 `A`、`B` 的数值不同，落到权重上的实际更新量自然不同。
>
> 因此把 `α/r` 理解为"一个可调的缩放系数"，而不是"唯一决定实际强度的开关"；调强度时应把它与学习率放在一起看，并以验证集表现为准。

---

例如：

## 配置1

```python
r=8

alpha=16
```

比例：

```text
2
```

---

## 配置2

```python
r=16

alpha=32
```

比例：

```text
2
```

虽然rank不同：

但是缩放比例相同。

---

因此：

调整rank时：

常见做法是**同步调整**alpha，以保持 `α/r` 缩放比例大致稳定（这只是**经验做法**，不是必须遵守的规则）。下文各"方案"里出现的 `alpha = 2 × r`（如 r=8/alpha=16、r=16/alpha=32）也只是常见的**经验起点**，并非通用最优规则；实际仍应结合验证集表现调整，也可保持 alpha 固定而单独调 r。

# 十、Rank与Alpha选择误区（②③）

## 误区1：

认为：

> rank越大一定越好。

错误。

原因：

任务简单时：

大rank可能：

* 浪费显存；
* 增加训练成本。

---

## 误区2：

只调整rank，不调整alpha。

例如：

原：

```python
r=8
alpha=16
```

改：

```python
r=64
alpha=16
```

比例：

```text
16/64=0.25
```

LoRA影响降低。

---

## 误区3：

认为alpha越大越好。

错误。

alpha过大（即 `α/r` 缩放过大）：

可能：

* 更新过强；
* 训练不稳定。

> 说明：`α/r` 过大只是训练不稳定的**可能原因之一**，不是唯一或主要原因。训练震荡/发散还常常来自学习率过高、数据质量差、有效 batch size 过小、精度（fp16/bf16）与数值稳定性、缺少梯度裁剪等。排查不稳定时应综合这些因素，不要只盯着 alpha。
