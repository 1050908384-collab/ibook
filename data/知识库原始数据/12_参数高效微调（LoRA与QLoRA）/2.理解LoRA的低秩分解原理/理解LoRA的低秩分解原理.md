## 一、为什么需要LoRA？（①②③）
### 1.1 大模型微调的问题
现代大语言模型：

例如：

```text
LLaMA

Qwen

Baichuan

Mistral
```

通常拥有：

* 数十亿参数；
* 上百亿参数。

例如：

7B模型：

```text
70亿参数
```

如果采用传统方式：

```text
预训练模型

↓

更新全部参数

↓

保存新模型
```

需要：

* 巨大的GPU显存；
* 大量训练时间；
* 巨大的存储空间。

---

### 1.2 全参数微调的问题
假设模型有：

```text
100亿参数
```

训练时不仅保存：

模型参数：

```text
W
```

还需要保存：

梯度：

```text
∂W
```

优化器状态：

```text
Adam moment
```

实际显存需求远大于模型大小。

## 二、LoRA核心思想（①②）
### 2.1 不直接修改原模型参数
传统微调：

原始权重：

```text
W
```

训练：

```text
W → W'
```

也就是：

直接修改：

```text
W
```

---

LoRA：

保持：

```text
W
```

冻结。

增加一个新的参数：

```text
ΔW
```

最终：

模型使用：

```text
W' = W + ΔW
```

其中：

* W：

  * 原模型参数；
* ΔW：

  * LoRA新增参数。

---

### 2.2 为什么只训练ΔW？
因为大模型已经通过海量数据学习了：

* 语言规律；
* 世界知识；
* 推理能力。

微调通常只是：

> 对已有能力进行方向调整。

因此在很多任务上，**不必**重新学习全部参数，只学习任务相关的变化量往往就能取得不错的效果。

> 说明：这是一种**教学直觉/假设**，帮助理解 LoRA 为何可行，并**不是普遍成立的严格结论**。是否能用 LoRA 替代全参数微调，取决于任务与预训练能力的差距、数据规模、目标模块与秩的设置等；某些差距较大的任务或数据充足时，全参数微调仍可能明显更好。

只需要学习：

```text
任务相关变化量
```

即可。

## 三、什么是低秩分解？（底稿③）
### 3.1 矩阵基础概念
Transformer中大量参数都是矩阵。

例如：

注意力层（下面是**数学表达/示意**，不是可运行代码）：

```text
Q = X · Wq
```

> 形状说明（示意）：设输入 `X` 形状为 `(序列长度, d_model)`、权重 `Wq` 形状为 `(d_model, d_model)`（此处按同维投影举例），则 `Q = X · Wq` 得到形状 `(序列长度, d_model)`。实际实现中还涉及 batch 维、多头拆分等，这里只为说明"Q 由输入乘以权重矩阵得到"。

其中：

```text
Wq
```

是一个权重矩阵。

假设：

```text
Wq:

4096 × 4096
```

参数数量：

```text
4096 × 4096

≈1677万
```

---

### 3.2 直接训练矩阵的问题
如果修改：

```text
ΔW
```

仍然需要：

```text
4096 × 4096
```

个参数。

LoRA提出：

不要直接学习完整矩阵。

而是：

拆成两个小矩阵。

---

## 四、LoRA低秩分解数学原理（重点）（①②③）
LoRA核心公式：

原始：

```text
W
```

保持冻结。

新增：

```text
ΔW
```

```text
B × A
```

组成。

---

### 4.1 矩阵尺寸变化
假设：

原矩阵：

```text
W:

4096 × 4096
```

如果直接训练：

参数：

```text
4096×4096

16777216
```

---

LoRA：

设置：

```text
rank r=8
```

拆成：

A：

```text
8 × 4096
```

B：

```text
4096 × 8
```

参数：

A：

```text
32768
```

B：

```text
32768
```

总：

```text
65536
```

---

对比：

| 方式        |  参数数量 |
| --------- | ----: |
| 完整矩阵      | 1677万 |
| LoRA(r=8) |  6.5万 |

参数量大幅下降。

## 五、为什么低秩分解有效？（参考文章④⑤）
### 5.1 神经网络参数变化具有低维特征
LoRA论文提出：

模型适应新任务时：

参数变化：

```text
ΔW
```

并不需要覆盖所有方向。

实际上：

有效变化集中在：

```text
低维子空间
```

---

例如：

一个4096维空间。

真正影响任务的"有效方向"可能远少于满维度，集中在一个**低维子空间**里：

```text
远小于原维度的少数方向
```

> 说明：LoRA 的依据是"权重更新往往具有**较低的内在维度**（low intrinsic dimension）"这一**假设**。具体"有效维度"是多少并没有一个通用固定值，会随模型、任务、数据而变化；这里只做**定性**理解，不宜记成"几十维"之类的确定数字。

因此：

低秩矩阵：

```text
BA
```

可以近似：

```text
ΔW
```

---

### 5.2 类比理解
假设：

一张高清图片：

```text
4000×4000像素
```

完整保存：

1600万个数据。

但是：

如果图片主要变化：

只是：

* 亮度；
* 对比度；
* 少量结构变化。

可以用少量参数描述。

LoRA类似：

> 用少量参数描述模型变化方向。

## 六、LoRA在Transformer中的位置（①③）
Transformer主要结构：

```text
Input

↓

Embedding

↓

Attention

↓

FFN

↓

Output
```

其中Attention：

包含：

```text
Q

K

V

O
```

四个投影矩阵。

---

LoRA 在早期实践中**常见**加入：

```text
Q投影

V投影
```

例如：

```python
target_modules=[
    "q_proj",
    "v_proj"
]
```

表示：

只训练：

```text
Wq变化

Wv变化
```

> 说明：只挑 `q_proj`/`v_proj` 是 LoRA 原论文里的一种**常见选择**，并**不是固定标准**。现代实践中也经常把 LoRA 加到注意力的全部投影（q/k/v/o）、FFN 的线性层，甚至用 `target_modules="all-linear"` 覆盖所有线性层。选择哪些模块会影响可训练参数量、显存和效果，应结合模型结构（先确认实际模块名）与验证集表现来定，详见后续《LoraConfig 配置》一章。

为了让上面的说明不与实操脱节，这里给出**一个覆盖更完整线性层**的配置示例（以 Llama 类模型常见的模块名为例；不同模型模块名可能不同，请先用 `print(model)` 或 `model.named_modules()` 确认实际名称）：

```python
from peft import LoraConfig

# 示例：把 LoRA 同时加到注意力的 q/k/v/o 与 FFN 的 gate/up/down 线性层
lora_config = LoraConfig(
    r=8,
    lora_alpha=16,
    lora_dropout=0.05,
    bias="none",
    task_type="CAUSAL_LM",
    target_modules=[
        "q_proj", "k_proj", "v_proj", "o_proj",   # 注意力投影
        "gate_proj", "up_proj", "down_proj",       # FFN（MLP）线性层
    ],
)
```

> 上例是**显式列出模块名**的写法；若当前 PEFT 版本支持，也可用 `target_modules="all-linear"` 让 PEFT 自动匹配所有线性层（不含输出 lm_head 等，具体以版本文档为准）。覆盖的模块越多，可训练参数、显存与 Adapter 体积也越大——是否值得，应结合验证集表现权衡。完整字段含义、`all-linear` 的可运行示例与版本差异见后续《LoraConfig 配置》一章。

## 八、LoRA核心参数理解（参考文章④⑤）
### 8.1 rank（r）
参数：

```python
r=8
```

代表：

低秩矩阵维度。

越大：

优点：

* 表达能力更强；

缺点：

* 参数更多；
* 显存增加。

常见（下面仅为**经验起始范围**，非确定规则）：

| 任务   | rank（起点参考） |
| ---- | ---- |
| 简单任务 | 约 4-8  |
| 普通微调 | 约 8-32 |
| 复杂任务 | 约 64+  |

> 说明：合适的 `r` 与模型规模、目标模块、数据量、任务难度都相关，上表只作为**起点参考**，实际应结合验证集/基准任务的表现调整。`r` 越大表达能力越强但参数与显存也越多，两者需要权衡。
>
> **基于验证集选 `r` 的一个可操作流程（比背"配方"更可靠）**：
> 1. **划出验证集**：从数据里留出不参与训练的验证集（如 8:2 / 9:1），后续所有比较都在它上面看指标。
> 2. **固定其它变量**：先固定 `target_modules`、学习率、`lora_alpha`（或固定 `alpha/r` 比例）、训练步数等，只改 `r`，做**受控对比**。
> 3. **小范围网格搜索**：从较小值起步（如 `r ∈ {4, 8, 16, 32}`），逐个训练并在验证集上记录指标（loss/accuracy/F1 等）与显存、耗时。
> 4. **看边际收益**：若 `r` 增大带来的验证集提升已很小、甚至开始过拟合（训练指标升但验证指标降），说明再加大 `r` 不划算，取"性价比拐点"处的值。
> 5. **结合成本决策**：在效果接近时，优先选更小的 `r`（更省显存、Adapter 更小）；效果差距明显且资源允许时再上调。
>
> 换言之，`r` 不是查表就能定死的，上表只给**搜索起点**，最终值应由**验证集表现 + 资源成本**共同决定。

## 九、LoRA与全参数微调区别（①②）
| 项目   | 全参数微调 | LoRA（相对而言）      |
| ---- | ----- | --------- |
| 训练参数 | 全部    | 通常少很多     |
| 显存   | 高     | 通常更低      |
| 速度   | 慢     | 通常更快      |
| 保存文件 | GB级   | 通常较小（常见 MB 级） |
| 部署   | 复制模型  | 加载Adapter |

> 说明：上表是**相对趋势**，不是绝对数值。LoRA 的可训练参数量、显存、训练速度和 Adapter 文件大小会随 `target_modules` 选择、秩 `r`、模型层数与 `dtype` 变化——例如把 LoRA 加到很多模块并用较大 `r` 时，参数量和 Adapter 体积都会明显上升。"更快/更省显存/MB 级"通常成立，但不宜当作恒定保证。

## 十、LoRA与QLoRA关系
LoRA：

```text
FP16模型

+

LoRA参数
```

QLoRA：

```text
4bit量化模型

+

LoRA参数
```

区别：

| 项目     | LoRA      | QLoRA             |
| ------ | --------- | ----------------- |
| 基础模型精度 | FP16/BF16 | 4bit              |
| 显存     | 较低        | 更低                |
| 依赖     | PEFT      | PEFT+bitsandbytes |
| 适合     | GPU训练     | 消费级GPU训练          |
