## 一、DeepSpeed 的定位——为什么需要分布式训练？
### 1.1 从单卡到多卡的必然性
在单卡上训练大模型时，你会很快遇到一堵墙——**显存不足**：

| 模型规模 | FP16 显存需求 | 单卡 A100（80GB） |
|---------|-------------|------------------|
| 7B | ~14 GB | ✅ 可加载 |
| 13B | ~26 GB | ✅ 可加载 |
| 70B | ~140 GB | ❌ 无法加载 |

即使能加载，训练还需要额外的**梯度、优化器状态、激活值**显存。以 Adam 优化器为例，训练参数量为 $\Phi$ 的模型，显存需求约为：

$$\text{显存} \approx 16\Phi \text{（FP16 + 梯度 + 优化器状态）}$$

> **说明**：$16\Phi$ 是 Adam + FP16 全量微调的常用估算口径（FP16 参数 $2\Phi$ + FP16 梯度 $2\Phi$ + FP32 优化器状态 $12\Phi$），实际还会叠加激活值等开销，具体随优化器、精度策略、序列长度而变。按此口径，**70B 模型全量训练的静态显存约在 1TB 量级**——已远超当前单卡显存容量，因此必须借助分布式与显存优化技术。

### 1.2 数据并行 vs 模型并行
**数据并行（Data Parallelism, DP）**：
- 每张 GPU 保存一份完整模型副本
- 将 batch 数据切分到不同 GPU 上并行计算
- 每张卡独立计算梯度，然后**同步平均**
- 局限：模型必须能放进单卡显存

**模型并行（Model Parallelism, MP）**：
- 将模型的不同层切分到不同 GPU 上
- 每张卡只保存部分参数
- 局限：实现复杂，GPU 间通信频繁，利用率可能不高

### 1.3 DeepSpeed 的核心价值：ZeRO
DeepSpeed 提出的 **ZeRO（Zero Redundancy Optimizer）** 是一种革命性的数据并行优化技术。它的核心思想是：

> **模型参数、梯度、优化器状态，没必要在每张 GPU 上都存一份。**

ZeRO 通过将这三类数据**分片（partition）**到不同 GPU 上，实现了"数据并行的效率 + 模型并行的显存节省"：

| ZeRO 阶段 | 分片内容 | 显存节省 | 适用场景 |
|----------|---------|---------|---------|
| **ZeRO-1** | 优化器状态 | 最高约 4×（理论渐近上限，实际更低） | 大 batch 训练 |
| **ZeRO-2** | 优化器状态 + 梯度 | 最高约 8×（理论渐近上限，实际更低） | 中等规模模型 |
| **ZeRO-3** | 优化器状态 + 梯度 + 参数 | 与数据并行度大致线性相关 | 超大模型训练 |

> **说明**：表中"4×/8×/线性"是理想化的理论上界，前提是被分片的对象恰好占显存主导、且忽略通信缓冲与激活值等开销。实际节省倍数会低于理论值，需以显存监控为准。

**为什么这样写**：ZeRO-1/2/3 不是三种独立的并行方式，而是**同一套数据并行框架的三个显存优化级别**。你可以根据模型大小和硬件资源灵活选择。


## 二、环境准备——安装 DeepSpeed
### 2.1 基础环境检查
在安装 DeepSpeed 之前，先确认你的环境是否满足要求。

**本地环境检查清单**：

```bash
# 1. Python 版本（建议 3.10+）
python --version

# 2. PyTorch 是否能识别 GPU
python -c "import torch; print(torch.__version__); print(torch.cuda.is_available())"
# 应输出 True

# 3. CUDA 版本
nvidia-smi
# 查看右上角 CUDA Version

# 4. 查看可用 GPU 数量
python -c "import torch; print(torch.cuda.device_count())"
# 至少输出 2
```

**云端环境检查**：
如果你使用的是云服务器（AWS p3/p4、阿里云 GN7/GN10、AutoDL 等），通常已预装 NVIDIA 驱动和 CUDA。只需确认：

```bash
nvidia-smi       # 确认能看到所有 GPU
nvcc --version   # 确认 CUDA 编译器可用
```

### 2.2 安装 DeepSpeed
```bash
pip install deepspeed
```

验证安装：

```bash
ds_report
```

正常输出应包含 DeepSpeed 版本、PyTorch 版本、以及各算子的安装状态：

```
--------------------------------------------------
DeepSpeed C++/CUDA extension op report
--------------------------------------------------
op name ................ installed .. compatible
--------------------------------------------------
fused_adam ............. [NO] ....... [OKAY]
...
--------------------------------------------------
```

> **说明**：`[NO] ... [OKAY]` 表示该算子未预编译，但可以在运行时**JIT 编译**。只要 `compatible` 列为 `[OKAY]`，功能就可用。如果看到 `[NO] ... [NO]`，说明环境不兼容，需要检查 CUDA 版本。

### 2.3 电脑配置批注
**最低配置**：
- **GPU**：2 张 NVIDIA GPU（支持 CUDA，显存 ≥16GB/卡）
- **CPU**：8 核以上
- **内存**：32GB+
- **磁盘**：100GB+ SSD（模型权重 + 数据集）
- **网络**：单节点无需特殊网络；多节点需 10Gbps+ 以太网或 InfiniBand
- **CPU 支持**：DeepSpeed 支持 CPU 后端（Intel/AMD），但大模型训练强烈建议使用 GPU。CPU 仅适合极小模型调试或推理

**推荐配置**：
- **GPU**：4~8 张 A100（80GB）或 H100
- **内存**：128GB+
- **网络**：InfiniBand（多节点场景下相比普通以太网通常能显著降低通信延迟、提升扩展效率，具体提升幅度依模型规模、并行策略与集群拓扑而定）

**云端配置参考**：
- **AWS**：p3.8xlarge（4×V100）、p4d.24xlarge（8×A100）
- **阿里云**：gn7e（8×V100）、gn10e（8×A100）
- **AutoDL**：2×RTX 3090/4090 实例（适合初学者低成本实验）


## 三、配置多 GPU 环境（至少 2 卡）
### 3.1 单节点多 GPU 配置
单节点（一台机器）多 GPU 是最常见的分布式训练场景。DeepSpeed 会自动检测本地 GPU 数量，**无需 hostfile**。

**确认 GPU 可见性**：

```bash
# 查看本机 GPU 数量
nvidia-smi

# 限制使用特定 GPU（可选）
export CUDA_VISIBLE_DEVICES=0,1   # 只用 GPU 0 和 1
```

**为什么这样写**：`CUDA_VISIBLE_DEVICES` 可以灵活控制哪些 GPU 参与训练，优先级高于 `--num_gpus`。这在共享服务器上特别有用。

### 3.2 多节点配置与 hostfile
多节点（多台机器）训练需要配置**主机文件（hostfile）**，告诉 DeepSpeed 哪些机器参与训练、每台机器有多少张 GPU。

**hostfile 格式**：

```
worker-1 slots=4
worker-2 slots=4
```

- `worker-1`：机器的主机名或 IP 地址（需能通过 SSH 访问）
- `slots=4`：该机器上有 4 张 GPU

**为什么这样写**：DeepSpeed 的 hostfile 兼容 OpenMPI 和 Horovod 格式。`slots` 必须与实际可用 GPU 数量一致，否则会导致资源分配错误。

**云端多节点场景**：
云厂商通常提供集群管理工具（如 Slurm、Kubernetes）。此时可以不使用 hostfile，而是通过环境变量或启动器配置：

```bash
# Slurm 集群示例
deepspeed --launcher slurm train.py --deepspeed_config ds_config.json
```

### 3.3 免密 SSH 配置（多节点必需）
多节点训练要求主节点能**免密 SSH** 登录到所有工作节点：

```bash
# 在主节点生成 SSH 密钥（如果还没有）
ssh-keygen -t rsa

# 将公钥复制到所有工作节点
ssh-copy-id worker-1
ssh-copy-id worker-2

# 测试免密登录
ssh worker-1 "nvidia-smi"
```

**为什么这样写**：DeepSpeed 默认通过 SSH 在所有节点上启动训练进程。如果 SSH 需要密码，启动会挂起。

**无密码 SSH 的替代方案（云端/K8s）**：
在 Kubernetes 或某些云环境中，配置免密 SSH 较麻烦。DeepSpeed 支持 `--no_ssh` 模式：

```bash
# 在每个节点上分别执行，指定节点 rank 和主节点地址
deepspeed --hostfile=myhostfile --no_ssh --node_rank=0 \
    --master_addr=192.168.1.100 --master_port=29500 \
    train.py --deepspeed_config ds_config.json
```


## 四、编写 ds_config.json 文件
`ds_config.json` 是 DeepSpeed 的**核心配置文件**，所有优化策略、超参数都在此定义。

### 4.1 ZeRO 优化配置
#### ZeRO-1 配置（优化器状态分片）
```json
{
  "train_batch_size": "auto",
  "train_micro_batch_size_per_gpu": "auto",
  "gradient_accumulation_steps": "auto",
  "optimizer": {
    "type": "AdamW",
    "params": {
      "lr": 0.0001,
      "betas": [0.9, 0.999],
      "eps": 1e-8,
      "weight_decay": 0.01
    }
  },
  "zero_optimization": {
    "stage": 1
  },
  "fp16": {
    "enabled": true
  }
}
```

**为什么这样写**：ZeRO-1 只分片**优化器状态**（Adam 的动量和二阶矩）。4 张 GPU 时，每张卡只存 1/4 的优化器状态。仅按参数、梯度和优化器状态估算，单卡模型状态显存由 $16\Phi$ 降至约 $4\Phi + 12\Phi/4 = 7\Phi$，约节省 $16/7 \approx 2.29$ 倍；常说的"约 4×"是 GPU 数量趋于很大、且忽略未分片参数/梯度、激活值与通信缓冲后的理论渐近上限，不能当作 4 卡环境的实际节省倍率。

#### ZeRO-2 配置（优化器状态 + 梯度分片）
```json
{
  "train_batch_size": "auto",
  "train_micro_batch_size_per_gpu": "auto",
  "gradient_accumulation_steps": "auto",
  "optimizer": {
    "type": "AdamW",
    "params": {
      "lr": 0.0001,
      "betas": "auto",
      "eps": 1e-8,
      "weight_decay": 0.1
    }
  },
  "scheduler": {
    "type": "WarmupDecayLR",
    "params": {
      "total_num_steps": "auto",
      "warmup_max_lr": 0.0001,
      "warmup_num_steps": 400
    }
  },
  "zero_optimization": {
    "stage": 2,
    "allgather_partitions": true,
    "allgather_bucket_size": 2e8,
    "reduce_scatter": true,
    "reduce_bucket_size": 2e8,
    "overlap_comm": true,
    "contiguous_gradients": true
  },
  "fp16": {
    "enabled": true
  }
}
```

**为什么这样写**：ZeRO-2 在 ZeRO-1 基础上增加**梯度分片**。`overlap_comm: true` 让梯度通信与计算重叠，`contiguous_gradients: true` 让梯度内存连续，减少内存碎片。

#### ZeRO-3 配置（全分片：参数 + 梯度 + 优化器状态）
```json
{
  "train_batch_size": "auto",
  "train_micro_batch_size_per_gpu": "auto",
  "gradient_accumulation_steps": "auto",
  "optimizer": {
    "type": "AdamW",
    "params": {
      "lr": 5e-5,
      "betas": "auto",
      "eps": 1e-8,
      "weight_decay": 0.1
    }
  },
  "zero_optimization": {
    "stage": 3,
    "offload_optimizer": {
      "device": "cpu",
      "pin_memory": true
    },
    "offload_param": {
      "device": "cpu",
      "pin_memory": true
    },
    "overlap_comm": true,
    "contiguous_gradients": true,
    "reduce_bucket_size": 1e6,
    "stage3_prefetch_bucket_size": 1e6,
    "stage3_param_persistence_threshold": 1e5
  },
  "fp16": {
    "enabled": true
  },
  "gradient_clipping": 1.0
}
```

**为什么这样写**：ZeRO-3 将**参数也分片**到不同 GPU 上，单卡只保存当前计算所需的参数。`offload_optimizer` 和 `offload_param` 将数据进一步卸载到 CPU 内存甚至 NVMe 硬盘，使得**单卡可以训练百亿参数模型**。

### 4.2 关键参数详解
| 参数 | 含义 | 建议 |
|------|------|------|
| `train_batch_size` | 全局 batch size | 设为 `"auto"`，由 HuggingFace Trainer 自动计算 |
| `train_micro_batch_size_per_gpu` | 每卡 micro batch | 设为 `"auto"`，根据显存调整 |
| `gradient_accumulation_steps` | 梯度累积步数 | 设为 `"auto"`，用于等效扩大 batch |
| `zero_optimization.stage` | ZeRO 阶段 | 1/2/3，根据显存选择 |
| `fp16.enabled` | 混合精度训练 | `true`（V100/A100/H100） |
| `gradient_clipping` | 梯度裁剪阈值 | 1.0，防止梯度爆炸 |

**为什么这样写**：`"auto"` 是 DeepSpeed 与 HuggingFace Transformers 集成时的便利特性。Trainer 会自动将 `per_device_train_batch_size` 等参数传入 DeepSpeed，无需手动计算。


## 五、启动训练——`deepspeed --num_gpus=N`
### 5.1 单节点启动
```bash
# 使用本机所有 GPU
deepspeed train.py --deepspeed_config ds_config.json

# 指定使用 N 张 GPU
deepspeed --num_gpus=2 train.py --deepspeed_config ds_config.json

# 指定使用特定 GPU
deepspeed --include localhost:0,1 train.py --deepspeed_config ds_config.json
```

**为什么这样写**：`deepspeed` 命令是 DeepSpeed 的启动器，会自动处理进程创建、环境变量设置、NCCL 通信初始化。如果不指定 `--num_gpus`，DeepSpeed 会自动使用本机所有 GPU。

### 5.2 多节点启动
```bash
# 使用 hostfile 启动
deepspeed --hostfile=myhostfile train.py --deepspeed_config ds_config.json

# 限制节点和 GPU 数量
deepspeed --num_nodes=2 --num_gpus=4 --hostfile=myhostfile \
    train.py --deepspeed_config ds_config.json

# 排除特定资源
deepspeed --exclude="worker-2:0" --hostfile=myhostfile \
    train.py --deepspeed_config ds_config.json
```

**为什么这样写**：`--num_nodes` 和 `--num_gpus` 可以灵活限制使用的资源，方便在共享集群上调试。

### 5.3 与 HuggingFace Transformers 集成
HuggingFace Transformers 原生支持 DeepSpeed，只需在 `TrainingArguments` 中指定配置文件路径：

```python
from transformers import TrainingArguments, Trainer

training_args = TrainingArguments(
    output_dir="./output",
    deepspeed="ds_config.json",        # 指定 DeepSpeed 配置文件
    per_device_train_batch_size=4,
    num_train_epochs=3,
    fp16=True,
)

trainer = Trainer(
    model=model,
    args=training_args,
    train_dataset=train_dataset,
)

trainer.train()
```

**为什么这样写**：`Trainer` 会自动读取 `ds_config.json`，并在内部调用 `deepspeed.initialize()`。你不需要手动管理 DeepSpeed Engine，大大降低了使用门槛。

### 5.4 常用环境变量
DeepSpeed 支持通过环境变量覆盖配置，以下是分布式训练中最常用的几个：

```bash
# 1. 主节点地址和端口（多节点必需）
export MASTER_ADDR=192.168.1.100
export MASTER_PORT=29500

# 2. 限制可见 GPU
export CUDA_VISIBLE_DEVICES=0,1,2,3

# 3. NCCL 通信优化（多节点）
export NCCL_IB_DISABLE=0        # 启用 InfiniBand
export NCCL_SOCKET_IFNAME=eth0  # 指定通信网卡
export NCCL_ALGO=Tree           # 通信算法

# 4. DeepSpeed 日志级别
export DEEPSPEED_LOG_LEVEL=INFO
```

**为什么这样写**：部分环境变量（如 `MASTER_ADDR`/`MASTER_PORT`、`CUDA_VISIBLE_DEVICES`、NCCL 系列）在分布式启动中很常用，可在调试或快速实验时临时调整而无需改动代码。

> **说明**：`DEEPSPEED_LOG_LEVEL` 等变量的支持情况与命名可能随 DeepSpeed 版本演进而变化，使用前建议以所用版本的官方文档 / `deepspeed --help` 为准。
>
> **关于 ZeRO 阶段的设置**：ZeRO 阶段请统一在 `ds_config.json` 的 `zero_optimization.stage` 中显式设置，这是官方稳定、可复现的方式。网上流传的 `export DEEPSPEED_ZERO_STAGE=...` 之类"用环境变量覆盖 ZeRO 阶段"的写法，并非常规、稳定的官方接口，不同版本行为不一致，容易被误认为可靠地覆盖配置文件，本教程不建议使用。

### 5.5 环境变量持久化
在多节点环境中，确保所有节点共享相同的环境变量：

```bash
# 方法1：写入 .deepspeed_env 文件（DeepSpeed 自动读取）
echo "NCCL_IB_DISABLE=1" >> .deepspeed_env
echo "NCCL_SOCKET_IFNAME=eth0" >> .deepspeed_env

# 方法2：通过 DS_ENV_FILE 指定自定义环境文件
export DS_ENV_FILE=/path/to/my_env.conf
```

**为什么这样写**：`.deepspeed_env` 文件会被 DeepSpeed launcher 自动传播到所有节点，避免手动在每个节点上 export。


## 六、环境验证实验
### 6.1 最小验证脚本
创建 `test_deepspeed.py`：

```python
import torch
import deepspeed

# 检查 DeepSpeed 版本
print(f"DeepSpeed version: {deepspeed.__version__}")

# 检查 GPU 可用性
print(f"PyTorch CUDA available: {torch.cuda.is_available()}")
print(f"GPU count: {torch.cuda.device_count()}")

# 检查当前加速器
from deepspeed.accelerator import get_accelerator
print(f"Accelerator: {get_accelerator()._name}")

# 简单的分布式通信测试
if torch.cuda.is_available() and torch.cuda.device_count() >= 2:
    deepspeed.init_distributed()
    rank = torch.distributed.get_rank()
    world_size = torch.distributed.get_world_size()
    print(f"Rank: {rank}, World Size: {world_size}")

    # All-reduce 测试
    tensor = torch.ones(1).cuda()
    torch.distributed.all_reduce(tensor)
    print(f"Rank {rank}: All-reduce result = {tensor.item()}")
```

### 6.2 运行验证
```bash
# 单卡验证
python test_deepspeed.py

# 双卡验证
deepspeed --num_gpus=2 test_deepspeed.py
```

**预期输出**（2 卡）：

```
Rank: 0, World Size: 2
Rank 0: All-reduce result = 2.0
Rank: 1, World Size: 2
Rank 1: All-reduce result = 2.0
```

**为什么这样写**：`all_reduce` 将两张卡的 `tensor` 相加，结果应为 2.0。如果输出正确，说明 NCCL 通信正常，多卡环境配置成功。


## 七、常见问题排查
| 问题 | 现象 | 解决方案 |
|------|------|---------|
| **NCCL 通信失败** | `NCCL error: unhandled system error` | 检查 `MASTER_ADDR` 和 `MASTER_PORT`；确认防火墙放行；设置 `NCCL_IB_DISABLE=1` 回退到以太网 |
| **显存不足（OOM）** | `CUDA out of memory` | 启用 ZeRO-3 + CPU Offload；减小 `per_device_train_batch_size`；启用梯度检查点 |
| **SSH 免密失败** | 启动时卡住，要求输入密码 | 配置 `ssh-copy-id`；或使用 `--no_ssh` 模式 |
| **CUDA 版本不匹配** | `ds_report` 显示算子不兼容 | 重新安装匹配 CUDA 版本的 PyTorch 和 DeepSpeed |
| **进程挂起** | 训练开始但无输出 | 设置 `DEEPSPEED_LOG_LEVEL=DEBUG`；检查 hostfile 中的 slots 是否正确 |
| **梯度不同步** | 多卡 loss 不一致 | 确认 `deepspeed.init_distributed()` 已调用；检查 NCCL 环境 |
