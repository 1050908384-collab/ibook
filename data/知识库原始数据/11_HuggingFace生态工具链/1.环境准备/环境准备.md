# 一、先理解 Hugging Face 生态工具链（参考文章③）

## 1.1 Hugging Face是什么？

Hugging Face 是目前大语言模型开发中最常用的开源生态之一。

它主要包含：

| 工具               | 作用                    |
| ---------------- | --------------------- |
| Transformers     | 加载、训练、推理Transformer模型 |
| Datasets         | 加载和处理训练数据             |
| Accelerate       | 简化单卡、多卡、混合精度训练        |
| Hugging Face Hub | 模型、数据集和代码共享平台         |

整体学习流程：

```
Tokenizer
    ↓
Transformers加载模型
    ↓
Datasets处理数据
    ↓
Accelerate优化训练
    ↓
Trainer完成微调
    ↓
LoRA / QLoRA
    ↓
部署推理
```

下面为**带条件的经验参考**（实际显存取决于模型精度、上下文长度、batch、是否量化、KV Cache、是否训练等，请以实际运行为准）：

| 任务     | 经验参考显存  | 主要前提条件（示例）  |
| ------ | ----- | ----- |
| 小模型测试  | 约 4GB+  | 数亿~1B 级模型、FP16/BF16、短上下文、batch=1、纯推理 |
| 7B模型推理 | 约 12GB+ | 7B、FP16/BF16、上下文数百~2K、batch=1、含 KV Cache；若 4-bit 量化可更低 |
| 模型微调   | 约 16GB+ | 与方式强相关：全参数微调远高于此；LoRA/QLoRA 通常明显更低，且随序列长度/batch/梯度累积/是否梯度检查点变化 |

> 说明：上表**不是通用门槛**，只给出量级直觉。同一数字能否跑起来，取决于精度（FP32/FP16/BF16/4-bit）、上下文/序列长度、batch size、是否量化、KV Cache 大小、以及是训练还是推理、用哪种微调方式（全参 vs LoRA vs QLoRA）。请以实际运行为准，并参考后续 11.4 / 12.x 各章更具体的条件说明。

## 6.1 关于版本：请固定一套"已验证版本矩阵"（重要）

本文（以及第 11、12 板块其余文章）中的安装命令**默认不锁定版本**，方便快速上手。但 Transformers / PEFT / Accelerate / Datasets / bitsandbytes 迭代较快，后文涉及的 `evaluation_strategy` → `eval_strategy`、`tokenizer=` → `processing_class=`、4-bit 量化加载、`merge_and_unload` 等行为**会随版本变化**（出现警告、报错或行为差异）。

因此在正式实验/教学前，建议**实际跑通一次并记录一套版本矩阵**，之后统一用它安装，避免"文档能跑、学员环境报错"。至少记录：

| 组件 | 版本 | 备注 |
| ---- | ---- | ---- |
| 操作系统 | 例：Ubuntu 22.04 / Windows 11 | 注明是否 WSL2 |
| GPU / 驱动 | 例：RTX 4090 / 驱动 5xx | 无 GPU 则填 CPU |
| Python | 例：3.10 |  |
| PyTorch | 例：2.x | 注明 CPU / CUDA(cuXXX) / ROCm |
| CUDA / ROCm | 例：cu121 | 与 PyTorch 对应 |
| Transformers | 例：4.xx |  |
| Datasets | 例：2.xx / 3.xx |  |
| Accelerate | 例：0.xx / 1.xx |  |
| PEFT | 例：0.xx | 第 12 板块用 |
| bitsandbytes | 例：0.xx | QLoRA 用，注明后端支持 |

> 建议同时记录**测试日期**和**当次使用的安装命令**（可直接 `pip freeze > requirements.txt` 附在项目里）。本文示例版本仅为占位，请以你实际验证通过的版本为准；上述具体版本号不代表推荐或已验证组合。

# 九、配置模型缓存路径（重点）

## 9.1 为什么修改缓存？

默认：

Linux：

```
~/.cache/huggingface
```

Windows：

```
C:\Users\用户名\.cache\huggingface
```

模型可能占用：

| 模型    | 空间   |
| ----- | ---- |
| GPT-2 | 几百MB |
| 7B模型  | 十几GB |
| 70B模型 | 百GB  |

建议提前修改。

> 变量说明：
> - `HF_HOME`：Hugging Face 相关文件的总根目录（包含模型/数据集下载缓存、token 等），作用范围最广，改它通常就够用；
> - `HF_HUB_CACHE`：只影响从 Hub 下载的模型/数据集**缓存**目录，粒度更细；
> - 旧变量 `TRANSFORMERS_CACHE` 已弃用，新项目请优先用 `HF_HOME`。
>
> 若同时设置，细粒度变量（如 `HF_HUB_CACHE`）会覆盖 `HF_HOME` 推导出的对应子目录。

## PyTorch 与 GPU（有 GPU 时建议验证）

只验证 Transformers/Datasets/Accelerate 能导入**不足以**确认 GPU 可用。若要用 GPU，还应验证 PyTorch 的 CUDA 状态、编译 CUDA 版本，以及模型是否真的放到了 GPU 上：

```python
import torch
from transformers import AutoModel

print(torch.__version__)
print(torch.cuda.is_available())        # 期望 True（有可用 GPU 时）
print(torch.version.cuda)               # torch 编译时的 CUDA 版本
if torch.cuda.is_available():
    print(torch.cuda.get_device_name(0))

# 确认模型确实加载到了 GPU
model = AutoModel.from_pretrained("bert-base-uncased")
model.to("cuda" if torch.cuda.is_available() else "cpu")
print(next(model.parameters()).device)  # 期望 cuda:0（使用 GPU 时）
```

✅ `is_available()` 为 True、`version.cuda` 与你的环境匹配、参数 device 为 `cuda:0`

> 说明：`torch.cuda.is_available()=True` 说明 PyTorch 能用 GPU，但**不等于** bitsandbytes 4-bit 量化等更上层功能一定可用（后者见第 12 板块）。
