## 一、为什么需要正则表达式？（①+③）

在处理文本数据时，你经常会遇到这样的需求：（①）

- 从一段杂乱的日志中提取时间戳和错误级别
- 把用户输入的手机号中间四位脱敏
- 清除网页爬取内容中的 HTML 标签
- 验证邮箱格式是否正确
- 从文章中提取所有中文词汇

这些任务如果只用字符串的 `split()`、`replace()` 等方法，代码会又臭又长。正则表达式（Regular Expression）就是专门描述**字符串模式**的规则语言，配合 Python 的 `re` 模块，几行代码就能搞定复杂的文本处理。（①+③）

## 二、正则语法速查（②+③）

正则表达式的核心是**元字符**——具有特殊含义的符号。以下是处理文本时最常用的元字符：

### 2.1 匹配字符类（②+③）

| 元字符 | 含义 | 示例 |
|--------|------|------|
| `.` | 匹配除换行符外的任意单个字符 | `a.b` 匹配 "acb"、"a1b" |
| `\d` | 匹配数字（0-9） | `\d{4}` 匹配四位数字 |
| `\D` | 匹配非数字 | `\D+` 匹配连续非数字 |
| `\w` | 匹配单词字符（字母、数字、下划线） | `\w+` 匹配一个单词 |
| `\W` | 匹配非单词字符（标点、空格等） | `\W` 匹配标点 |
| `\s` | 匹配空白符（空格、制表符、换行等） | `\s+` 匹配连续空白 |
| `\S` | 匹配非空白字符 | `\S*` 匹配非空字符串 |
| `[abc]` | 匹配方括号内的任意一个字符 | `[aeiou]` 匹配元音 |
| `[^abc]` | 匹配不在方括号内的字符 | `[^0-9]` 匹配非数字 |
| `[a-z]` | 匹配指定范围内的字符 | `[A-Z]` 匹配大写字母 |

### 2.2 量词：控制匹配次数（②+③）

| 量词 | 含义 | 示例 |
|------|------|------|
| `*` | 零次或多次 | `a*b` 匹配 "b"、"ab"、"aab" |
| `+` | 一次或多次 | `a+b` 匹配 "ab"、"aab" |
| `?` | 零次或一次 | `colou?r` 匹配 "color"和"colour" |
| `{n}` | 精确匹配 n 次 | `\d{4}` 匹配四位数字 |
| `{n,m}` | 匹配 n 到 m 次 | `\d{2,4}` 匹配 2-4 位数字 |

### 2.3 定位符与分组（②+③）

| 符号 | 含义 |
|------|------|
| `^` | 匹配字符串开头 |
| `$` | 匹配字符串结尾 |
| `\b` | 匹配单词边界 |
| `()` | 分组捕获，用于提取局部内容 |
| `\|` | 逻辑"或" |
| `\1` `\2` | 反向引用第 1、2 个分组 |

### 2.4 贪婪 vs 非贪婪（①+②+③）

- **贪婪（默认）**：尽可能多地匹配
- **非贪婪**：在量词后加 `?`，尽可能少地匹配

```python
html = "<div>标题1</div><div>标题2</div>"

# 贪婪：匹配到最后一个 </div>
re.findall(r"<div>.*</div>", html)
# ['<div>标题1</div><div>标题2</div>']

# 非贪婪：逐个匹配
re.findall(r"<div>.*?</div>", html)
# ['<div>标题1</div>', '<div>标题2</div>']
```

> **当起止分隔符可能重复出现时，通常应使用非贪婪 `.*?`**，避免一次性匹配过多内容；具体模式仍需结合文本结构设计。（①）

## 三、re 模块五大核心方法（①+②）

| 方法 | 作用 | 适用场景 |
|------|------|---------|
| `re.match()` | 从字符串**开头**匹配 | 完整格式校验（身份证、手机号） |
| `re.search()` | 扫描**全文**，返回第一个匹配 | 从杂乱文本中提取单个信息 |
| `re.findall()` | 返回**所有**匹配的列表 | 批量提取（最常用） |
| `re.sub()` | 替换匹配到的内容 | 数据脱敏、清洗无用字符 |
| `re.split()` | 按正则分割字符串 | 多分隔符分割脏文本 |

> **最佳实践**：正则表达式字符串前加 `r`，表示原始字符串，避免反斜杠 `\` 的转义问题。例如 `r"\d+"` 而不是 `"\d+"`。（①+②）

## 四、实战：文本清洗三步走（①+③）

文本清洗可以归纳为三个步骤：**去噪音 → 标准化 → 提取信息**。（③）

### 4.1 去噪音：清除无用字符（①+③）

**清除 HTML 标签**

```python
import re

html_text = "<p>这是一段<b>加粗</b>的文本</p>"
clean = re.sub(r"<[^>]+>", "", html_text)
print(clean)  # 这是一段加粗的文本
```

**清除特殊符号，只保留中文、英文和数字**（①）

```python
text = "你好！@#￥%Python正则&*实战~"
clean = re.sub(r"[^\u4e00-\u9fa5a-zA-Z0-9]", "", text)
print(clean)  # 你好Python正则实战
```

> `[^\u4e00-\u9fa5a-zA-Z0-9]` 表示"非中文、非英文、非数字"的所有字符。（①）

**合并连续空白**

```python
text = "  这   段  文本   空白   太多  "
clean = re.sub(r"\s+", " ", text).strip()
print(clean)  # 这段 文本 空白 太多
```

### 4.2 标准化：统一格式（③）

**日期格式统一**

```python
text = "出生日期：05/23/1998"
# 将 MM/DD/YYYY 转为 YYYY-MM-DD
result = re.sub(r"(\d{2})/(\d{2})/(\d{4})", r"\3-\1-\2", text)
print(result)  # 出生日期：1998-05-23
```

> `\1` `\2` `\3` 分别引用第 1、2、3 个括号分组匹配到的内容。（②）

### 4.3 提取信息：从文本中捕获目标（①+③）

**提取所有中文**

```python
text = "Python正则2026实战，提取中文，123测试数据"
chinese = re.findall(r"[\u4e00-\u9fa5]+", text)
print(chinese)  # ['正则', '实战', '提取中文', '测试数据']
```

**提取所有数字**

```python
text = "订单1：599元，订单2：1299元，运费20元"
nums = re.findall(r"\d+", text)
print(nums)  # ['599', '1299', '20']
```

**提取 URL**

```python
text = "我的博客：https://blog.csdn.net，备用：http://www.example.com"
urls = re.findall(r"https?://\S+", text)
print(urls)  # ['https://blog.csdn.net，备用：http://www.example.com']
# 注意：上面的正则会把后面的中文也匹配进去，改进如下：
urls = re.findall(r"https?://[a-zA-Z0-9.-]+", text)
print(urls)  # ['https://blog.csdn.net', 'http://www.example.com']
```

## 五、实战：数据脱敏与验证（①+②）

### 5.1 手机号脱敏（①）

```python
text = "用户1：13812345678，用户2：15987654321"

# 保留前3位和后4位，中间替换为 ****
result = re.sub(r"(1[3-9]\d)\d{4}(\d{4})", r"\1****\2", text)
print(result)
# 用户1：138****5678，用户2：159****4321
```

### 5.2 邮箱格式验证（②+③）

```python
def is_valid_email(email):
    pattern = r"^\w+([.-]?\w+)*@\w+([.-]?\w+)*(\.\w{2,})+$"
    return re.match(pattern, email) is not None

print(is_valid_email("test@example.com"))   # True
print(is_valid_email("invalid-email"))      # False
```

> `re.match()` 从字符串开头匹配，配合 `^` 和 `$` 可实现严格的完整格式校验。（②）

### 5.3 身份证号格式初筛（①）

```python
def is_valid_id(id_card):
    pattern = r"^[1-9]\d{5}(19|20)\d{2}(0[1-9]|1[0-2])(0[1-9]|[12]\d|3[01])\d{3}[\dXx]$"
    return re.match(pattern, id_card) is not None

print(is_valid_id("34012320000101123X"))  # True
print(is_valid_id("123456"))              # False
```

> 上述正则只能初步检查长度、日期字段形状和末位格式，**不能**验证地区码、真实日期或校验位；需要严格校验时应使用专门的身份证校验逻辑。

## 六、实战：结构化日志解析（①+③）

综合使用分组提取，从日志中解析结构化信息：

```python
log_text = """
2026-05-23 10:20:30 INFO: 用户test登录成功
2026-05-23 10:21:10 ERROR: 接口请求超时
2026-05-23 10:22:00 WARN: 内存占用过高
"""

pattern = r"(\d{4}-\d{2}-\d{2}\s\d{2}:\d{2}:\d{2})\s(\w+):\s(.+)"
results = re.findall(pattern, log_text)

for time, level, msg in results:
    print(f"时间：{time} | 级别：{level} | 内容：{msg}")
```

输出：

```
时间：2026-05-23 10:20:30 | 级别：INFO | 内容：用户test登录成功
时间：2026-05-23 10:21:10 | 级别：ERROR | 内容：接口请求超时
时间：2026-05-23 10:22:00 | 级别：WARN | 内容：内存占用过高
```

## 八、常见问题与解决（①+②+③）

| 症状 | 可能原因 | 解决方案 |
|------|---------|---------|
| 正则匹配不到中文 | 未使用 `[\u4e00-\u9fa5]` | 中文字符用 Unicode 范围匹配 |
| `re.sub` 后中文变 `\uXXXX` | 与正则无关，是输出编码问题 | 确保文件编码为 UTF-8 |
| 贪婪匹配结果过大 | 使用了 `.*` 而非 `.*?` | 提取多组内容时用非贪婪 `.*?` |
| 反斜杠 `\d` 报错 | 未使用原始字符串 `r""` | 正则前加 `r`，如 `r"\d+"` |
| `re.match` 明明有内容却返回 None | `match` 只从开头匹配 | 全文查找用 `re.search` 或 `re.findall` |
| 分组引用 `\1` 无效 | 括号用了中文括号 | 确保使用英文括号 `()` |
| 正则越来越复杂难以维护 | 试图用一行正则解决所有问题 | 拆分为多步处理，或配合字符串方法 |
