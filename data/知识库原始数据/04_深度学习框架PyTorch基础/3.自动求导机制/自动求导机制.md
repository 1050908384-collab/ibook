## 一、为什么需要自动求导？（①）

神经网络的训练过程可以概括为一句话：**不断调整参数，让损失函数变小**。而"怎么调整"取决于**损失函数对每个参数的梯度**（即导数）。（①）

如果手动推导梯度，哪怕是一个简单的三层全连接网络，链式法则的公式也会写满一页纸。PyTorch 的 **Autograd（自动求导）** 引擎帮你做了这件事：你只需要定义前向计算过程，PyTorch 会自动构建计算图，并在调用 `.backward()` 时反向遍历这张图，算出所有需要梯度的参数的导数。（①+②）

> **官方文档**：PyTorch Autograd 机制完整说明 https://pytorch.org/docs/stable/autograd.html

## 二、计算图：Autograd 的"地图"（①）

### 2.1 什么是计算图？（①）

计算图是 PyTorch 用来记录张量运算过程的**有向无环图（DAG）**。（①+②）

- **节点（Node）**：张量（Tensor）
- **边（Edge）**：运算操作（如加减乘除、矩阵乘法）
- **前向传播（Forward）**：从输入计算输出，同时构建计算图
- **反向传播（Backward）**：从输出反向遍历图，利用链式法则求导

举个例子，计算 $y = x_1 \cdot w + x_2$：

```
x1 ────┐
        × ──── + ──── y
w  ────┘     ↑
x2 ──────────┘
```

PyTorch 会自动把这个运算流程记录下来，形成一张"地图"。当你调用 `y.backward()` 时，它就沿着这张地图从后往前算梯度。（①）

### 2.2 动态计算图（①+②）

PyTorch 使用的是**动态计算图**（Dynamic Computation Graph）——图是在代码**运行时**逐行构建的，每次前向传播都可以不一样。（②）

这与早期 TensorFlow 的静态图形成对比。动态图的好处是：你可以像写普通 Python 代码一样，在模型里用 `if`、`for` 等控制流，PyTorch 会根据实际执行路径自动记录操作序列。（②）

```python
import torch

def dynamic_net(x):
    # 动态控制流：根据输入决定走哪条路
    if x.sum() > 0:
        return x * 2
    else:
        return x * 3

x = torch.tensor([1.0, -1.0], requires_grad=True)
y = dynamic_net(x).sum()
y.backward()
print(x.grad)   # 根据实际路径正确计算梯度
```

## 三、核心 API：requires_grad、backward、grad（①+③）

### 3.1 requires_grad：标记"谁需要求导"（①+③）

只有设置了 `requires_grad=True` 的张量，才会被加入计算图、参与梯度计算。（①）

```python
import torch

# 叶子节点：用户直接创建的张量，通常作为模型参数或输入
x = torch.tensor(2.0, requires_grad=True)   # 需要求导
w = torch.tensor(3.0, requires_grad=True)   # 需要求导
b = torch.tensor(1.0, requires_grad=False)  # 不需要求导（默认）

print(x.is_leaf)   # True  ← 叶子节点
print(w.is_leaf)   # True
```

> **叶子节点（Leaf Node）**：由用户直接创建、而非通过运算生成的张量。模型中的 `nn.Parameter` 也是叶子节点。只有叶子节点会保存 `.grad`，非叶子节点的梯度默认不存储（节省内存）。（③）

### 3.2 前向传播：自动构建计算图（①）

```python
# 前向计算：PyTorch 在后台默默记录每一步操作
y = w * x + b
print(y)           # tensor(7., grad_fn=<AddBackward0>)
print(y.grad_fn)   # <AddBackward0>  ← 记录了"y是通过加法得到的"
```

`grad_fn` 是计算图的"连线"——它知道如何对这个运算进行反向求导。（①）

### 3.3 反向传播：backward()（①）

调用输出张量的 `.backward()`，触发自动求导：

```python
y.backward()       # 反向传播，计算所有叶子节点的梯度

print(x.grad)      # dy/dx = w = 3.0
print(w.grad)      # dy/dw = x = 2.0
print(b.grad)      # None  ← b 的 requires_grad=False，不求导
```

> **注意**：`.backward()` 默认只能对标量（单个数值）调用。如果 `y` 是张量（多个值），需要传入权重参数，例如 `y.backward(torch.ones_like(y))`，或者先求平均 `y.mean().backward()`。（①）

### 3.4 梯度累加：为什么要清零？（①+④）

PyTorch 的 `.grad` 属性是**累加**的，而不是覆盖。这意味着如果你连续两次调用 `backward()`，第二次的梯度会**加到第一次的结果上**。（④）

```python
# 第一次反向传播
y = w * x + b
y.backward()
print(w.grad)      # 2.0

# 第二次反向传播（没有清零）
y = w * x + b
y.backward()
print(w.grad)      # 4.0  ← 累加了！2.0 + 2.0
```

这在标准训练中是不希望发生的。因此在每次迭代开始时，必须**清零梯度**：（④）

```python
# 手动清零
w.grad.zero_()
x.grad.zero_()

# 或者用优化器统一清零（后续 torch.nn 章节会详细讲解）
optimizer.zero_grad()
```

## 四、停止梯度追踪的两种方法（①+⑤）

在某些场景下，你不需要计算梯度，例如模型推理、冻结部分网络、或者把 Tensor 转成 NumPy。这时需要停止梯度追踪。

### 4.1 torch.no_grad()：整段代码不建图（①+⑤）

`torch.no_grad()` 是一个上下文管理器，进入该上下文后，所有操作都不会被记录到计算图中。这是**推理阶段的标准做法**，能节省显存和计算。（①+⑤）

```python
with torch.no_grad():
    pred = model(x)      # 不构建计算图，速度更快，省内存
    accuracy = (pred == label).float().mean()
```

### 4.2 detach()：单个张量"摘"出计算图（⑤）

`.detach()` 返回一个新的张量，**与原张量共享数据**，但不再有 `grad_fn`，`requires_grad=False`。它只影响从它开始的新分支，不会破坏原计算图。（⑤）

```python
x = torch.tensor([2.0, 3.0], requires_grad=True)
y = x ** 2

# detach：把 y 从计算图中"摘下来"
y_detached = y.detach()
z = y_detached * 3

# z 对 x 的梯度？不会传播到 x，因为 y_detached 已经断了
# z.backward()  # 如果调用，只会影响 y_detached，不会回传到 x
```

**detach 的典型应用场景**：（⑤）

| 场景 | 代码 | 说明 |
|---|---|---|
| 推理转 NumPy | `pred.detach().numpy()` | NumPy 不接受需要梯度的 Tensor |
| 冻结部分网络 | `h = encoder(x).detach()` | 只训练 decoder，不更新 encoder |
| 作为常数使用 | `y_const = y.detach()` | 后续把 y 当常数参与计算 |

### 4.3 no_grad vs detach vs eval 对比（⑤）

| 方法 | 作用范围 | 是否构建计算图 | 典型场景 |
|---|---|---|---|
| `torch.no_grad()` | 整段代码块 | 不构建 | 模型推理、验证 |
| `.detach()` | 单个张量 | 该张量后续不构建 | 冻结子网络、转 NumPy |
| `model.eval()` | 模型行为 | 与梯度无关 | 关闭 Dropout/BatchNorm 训练模式 |

> `model.eval()` 只是改变模型中某些层的行为（如 Dropout 停止随机失活），**不会关闭梯度计算**。推理时通常 `model.eval()` 和 `torch.no_grad()` 一起用。（⑤）

## 五、叶子节点与非叶子节点（③）

### 5.1 核心区别

| 特性 | 叶子节点 | 非叶子节点 |
|---|---|---|
| 创建方式 | 用户直接创建 | 通过运算生成 |
| `is_leaf` | `True` | `False` |
| `.grad` 存储 | ✅ 保存 | ❌ 默认不保存（省内存） |
| 典型例子 | `torch.tensor(..., requires_grad=True)`、`nn.Parameter` | `y = x * w` 中的 `y` |

### 5.2 保留非叶子节点的梯度（③）

如果确实需要查看中间结果的梯度，可以用 `.retain_grad()`：

```python
x = torch.tensor(2.0, requires_grad=True)
y = x ** 2
y.retain_grad()    # 显式保留 y 的梯度
z = y * 3
z.backward()

print(y.grad)      # 3.0  ← 如果没有 retain_grad()，这里是 None
print(x.grad)      # 12.0
```

## 六、标准训练循环：Autograd 的实际应用（①+④）

把前面学的知识串起来，一个典型的 PyTorch 训练循环长这样：（①+④）

```python
import torch
import torch.nn as nn

# 假设模型、数据、损失函数和优化器已定义（后续章节详细讲解）
model = nn.Linear(10, 1)           # 简单线性模型
optimizer = torch.optim.SGD(model.parameters(), lr=0.01)
criterion = nn.MSELoss()

for epoch in range(100):
    # 1. 前向传播
    pred = model(x)
    loss = criterion(pred, y)

    # 2. 清零旧梯度（必须！否则累加）
    optimizer.zero_grad()

    # 3. 反向传播：自动计算所有参数的梯度
    loss.backward()

    # 4. 更新参数：优化器根据梯度调整权重
    optimizer.step()
```

**四步口诀**：前向 → 清零 → 反向 → 更新。（①）

## 七、综合实战演练（①+③+④+⑤）

请在你的 Python 环境中完成以下操作：

### 场景 1：手动验证链式法则

```python
import torch

# 定义参数
x = torch.tensor(2.0, requires_grad=True)
w1 = torch.tensor(3.0, requires_grad=True)
w2 = torch.tensor(4.0, requires_grad=True)

# 前向：y = (x * w1) ** 2 + w2
h = x * w1          # h = 6
y = h ** 2 + w2     # y = 36 + 4 = 40

# 反向
y.backward()

# 手动验证：
# dy/dh = 2*h = 12
# dh/dx = w1 = 3    → dy/dx = 12 * 3 = 36
# dh/dw1 = x = 2    → dy/dw1 = 12 * 2 = 24
# dy/dw2 = 1

print(f"x.grad = {x.grad}")     # 应输出 36.0
print(f"w1.grad = {w1.grad}")   # 应输出 24.0
print(f"w2.grad = {w2.grad}")   # 应输出 1.0
```

### 场景 2：观察梯度累加

```python
x = torch.tensor(2.0, requires_grad=True)

for i in range(3):
    y = x ** 2
    y.backward()
    print(f"第{i+1}次 backward 后, x.grad = {x.grad}")
    # 注意：没有 zero_grad()，梯度会累加！
    # 第1次: 4.0
    # 第2次: 8.0  (4+4)
    # 第3次: 12.0 (4+4+4)

# 清零
x.grad.zero_()
print(f"清零后, x.grad = {x.grad}")   # 0.0
```

### 场景 3：detach 冻结中间结果

```python
x = torch.tensor(2.0, requires_grad=True)
y = x ** 2          # y = 4

# 正常情况：z = y * 3，梯度会回传到 x
z1 = y * 3
z1.backward()
print(f"正常反向: x.grad = {x.grad}")   # 12.0

# 使用 detach：y 被"冻结"为常数
x.grad.zero_()
y_detached = y.detach()
z2 = y_detached * 3
z2.backward()
print(f"detach 后: x.grad = {x.grad}")  # 0.0  ← 梯度传不到 x 了！
```

## 八、常见问题与解决（①+③+④+⑤）

| 症状 | 可能原因 | 解决方案 |
|---|---|---|
| `backward()` 报错 `grad can be implicitly created only for scalar outputs` | 对非标量张量直接调用 `backward()` | 先 `.mean()` 或 `.sum()` 变成标量，或传入 `torch.ones_like(y)` |
| 梯度值越来越大 / 模型不收敛 | 忘记 `zero_grad()`，梯度累加 | 每次迭代开始时调用 `optimizer.zero_grad()` |
| `x.grad` 是 `None` | `x` 不是叶子节点，或 `requires_grad=False` | 检查 `x.is_leaf` 和 `x.requires_grad` |
| 推理时显存爆炸 | 没有关闭梯度追踪 | 用 `with torch.no_grad():` 包裹推理代码 |
| `pred.numpy()` 报错 | Tensor 仍在计算图中 | 先 `.detach()` 再 `.numpy()` |
| 原地操作报错 `a leaf Variable that requires grad is being modified in-place` | 对需要梯度的叶子节点做了 `x += 1` 等原地操作 | 改用 `x = x + 1` |
| 需要多次 backward | 第一次后计算图被销毁 | 第一次 `backward(retain_graph=True)` |
