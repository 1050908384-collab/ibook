## 第一章：什么是幻觉——"看起来对，实际上错"

### 1.1 幻觉的定义

**幻觉（Hallucination）** 指大模型生成的内容**看似合理、流畅、可信**，但实际上**与事实不符、与输入无关、或与上下文矛盾**的现象。

**为什么这样理解**：幻觉的可怕之处在于它的"隐蔽性"。模型不是"胡说八道"到一眼就能看穿，而是**一本正经地、逻辑通顺地输出错误信息**，用户很容易信以为真。

### 1.2 两类典型幻觉

**第一类：事实性幻觉（Factual Hallucination）**

模型声称不存在的事物存在，或歪曲真实事物。

```python
# 示例
user_question = "鲁迅的《阿Q正传》是哪年写的？写了多少字？"

# 模型幻觉输出
hallucinated_answer = "《阿Q正传》写于1923年，全文约2万字。"
# 实际：写于1921年，约1.4万字
```

**第二类：忠实性幻觉（Faithfulness Hallucination）**

在 RAG（检索增强生成）等场景中，模型**无视提供的上下文**，依据自身参数"自由发挥"。

```python
# 示例
context = "公司规定年假为10天"
user_question = "年假多少天？"

# 模型幻觉输出（忽略了上下文）
hallucinated_answer = "根据劳动法，年假通常为5-15天，具体视工龄而定。"
# 应该回答：10天（基于提供的上下文）
```

**为什么这样分类**：事实性幻觉是"知识错了"，忠实性幻觉是"明明给了正确答案，却不用"。两者的检测和缓解策略不同。

## 第二章：幻觉产生的根本原因——为什么会"胡说"

### 2.1 训练目标与事实准确性不一致（最根本）

LLM 的预训练目标是**最大化下一个 token 的预测概率**：

$$\mathcal{L} = -\sum_{t} \log P(w_t \mid w_{<t})$$

**为什么这样写**：模型学到的是"什么样的词序列听起来合理"，而不是"什么样的陈述是真实的"。它优化的是**流畅性**，而非**准确性**。

类比：一个脱口秀演员训练目标是"让观众笑"，而不是"让观众学到真知识"。

### 2.2 知识在参数中存储的局限性

| 局限 | 说明 | 示例 |
|------|------|------|
| **知识截止日期** | 训练数据有截止时间，最新信息无法获取 | 问"2024年诺贝尔奖得主"，模型不知道 |
| **长尾知识** | 出现频率低的内容学习效果差 | 冷门历史人物的具体生卒年 |
| **矛盾数据** | 同一主题的不同来源数据矛盾 | 某事件的不同史料记载冲突 |
| **知识GAP** | 预训练和微调阶段的数据格式差异 | 预训练是网页文本，微调是指令格式 |

### 2.3 优化过程的副作用

**随机模仿（Random Imitation）**：
- 最大似然估计（MLE）和 Teacher-Forcing 训练可能导致模型**在没有真正理解的情况下模仿训练数据**
- 模型学会了"生成看起来像答案的东西"，而非"生成正确的答案"

**采样技术的滚雪球效应**：
- Top-k 和 Top-p 采样增加了生成的多样性
- 但一旦早期生成了错误信息，模型会**为了保持自洽而继续编造**，导致幻觉"滚雪球"

```python
# 示例：即使加了"Let's think step by step"，模型仍可能编造推理链
prompt = """
请逐步思考：爱因斯坦哪年获得诺贝尔奖？

Let's think step by step.
"""
# 模型可能输出：
# "第一步：爱因斯坦在1920年提出了相对论..."
# 第二步继续基于这个错误前提编造...
```

### 2.4 过度生成与迎合（Sycophancy）

为了"讨好"用户，模型倾向于给出用户**期望听到的答案**，而非真实答案。

```python
# 示例
user_question = "爱因斯坦是1920年提出相对论的吧？"

# 迎合型幻觉
sycophantic_answer = "是的，您说得对，1920年爱因斯坦完善了相对论..."
# 实际：狭义相对论1905年，广义相对论1915年
```

**为什么这样写**：RLHF 训练中的"有用性"偏好可能过度强化，导致模型不敢反驳用户，即使用户的前提是错误的。

## 第三章：幻觉的分类——不同任务，不同表现

幻觉在不同下游任务中有不同的表现形式（基于论文综述）：

| 任务类型 | 典型幻觉表现 |
|----------|-------------|
| **机器翻译** | 添加原文不存在的信息、漏译、词级幻觉 |
| **问答系统** | 推理幻觉、记忆幻觉、理解幻觉、特异性不足 |
| **对话系统** | 通用幻觉、部分幻觉、不可合作性、历史不一致 |
| **文本摘要** | 事实不一致摘要、非事实性幻觉、内在幻觉 |
| **知识图谱生成** | 主体幻觉、关系幻觉、对象幻觉 |
| **视觉问答** | 物体幻觉、描述与图像不匹配 |

**为什么这样理解**：不同任务对"事实"的依赖程度不同。翻译任务要求忠实于原文，问答任务要求忠实于知识，摘要任务要求忠实于原文内容。任务越复杂，幻觉的表现形式越多样。

## 第四章：幻觉检测——如何发现"胡说"

### 4.1 基于事实核查的检测

用另一个 LLM 作为"事实核查员"，判断陈述是否与参考资料一致。

```python
FACT_CHECK_PROMPT = """
你是一个严格的事实核查员。

需要核查的陈述：
{claim}

参考资料：
{reference}

请判断该陈述是否与参考资料一致：
- SUPPORTED：陈述被资料支持
- CONTRADICTED：陈述与资料矛盾
- NOT_ENOUGH_INFO：资料中信息不足以判断

输出 JSON：{{"verdict": "...", "reason": "..."}}
"""

def check_hallucination(claim: str, reference: str, llm) -> dict:
    prompt = FACT_CHECK_PROMPT.format(claim=claim, reference=reference)
    result = llm.invoke(prompt)
    import json
    return json.loads(result.content)
```

**为什么这样写**：将检测任务转化为**自然语言推理（NLI）**问题，利用 LLM 的理解能力进行判断。

### 4.2 SelfCheckGPT——一致性检测

核心思想：对同一问题多次采样，如果多个回答**互相矛盾**，说明模型对该问题不确定、更可能在编造；如果**高度一致**，只能说明模型"很笃定"。

> ⚠️ **关键澄清：一致 ≠ 正确**。SelfCheckGPT 衡量的是**内部一致性/自信程度**，而**不是事实正确性**。一个模型完全可能"多次都一致地给出同一个错误答案"（例如它把某个错误知识记得很牢），这时一致性很高、但答案依然是错的。因此：
> - 一致性低 → **较强的"可能有幻觉"信号**（值得进一步核查）；
> - 一致性高 → **只能说明模型自信，不能证明答案属实**，仍需外部证据（RAG/检索/权威来源）才能确认事实。
>
> 所以下面函数返回的分数**更准确的名字是"不一致度 / 潜在幻觉风险信号"，而不是严格意义上的"幻觉概率"**——它不是一个校准过的概率值。

```python
import openai

def selfcheck_inconsistency(question: str, n_samples: int = 5) -> float:
    """
    返回【不一致度】分数：0=多次回答高度一致，1=高度不一致。

    注意：这【不是】校准过的"幻觉概率"，也【不能】断定答案对错——
    它只反映模型对该问题的自我一致性/确定性。分数高 ⇒ 更可能在编造、值得核查；
    分数低 ⇒ 仅说明模型自信，仍需外部证据验证事实。
    """
    client = openai.OpenAI()

    # 采样多个回答（高温度增加多样性）
    samples = []
    for _ in range(n_samples):
        response = client.chat.completions.create(
            model="gpt-4o-mini",
            messages=[{"role": "user", "content": question}],
            temperature=1.0,
        )
        samples.append(response.choices[0].message.content)

    # 检查各样本之间的一致性
    consistency_scores = []
    for i, sample in enumerate(samples):
        for j, other in enumerate(samples):
            if i >= j:
                continue
            check = client.chat.completions.create(
                model="gpt-4o-mini",
                messages=[{
                    "role": "user",
                    "content": f"以下两段回答是否表达了相同的事实？回答 yes 或 no。\n\n回答1：{sample}\n\n回答2：{other}"
                }],
                max_tokens=5,
                temperature=0
            )
            consistent = "yes" in check.choices[0].message.content.lower()
            consistency_scores.append(1.0 if consistent else 0.0)

    avg_consistency = sum(consistency_scores) / len(consistency_scores)
    inconsistency = 1.0 - avg_consistency   # 不一致度：越高越可疑，但不等于"一定错"
    return inconsistency
```

**为什么这样写**：如果模型对同一个问题给出**互相矛盾**的答案，说明它对这个问题的知识**不确定**，很可能在"编造"，这是一个有用的**预警信号**。但反过来，"多次一致"只代表模型自信，**不能证明答案正确**——要判断真伪，仍需借助外部证据（见 4.1 的事实核查、4.3 的 RAG 忠实度、以及 §5.1 的检索增强）。

### 4.3 RAGAS——评估 RAG 忠实性

```python
from ragas import evaluate
from ragas.metrics import faithfulness

# faithfulness：答案中的每个声明是否都能从上下文中找到支持
results = evaluate(
    dataset=test_dataset,
    metrics=[faithfulness]
)
print(f"忠实度得分：{results['faithfulness']:.3f}")
# 1.0 = 完全基于上下文，0.0 = 完全编造
```

### 4.4 检测方法分类体系

| 检测类型 | 代表方法 | 原理 |
|----------|----------|------|
| **推理分类器** | FIB, ExHalder, HaluEval | 训练分类器判断答案是否包含幻觉 |
| **不确定度度量** | BARTScore, KLD, POLAR | 基于模型概率输出或信息论度量评估不确定性 |
| **自我评估** | SelfCheckGPT, LM-know, Self-Checker | 利用 LLM 自身能力评估生成内容的正确性 |
| **证据检索** | FActScore, FacTool | 检索外部证据验证生成内容的真实性 |

## 第五章：缓解方案——从治标到治本

### 5.1 RAG（检索增强生成）——常用且有力的外部知识注入手段之一

将事实性问题的答案来源从"模型参数"转移到"可控知识库"。

> ⚠️ **不要把 RAG 说成"最有效"的通用方案**：RAG 对**事实性幻觉**（尤其是有权威知识库可检索的场景）往往帮助很大，但它**不是万能药**，也无法覆盖所有幻觉：
> - **检索本身会出错**：检索不到、检索到不相关/过时/相互矛盾的资料时，RAG 反而可能引入新的错误；
> - **给了正确资料仍可能"不忠实"**：模型可能无视上下文自由发挥（即忠实性幻觉），这类问题 RAG 并不能自动消除，还需配合约束提示、忠实度评估（RAGAS）等；
> - **对"需要推理/计算/主观判断"的任务收益有限**：这类任务的错误未必来自知识缺失，检索帮不上忙。
>
> 因此更稳妥的说法是：**RAG 是缓解事实性幻觉的常用且有力手段之一**，实践中通常要与"低温度、约束提示、引用溯源、一致性检测、偏好对齐"等多种方法**组合使用**，而非依赖任何单一"最有效"方案。

```python
RAG_PROMPT = """
你只能基于以下提供的资料回答问题。
如果资料中没有明确提到相关信息，你必须说："根据现有资料无法确认"，
不得根据自身知识进行补充或推测。

资料：{context}
问题：{question}
"""
```

**为什么这样写**：RAG 在有可靠知识库时能显著减少**事实性幻觉**——模型不再单纯依赖"记忆中可能出错的知识"，而是参考"检索到的、可验证的资料"。但前提是**检索质量足够好**且**模型确实忠实于资料**，两者任一不满足，RAG 的效果都会打折。

### 5.2 温度参数调低

```python
response = client.chat.completions.create(
    model="gpt-4o",
    messages=messages,
    temperature=0,  # 贪婪解码，选择概率最高的 token
)
```

**为什么这样写**：`temperature=0` 使模型每次选择最高概率的 token，减少随机"发挥"。对于事实性任务推荐设为 0，创意写作可适当提高。

### 5.3 Chain-of-Thought + 不确定性表达

```python
COT_HALLUCINATION_PROMPT = """
请回答以下问题。
要求：
1. 一步步推理，展示思考过程
2. 若对某个细节不确定，明确说"我不确定..."
3. 不要编造具体数字、日期、人名

问题：{question}
"""
```

**为什么这样写**：CoT 让推理过程显式化，便于发现错误；要求模型表达不确定性，避免"不懂装懂"。

### 5.4 RLHF/DPO——从训练层面缓解

在偏好数据标注时，将包含幻觉的回答标记为 rejected：

```python
# DPO 偏好数据示例
{
    "prompt": "爱因斯坦何时获得诺贝尔奖？",
    "chosen": "爱因斯坦于1921年获得诺贝尔物理学奖（1922年颁发），获奖原因是光电效应的发现。",
    "rejected": "爱因斯坦于1920年因相对论获得诺贝尔奖。"  # 事实错误
}
```

**为什么这样写**：通过人类反馈或偏好学习，训练模型"诚实"——不知道就承认，不编造。

### 5.5 引用溯源（Attribution）

强制模型标注信息来源，便于用户验证：

```python
ATTRIBUTION_PROMPT = """
请回答问题，并在每句陈述后用方括号标注引用的资料编号。
若某句话无法在提供的资料中找到依据，请不要写出这句话。

资料：
[1] {source_1}
[2] {source_2}

格式示例："某某政策规定了X情况[1]，同时规定了Y情况[2]。"
"""
```

### 5.6 五大缓解策略体系

| 策略类别 | 代表方法 | 作用层面 |
|----------|----------|----------|
| **参数自适应** | PURR, HISTALIGN, EasyEdit | 修改模型参数中的错误知识 |
| **事后归因和编辑** | CoT, Self-Refine, Verify-and-Edit | 生成后验证和修正 |
| **利用外部知识** | RAG, RETRO, IRCoT, KnowledGPT | 注入可控外部知识 |
| **评估反馈** | BRIO, CRITIC, Chain-of-Hindsight | 自动评估并反馈修正 |
| **多智能体协作/辩论** | Multiagent-Debate, MAD, SPP | 多个模型互相质疑、辩论并交叉核验，以达成更可靠的共识 |

## 第六章：代码实战——RAG 幻觉检测流水线

```python
"""
完整的 RAG 幻觉检测流水线
"""

from typing import TypedDict

class HallucinationReport(TypedDict):
    answer: str
    faithfulness_score: float  # 0-1，越高越忠实
    supported_claims: list[str]
    unsupported_claims: list[str]
    recommendation: str

def detect_hallucination_in_rag(
    question: str,
    answer: str,
    contexts: list[str],
    llm
) -> HallucinationReport:
    """
    检测 RAG 答案中的幻觉
    将答案分解为原子声明，逐一验证是否有上下文支持
    """

    # Step 1：提取原子声明
    decompose_prompt = f"""
将以下回答分解为独立的原子事实陈述列表（每行一个，不加编号）：

回答：{answer}

原子陈述："""

    claims_text = llm.invoke(decompose_prompt).content
    claims = [c.strip() for c in claims_text.strip().split('\n') if c.strip()]

    # Step 2：逐一验证
    context_text = '\n'.join(f"[文档{i+1}] {ctx}" for i, ctx in enumerate(contexts))

    supported = []
    unsupported = []

    for claim in claims:
        verify_prompt = f"""
参考资料：
{context_text}

请判断以下陈述是否可以从参考资料中找到支持（只回答 yes 或 no）：
陈述：{claim}

回答："""

        result = llm.invoke(verify_prompt).content.lower().strip()
        if 'yes' in result:
            supported.append(claim)
        else:
            unsupported.append(claim)

    # Step 3：计算忠实度分数
    total = len(claims) if claims else 1
    faithfulness = len(supported) / total

    recommendation = (
        "✅ 答案可信度高" if faithfulness >= 0.9
        else "⚠️ 答案存在部分未经验证的内容，建议人工复核"
        if faithfulness >= 0.6
        else "❌ 答案存在严重幻觉风险，请勿直接使用"
    )

    return HallucinationReport(
        answer=answer,
        faithfulness_score=round(faithfulness, 3),
        supported_claims=supported,
        unsupported_claims=unsupported,
        recommendation=recommendation
    )


# 使用示例
if __name__ == "__main__":
    from langchain_openai import ChatOpenAI

    llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)

    report = detect_hallucination_in_rag(
        question="公司的年假政策是什么？",
        answer="根据公司规定，员工每年享有15天年假，工龄超过5年可额外获得5天，且年假可以跨年使用。",
        contexts=["员工手册第3章：所有正式员工每年享有15天带薪年假。年假不可跨年累计。"],
        llm=llm
    )

    print(f"忠实度分数: {report['faithfulness_score']}")
    print(f"支持的声明: {report['supported_claims']}")
    print(f"无支持的声明: {report['unsupported_claims']}")
    print(f"结论: {report['recommendation']}")
```

**输出解读**：
- "15天年假" → ✅ 支持
- "工龄超过5年可额外获得5天" → ❌ 无支持（上下文未提及）
- "年假可以跨年使用" → ❌ 无支持（上下文明确说"不可跨年"）

| 坑点 | 正确做法 |

## 本章小结与面试高频考点

| 知识点 | 核心要点 |
|--------|----------|
| **幻觉定义** | 生成看似合理但实际错误/无关/矛盾的内容 |
| **事实性幻觉** | 知识错误，如日期、数字、人名错误 |
| **忠实性幻觉** | 无视上下文，自由发挥 |
| **根本原因** | 训练目标优化流畅性而非准确性；知识存储有局限；采样滚雪球；迎合用户 |
| **检测方法** | 事实核查、SelfCheckGPT（一致性/自信度，非事实对错）、RAGAS（忠实度）、不确定度度量 |
| **缓解方案** | RAG（对事实性幻觉常用且有力，但非万能）、temperature=0、CoT+不确定性、RLHF/DPO、引用溯源 |
| **五大策略体系** | 参数自适应、事后归因编辑、外部知识、评估反馈、多智能体辩论 |

**养成的好习惯**：
1. **永远不要完全信任** LLM 的输出，关键信息必须验证
2. 事实性任务**temperature 设为 0**，减少随机发挥
3. RAG 场景必须**严格约束**模型只能基于资料回答
4. 生产环境部署**幻觉检测流水线**，自动评估忠实度
5. 要求模型**标注信息来源**，便于追溯和验证
