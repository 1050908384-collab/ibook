### 1.2 运行时 Agent 口径

正式方案只使用以下四个运行时 Agent：

| 运行时名称 | 代码职责与主证据 |
|---|---|
| 学情诊断与阶段规划 Agent | `backend/agents/agent_01_diagnostic.py`；`Harness` 在 `harness.py` 中以 `agent1` 初始化、诊断和规划阶段。 |
| 个性化学习资源生成 Agent | `backend/agents/agent_03_content_gen.py`；生成学习包、阶段答疑、修订学习内容。 |
| 专业知识与教学质量审核 Agent | `backend/agents/agent_04_tech_review.py`；代码中统一承担专业事实、规则、适配与教学质量审核。 |
| 学情评估与动态决策 Agent | `backend/agents/agent_06_stage_decision.py`；依据测评和状态生成阶段策略与总结。 |

`Agent2` 是学情诊断与阶段规划 Agent 内的阶段规划能力，`Agent5` 的历史“质量评审”职责已并入专业知识与教学质量审核 Agent。二者不得以独立运行时 Agent 出现在正式方案中。Orchestrator 是编排基础设施，不是第五个业务 Agent。

### 3.2 数据库副本风险

## 4. 测试口径

### 4.1 正式模块级测试

- 正式测试目录：根目录 `tests/`，Python `unittest`。
- 测试范围：编排闭环、检索与生成、审核修订、图谱路径、数据库状态、测评与判分、并发和云端/本地回退。
- 现有正式测试报告记录：`141` 个测试全部通过；来源为 `测试数据与评测材料/07_测试报告/正式测试报告.md` 第 1.1 节。
- 本轮重新执行 `python -m unittest discover -s tests -p "test*.py"` 已开始并产生多项通过日志，但在当前执行窗口内未获得测试进程的最终 `Ran ... / OK` 汇总；因此“本轮复测全部通过”当前未验证，方案只能引用已归档正式报告并标明报告版本。

### 4.2 系统级主评测

- 执行工具：`scripts/run_real_evaluation.py`；指标汇总：`scripts/calculate_real_metrics.py`；回退专项：`scripts/run_fallback_tests.py`。
- 不计为正式结果：`scripts/run_ablation_tests.py`（历史消融）；以及名称含 `debug_`、`diagnose_`、`patch_` 等的开发辅助脚本。
- 已归档主评测结果：50/50 完成；画像适配 247/250 = 98.80%；事实错误 0/150 = 0.00%；策略真实规则一致 55/56 = 98.21%。证据：`测试数据与评测材料/06_指标统计/metrics_summary.json`、审核 CSV 和正式测试报告。

### 4.3 前端测试边界

前端存在 5 个 Node 内置测试文件，`frontend/package.json` 中的 `test:agent-flow` 会编译工具模块后运行 `node --test tests/*.test.mjs`。它们核验 Agent 状态、知识网络布局、阶段结果操作等前端逻辑，**不是浏览器端到端自动化测试**。因此方案应写“前端页面和交互以人工验收为主，另有部分工具逻辑自动测试；浏览器自动化测试当前未验证/待建设”，不能写成“前端没有任何自动测试”。
