### 3.1 五层技术架构

系统按照数据与模型层、Skill 与 Tool 能力层、多 Agent 编排层、业务服务层和用户交互层组织。数据与模型层保存结构化会话与知识数据，并提供向量检索和知识图谱路径依据；Skill 与 Tool 层将目录查询、语义召回、代码处理、知识核验、题目抽取和策略选择等原子能力按职责封装；多 Agent 编排层负责调用顺序、状态传递、审核循环和回退；业务服务层以 FastAPI 对外提供会话、诊断、阶段、答疑、测评和可视化接口；用户交互层以 React 页面呈现学习目标创建、学习包、测试、结果和学习进度。

该分层的关键不在于堆叠技术名词，而在于约束依赖方向：前端不直接操作模型或数据库；业务接口不承担复杂编排；Agent 不直接决定跨会话持久化；状态管理和数据存取由统一组件负责。这样可以使一个阶段的输入、生成结果、审核记录和测评结论在不同页面与接口中保持一致。

### 3.2 核心组件说明

后端通过 FastAPI 注册传统兼容接口和 `/api/v1` 接口，覆盖会话创建与查询、诊断消息、画像确认、当前阶段启动、学习包读取、答疑、测评尝试、答题提交、阶段完成及下一阶段规划。`Harness` 是 Orchestrator 的核心实现，初始化四个 Agent，并把执行结果写入状态管理和数据库。SQLite 是运行时结构化真相源；Chroma 路径用于语义检索；NetworkX 图数据用于表达知识点前置关系；云端 DeepSeek 与本地 Ollama 构成可配置调用链；确定性逻辑承担规则、状态与不可用时的流程保障。

## 三、系统总体架构

### 3.1 五层技术架构

系统采用分层架构设计，从下到上依次为数据与模型层、Skill与Tool能力层、多Agent编排层、业务服务层和用户交互层。各层职责明确、松耦合协作，既保证了系统的可维护性，也为领域迁移预留了空间。

```text
┌─────────────────────────────────────────────────────────────┐
│ 用户交互层                                                  │
│ 学习画像 ｜ 知识网络 ｜ 学习包 ｜ 实时答疑 ｜ 阶段测试 ｜ 报告   │
├─────────────────────────────────────────────────────────────┤
│ 业务服务层                                                  │
│ React前端 ｜ FastAPI ｜ 会话服务 ｜ 阶段服务 ｜ 问答服务 ｜ 可视化 │
├─────────────────────────────────────────────────────────────┤
│ 多Agent编排层                                               │
│ Orchestrator ｜ 状态管理 ｜ 调用调度 ｜ 并发控制 ｜ 审核轮次 ｜ 回退 │
├─────────────────────────────────────────────────────────────┤
│ Skill与Tool能力层                                           │
│ 语义召回 ｜ 图谱查询 ｜ 知识检索 ｜ 代码解析 ｜ 代码执行 ｜ 知识核验 │
│ 难度分析 ｜ 认知负荷 ｜ 风格匹配 ｜ 正确率计算 ｜ 画像更新     │
├─────────────────────────────────────────────────────────────┤
│ 数据与模型层                                                │
│ SQLite ｜ ChromaDB ｜ NetworkX知识图谱 ｜ DeepSeek ｜ Ollama  │
└─────────────────────────────────────────────────────────────┘
```

五层架构的设计遵循"能力下沉、业务上浮"的原则：越底层的能力越通用、越稳定，越上层的逻辑越贴近用户场景、越灵活可调。数据与模型层提供最基础的存储和计算能力；Skill与Tool能力层封装了可复用的原子能力；多Agent编排层负责Agent之间的协同和流程控制；业务服务层面向具体业务场景提供API；用户交互层直接面向学习者。

### 3.2 核心组件说明

#### 用户交互层

前端以学习工作台为主要形态，覆盖从入门画像到结业报告的完整学习周期。学习者可以查看学情诊断结果、阅读个性化学习包、在学习过程中实时提问、完成阶段测试，并通过知识网络可视化了解自己在整个知识体系中的位置。交互层强调"过程可见"——Agent的运行状态、审核的进度、学习的推进都以可视化方式呈现，避免学习者面对黑盒式的等待。

#### 业务服务层

后端采用FastAPI提供会话、画像、阶段、学习包、答疑、测试和可视化等接口。业务服务层不将复杂逻辑散落在前端或直接调用模型，而是统一通过Orchestrator调度Agent并持久化结果，确保业务逻辑的集中管理和数据一致性。

#### 多Agent编排层

Orchestrator是系统的调度和状态中枢，负责建立和恢复学习会话、依次调用四个运行时Agent、维护当前阶段和下一阶段状态、管理内容块级并行生成和审核、控制审核最大轮次、处理模型回退和人工复核标记、以及将中间结果写入数据库。Orchestrator不作为第五个业务Agent，而是保证多Agent协同有序运转的基础设施。

#### Skill与Tool能力层

工具层按照Agent职责进行组织，不将所有工具暴露给所有Agent。诊断规划Agent使用知识目录、语义召回和图谱查询工具；资源生成Agent使用向量检索、内容生成、代码生成、题目抽取和格式转换工具；审核Agent使用代码解析、代码执行、知识核验、规则检查、难度分析、认知负荷和风格匹配工具；评估决策Agent使用正确率计算、画像更新、策略选择和阶段总结工具。

#### 数据与模型层

SQLite保存结构化业务状态和审核轨迹，是运行时的权威真相源；ChromaDB保存知识内容向量索引，支撑语义检索；NetworkX知识图谱保存知识点先修和关联关系，支撑动态路径规划；DeepSeek提供云端主生成模型服务；Ollama提供本地模型和云端异常时的回退能力；确定性逻辑在模型不可用时提供流程级兜底，保障状态一致性。
