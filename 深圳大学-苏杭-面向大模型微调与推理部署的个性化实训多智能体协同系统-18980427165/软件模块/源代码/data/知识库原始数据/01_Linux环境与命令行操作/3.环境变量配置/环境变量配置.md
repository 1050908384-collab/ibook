## 一、环境变量是什么？（①）

### 1.1 通俗理解（①）

环境变量是操作系统或应用程序运行时使用的**动态键值对**，用于传递配置信息。你可以把它理解为操作系统的"备忘录"——系统启动时加载这些备忘录，所有程序都能读到里面的内容，并据此调整自己的行为。（①）

**常见例子**：（①+④）

| 变量名 | 作用 |
|---|---|
| `PATH` | 告诉系统去哪里找可执行程序（比如你输入 `python3`，系统就是靠 PATH 找到它的位置） |
| `HOME` | 当前用户的家目录路径（如 `/home/zhangsan`） |
| `USER` | 当前登录的用户名 |
| `SHELL` | 当前使用的 Shell 程序路径（如 `/bin/bash`） |
| `LANG` | 系统语言和字符编码（如 `en_US.UTF-8`） |
| `PWD` | 当前工作目录路径（随 `cd` 命令自动更新） |
| `EDITOR` | 默认文本编辑器（影响 `git commit` 等操作） |

### 1.2 为什么需要环境变量？（①）

1. **控制程序行为**：例如通过 `JAVA_HOME` 指定 JDK 路径，让依赖 Java 的程序知道去哪找它。
2. **简化配置**：避免在每次运行程序时都手动输入长长的路径。
3. **跨进程通信**：子进程会自动继承父进程的环境变量，实现配置的无缝传递。

## 二、环境变量的分类：临时 vs 永久（①）

环境变量按生命周期分为两类，理解这个区别是后续操作的基础。（①）

### 2.1 临时变量：当前终端会话有效（①）

关闭终端窗口或退出 SSH 连接后，临时变量就消失了。适合快速测试。（①）

```bash
# 设置一个临时变量
export MY_VAR="hello_linux"

# 查看它的值
echo $MY_VAR
# 输出：hello_linux

# 删除这个变量
unset MY_VAR

# 再查看
echo $MY_VAR
# 输出：（空，因为已经删除了）
```

> **`export` 是什么？** 如果不加 `export`，变量只对当前 Shell 有效，子进程（比如你启动的另一个程序）读不到。加了 `export`，子进程也能继承这个变量。通常设置环境变量时都加 `export`。（①）

### 2.2 永久变量：写入配置文件，持久生效（①）

想让变量每次打开终端都存在，就需要把它写入**配置文件**。（①）

| 级别 | 配置文件 | 影响范围 | 是否需要 sudo |
|---|---|---|---|
| **用户级（推荐）** | `~/.bashrc` | 仅当前用户 | 否 |
| **用户级** | `~/.bash_profile` 或 `~/.profile` | 仅当前用户（登录时生效） | 否 |
| **系统级** | `/etc/profile` 等 | 所有用户 | 是 |

> **该选哪个？** 日常开发中，建议优先使用 `~/.bashrc`（用户级），只影响你自己，改错了也不会影响系统。系统级配置（如 `/etc/profile`）需要 `sudo`，且会影响所有用户，日常开发不建议修改。（①+④）

## 三、永久环境变量的配置方法（①）

### 3.1 用户级配置：修改 ~/.bashrc（推荐）（①）

`~/.bashrc` 是 Bash Shell 的配置文件，**每次打开新的交互式终端时自动加载**。这是日常开发中最常用的配置位置。（①）

**操作步骤**：（①）

```bash
# 1. 用 nano 打开配置文件（上节课学过的命令）
nano ~/.bashrc

# 2. 滚动到文件末尾，添加一行：
export MY_VAR="hello_permanent"

# 3. 按 Ctrl + O 保存，Ctrl + X 退出

# 4. 让修改立即生效（不重启终端）
source ~/.bashrc

# 5. 验证
echo $MY_VAR
# 输出：hello_permanent
```

> **`source` 是什么？** 相当于"重新执行一遍这个配置文件"，让刚才的修改在当前终端立刻生效，不用关掉重开。（①）

> **`~/.bashrc` 的加载限制**：`~/.bashrc` 通常在打开新的**交互式终端**时加载，但并非所有 SSH 会话、IDE 集成终端或服务进程都会自动加载它。例如，某些 IDE 的内置终端可能只加载 `~/.profile`，非交互式 Shell（如自动化脚本）则通常不会加载 `~/.bashrc`。如果你发现配置未生效，尝试手动 `source ~/.bashrc`，或检查所用终端的加载行为。（④）

### 3.2 用户级配置：~/.bash_profile 或 ~/.profile（①）

这两个文件在**登录 Shell** 时生效（比如 SSH 远程登录、系统开机登录）。如果同时存在 `~/.bash_profile` 和 `~/.profile`，系统优先读取 `~/.bash_profile`。（①）

日常开发中 `~/.bashrc` 更常用，因为每开一个终端它都会加载。只有在需要"登录时才生效"的特殊场景，才考虑这两个文件。（①）

## 四、环境变量的优先级（①）

当同一个变量在多处定义时，遵循以下优先级（从高到低）：（①）

1. **临时变量**（当前终端里 `export` 的）
2. **用户级配置**（`~/.bashrc` 等）
3. **系统级配置**（`/etc/profile` 等）

**也就是说：临时设置会覆盖配置文件里的设置。** 如果你在 `~/.bashrc` 里把 PATH 设成了 A，然后在终端里 `export PATH=B`，那么当前终端的 PATH 就是 B。（①）

## 五、核心环境变量详解（①+②+③）

### 5.1 PATH：命令的"搜索路径"（①+②）

`PATH` 是最重要的环境变量，没有之一。它定义了系统**查找可执行文件**的目录列表。（①+②）

#### 5.1.1 查看 PATH（①+②）

```bash
echo $PATH
```

输出类似这样（多个路径用冒号 `:` 分隔）：（②）

```bash
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
```

当你在终端输入 `python3` 时，系统会**从左到右**依次在这些目录里找名为 `python3` 的可执行文件，找到了就执行，找不到就提示 `command not found`。（②）

#### 5.1.2 查看命令具体位置（②）

```bash
which python3
# 输出：/usr/bin/python3

which conda
# 输出：/home/zhangsan/miniconda3/bin/conda
```

`which` 命令能告诉你某个命令到底是从 PATH 的哪个目录里找到的。（②）

#### 5.1.3 修改 PATH（①+②）

**追加路径**（添加到末尾，优先级较低）：（①）

```bash
export PATH=$PATH:/new/path
```

**前置路径**（添加到开头，优先级更高，系统会先搜这里）：（①）

```bash
export PATH=/new/path:$PATH
```

> **安全提示**：不要把 `.`（当前目录）加入 PATH。如果你在某个目录里下载了一个名为 `ls` 的恶意脚本，而当前目录又在 PATH 里，那么你执行 `ls` 时可能运行的是恶意脚本而非真正的系统命令。（①）
>
> **避免重复添加**：多次 `source ~/.bashrc` 或在 `~/.bashrc` 中重复写入同一行，可能导致 PATH 里出现重复路径。建议定期检查 `~/.bashrc`，确保每条 PATH 修改只出现一次。（④）

### 5.2 LD_LIBRARY_PATH：运行时动态库路径（②+③）

`LD_LIBRARY_PATH` 用于指定程序**运行时**查找动态链接库（`.so` 文件）的额外路径。后续安装 CUDA、PyTorch 时经常需要配置它。（②+③）

```bash
# 查看当前值
echo $LD_LIBRARY_PATH

# 临时添加 CUDA 的动态库路径
export LD_LIBRARY_PATH=$LD_LIBRARY_PATH:/usr/local/cuda/lib64
```

**典型场景**：你编译了一个程序，它依赖某个 `.so` 文件，但这个 `.so` 不在系统的默认搜索路径（`/usr/lib`、`/lib`）里。这时把 `.so` 所在的目录加入 `LD_LIBRARY_PATH`，程序就能正常运行了。（②）

### 5.3 LIBRARY_PATH：编译时库文件路径（②）

`LIBRARY_PATH` 用于指定编译器（如 `gcc`）在**编译阶段**查找库文件的路径，主要影响静态库（`.a` 文件）和动态库（`.so` 文件）的链接。（②）

```bash
export LIBRARY_PATH=$LIBRARY_PATH:/path/to/your/libraries
```

**三者区别总结**：（②）

| 变量名 | 作用阶段 | 查找目标 | 典型用途 |
|---|---|---|---|
| `PATH` | 执行命令时 | 可执行文件 | 让命令在任何位置都能运行 |
| `LD_LIBRARY_PATH` | 程序运行时 | 动态链接库（`.so`） | 运行依赖自定义动态库的程序 |
| `LIBRARY_PATH` | 编译链接时 | 静态库/动态库 | 编译时链接第三方库 |

> **对大模型开发者的建议**：PATH 和 LD_LIBRARY_PATH 是你后续最常打交道的两个变量。安装 Miniconda、CUDA、PyTorch 时，都需要正确配置它们。（②+③）

## 六、实战：配置 CUDA 环境变量（③）

CUDA 是 NVIDIA 的并行计算平台，后续学习 PyTorch 和模型部署时必备。下面演示如何将 CUDA 路径加入环境变量。（③）

### 6.1 检查 CUDA 是否已在环境变量中（③）

```bash
echo $PATH | grep cuda
echo $LD_LIBRARY_PATH | grep cuda
```

如果有输出（如 `/usr/local/cuda/bin`），说明已配置；如果没有输出，继续下一步。（③）

### 6.2 编辑 ~/.bashrc 添加 CUDA 路径（③）

```bash
nano ~/.bashrc
```

在文件末尾添加以下两行：（③）

```bash
# CUDA 环境变量配置
export PATH=/usr/local/cuda/bin:$PATH
export LD_LIBRARY_PATH=/usr/local/cuda/lib64:$LD_LIBRARY_PATH
```

> **注意**：`/usr/local/cuda` 是 CUDA 的默认安装路径。如果你的 CUDA 装在其他位置，请替换为实际路径。（③）

### 6.3 使配置生效并验证（③）

```bash
# 重新加载配置文件
source ~/.bashrc

# 验证 PATH
echo $PATH | grep cuda

# 验证 nvcc（CUDA 编译器）是否可用
nvcc --version
```

如果 `nvcc --version` 能输出版本号，说明 CUDA 环境变量配置成功。（③）

## 八、常见问题与解决（①+④）

### 8.1 变量未生效（①）

**可能原因**：（①）
- 修改了配置文件但没有 `source` 或重启终端
- 配置文件有语法错误（比如少写了 `export`）
- 变量在其他地方被覆盖了
- 所用终端或 IDE 没有加载 `~/.bashrc`（见 3.1 节说明）

**排查步骤**：（①+④）

```bash
# 1. 确认配置文件语法正确
cat ~/.bashrc | grep "你的变量名"

# 2. 重新加载
source ~/.bashrc

# 3. 检查是否有重复定义
grep -r "PATH=" ~/.bashrc
```

### 8.2 路径冲突：多个目录有同名命令（①+②）

**场景**：你同时装了系统自带的 Python 和 Miniconda 的 Python，输入 `python` 时到底执行的是哪个？（①+②）

**排查**：（①）

```bash
which python
# 输出第一个匹配的路径

type -a python
# 输出所有匹配的路径（按 PATH 搜索顺序排列）
```

**解决**：调整 PATH 中目录的先后顺序。排在前面的目录优先级更高。（①）

### 8.3 特殊字符处理（①+④）

**路径中包含空格**：（①）

```bash
export MY_PATH="/path/with spaces"    # 必须用双引号包裹
```

**值中包含 `$` 符号**：（④）

```bash
export PRICE='$100'    # 用单引号防止变量扩展
```

## 九、进阶技巧与注意事项（①+④）

### 9.1 脚本中临时修改变量（①）

```bash
#!/bin/bash
export TEMP_VAR=123
# 仅在脚本执行期间生效，脚本结束后变量消失
```

### 9.2 使用 env 命令指定单次运行的变量（①）

```bash
env MY_VAR=hello python3 my_script.py
# MY_VAR 仅在这次 python3 运行时有效
```

### 9.3 使用 .env 文件分组管理变量（④）

当项目需要多个环境变量时，可以创建一个 `.env` 文件：（④）

```bash
# 创建 ~/.env 文件
nano ~/.env
```

内容示例：（④）

```bash
export PROJECT_HOME="$HOME/llm-learning"
export EDITOR="nano"
export TZ="Asia/Shanghai"
```

加载方法：（④）

```bash
set -o allexport
source ~/.env
set +o allexport
```

> **⚠️ 安全警告**：`source .env` 会**执行** `.env` 文件中的每一行 Shell 代码。如果 `.env` 来自不可信的来源（如下载的第三方项目），直接 `source` 可能导致恶意代码执行。加载前务必检查文件内容。（④）
>
> **⚠️ Git 安全警告**：`.env` 文件通常包含密钥、API Token、数据库密码等敏感信息。**绝对不要将 `.env` 文件提交到 Git 仓库**。应在 `.gitignore` 中添加一行 `.env`，防止意外提交。（④）

## 十、综合实战演练（①+②+③）

请在你的 Ubuntu 终端中完成以下操作，巩固本节所学：

### 场景 1：创建并验证自定义变量

```bash
# 1. 设置一个临时变量
export MY_NAME="zhangsan"

# 2. 验证
echo $MY_NAME

# 3. 写入 ~/.bashrc 使其永久生效
echo 'export MY_NAME="zhangsan"' >> ~/.bashrc

# 4. 重新加载并验证
source ~/.bashrc
echo $MY_NAME
```

### 场景 2：为自定义脚本目录配置 PATH

假设你在 `~/scripts` 文件夹里放了一些自己写的工具脚本，希望能在任何目录下直接运行它们。

```bash
# 1. 创建脚本目录
mkdir -p ~/scripts

# 2. 创建一个测试脚本
echo '#!/bin/bash' > ~/scripts/hello_tool.sh
echo 'echo "Hello from my tool!"' >> ~/scripts/hello_tool.sh
chmod +x ~/scripts/hello_tool.sh

# 3. 将 ~/scripts 加入 PATH（追加到 ~/.bashrc）
echo 'export PATH=$PATH:$HOME/scripts' >> ~/.bashrc

# 4. 生效并测试
source ~/.bashrc
hello_tool.sh
# 预期输出：Hello from my tool!
```

### 场景 3：模拟 CUDA 环境变量配置

即使你现在还没装 CUDA，也可以先练习配置方法：

```bash
# 1. 编辑 ~/.bashrc
nano ~/.bashrc

# 2. 在末尾添加（假设 CUDA 装在 /usr/local/cuda）
export PATH=/usr/local/cuda/bin:$PATH
export LD_LIBRARY_PATH=/usr/local/cuda/lib64:$LD_LIBRARY_PATH

# 3. 保存并生效
source ~/.bashrc

# 4. 验证 PATH 中是否包含 cuda
echo $PATH | grep cuda
```

## 附录：进阶参考（选读）

以下内容属于进阶知识，初学者可先跳过。在需要配置服务器全局环境、排查复杂问题或管理多项目时，再回来查阅。

### A. 系统级配置文件（①）

系统级配置会影响**所有用户**，修改需要 `sudo` 权限。日常开发不建议使用，但在配置公共服务器时需要了解。

#### A.1 /etc/environment（①）

这个文件的特点是**不需要 `export` 关键字**，直接写 `KEY=value` 即可。但它只支持简单的键值对，不支持 Shell 脚本语法（如 `$PATH` 引用）。（①）

```bash
# 需要 sudo 权限
sudo nano /etc/environment

# 添加：
JAVA_HOME=/usr/lib/jvm/java-11-openjdk

# 保存后，需要重启系统或重新登录才能生效
```

#### A.2 /etc/profile（①）

适用于全局 Bash 配置，需要 `export` 关键字。（①）

```bash
sudo nano /etc/profile

# 添加：
export PATH=$PATH:/usr/local/custom/bin

# 保存后，source 使当前会话生效，或重启系统
source /etc/profile
```

### B. 不同 Shell 的配置文件对照表（①）

如果你使用的不是 Bash（比如 Zsh），配置文件位置不同：（①）

| Shell 类型 | 配置文件 | 作用范围 |
|---|---|---|
| **Bash** | `~/.bashrc` | 非登录 Shell（日常终端） |
| **Bash** | `~/.bash_profile` | 登录 Shell（SSH 登录） |
| **Zsh** | `~/.zshrc` | 所有交互式 Shell |
| **Fish** | `~/.config/fish/config.fish` | 所有会话 |

> **怎么知道自己用的是什么 Shell？** 执行 `echo $SHELL`，如果输出 `/bin/bash`，就是 Bash。（④）

### C. 清理 PATH 中的重复项（④）

多次修改 PATH 后，可能会出现重复路径。可以这样清理：（④）

```bash
export PATH=$(echo $PATH | awk -v RS=: '!a[$0]++' | paste -sd: -)
```

### D. 根据环境加载不同配置（④）

```bash
# 在 ~/.bashrc 中添加
if [ "$ENVIRONMENT" = "production" ]; then
    source ~/.env.prod
else
    source ~/.env.dev
fi
```

### E. 脚本调试模式（④）

```bash
# 以详细模式运行脚本，会打印每一行执行前的变量值
bash -x your_script.sh

# 或者在当前 Shell 中开启追踪
set -o xtrace
source ~/.bashrc
set +o xtrace
```
