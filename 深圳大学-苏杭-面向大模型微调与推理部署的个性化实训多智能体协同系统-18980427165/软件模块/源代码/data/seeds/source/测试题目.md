### 知识点1.2：常用Shell命令（cd/ls/mkdir/cp/mv）

**题1 ⭐基础（选择）**
以下哪个命令用于**切换当前工作目录**？
A. `ls`  B. `cd`  C. `mkdir`  D. `pwd`

✅ **答案：B**
> `cd`（change directory）用于切换目录；`pwd` 显示当前目录；`ls` 列出文件；`mkdir` 创建目录。

**题2 ⭐基础（填空）**
命令 `ls -la` 中，`-l` 的作用是________，`-a` 的作用是________。

✅ **答案：** `-l` 以长格式（详细信息：权限、所有者、大小、修改时间）列出文件；`-a` 显示所有文件（包括以 `.` 开头的隐藏文件）。

**题3 ⭐基础（实操）**
请依次执行以下命令并描述每一步的结果：
```bash
mkdir -p /tmp/test_dir/sub_dir
cd /tmp/test_dir
touch hello.txt
cp hello.txt sub_dir/
mv hello.txt renamed.txt
ls -R
```
✅ **答案：**
- 递归创建嵌套目录 `/tmp/test_dir/sub_dir`
- 进入 `/tmp/test_dir`
- 创建空文件 `hello.txt`
- 将 `hello.txt` 复制到 `sub_dir/` 下
- 将 `hello.txt` 重命名为 `renamed.txt`
- `ls -R` 输出：当前目录有 `renamed.txt` 和 `sub_dir/`；`sub_dir/` 下有 `hello.txt`

**题4 ⭐⭐进阶（选择）**
`cp -r source_dir/ dest_dir/` 中 `-r` 参数的含义是？
A. 只复制文件不复制目录  B. 递归复制整个目录树  C. 覆盖时不提示  D. 保留文件属性

✅ **答案：B**
> `-r`（recursive）递归复制目录及其所有子目录和文件。

**题5 ⭐⭐进阶（判断）**
`mv` 命令只能用于移动文件，不能用于重命名文件。（ ）

✅ **答案：错误。** `mv` 既可以移动文件/目录到另一个路径，也可以在同一目录下重命名文件（本质是移动）。

**题6 ⭐⭐⭐高级（实操）**
请写出一条命令，将 `/tmp/test_dir` 下所有 `.txt` 文件复制到 `/tmp/backup/` 目录中（如目录不存在则先创建）。

✅ **答案：**
```bash
mkdir -p /tmp/backup && cp /tmp/test_dir/*.txt /tmp/backup/
```

### 知识点1.3：环境变量配置

**题1 ⭐基础（选择）**
在Linux中，查看**所有**环境变量的命令是？
A. `echo $PATH`  B. `env`  C. `set`  D. `export`

✅ **答案：B**（`env` 列出所有环境变量；`echo $PATH` 只查看某一个；`set` 包含shell变量；`export` 用于设置/导出变量）

**题2 ⭐基础（填空）**
临时设置环境变量 `MY_VAR=hello`，命令为________；若要使其在当前shell及子进程中生效，需使用________命令。

✅ **答案：** `MY_VAR=hello`；`export MY_VAR=hello`

**题3 ⭐⭐进阶（实操）**
请写出将 `/usr/local/cuda/bin` 永久添加到 `PATH` 环境变量的完整步骤（以bash为例）。

✅ **答案：**
```bash
echo 'export PATH=/usr/local/cuda/bin:$PATH' >> ~/.bashrc
source ~/.bashrc
echo $PATH  # 验证
```

**题4 ⭐⭐进阶（选择）**
以下哪个文件是bash shell用户登录时**最先**读取的全局配置文件？
A. `~/.bashrc`  B. `/etc/profile`  C. `~/.bash_profile`  D. `/etc/bash.bashrc`

✅ **答案：B**
> `/etc/profile` 是系统级全局配置，登录时最先执行；`~/.bash_profile` 是用户级登录配置；`~/.bashrc` 是非登录交互式shell读取的。

**题5 ⭐⭐⭐高级（判断+解释）**
在 `~/.bashrc` 中写入 `export LD_LIBRARY_PATH=/usr/local/lib` 后，新开一个终端窗口，该变量是否自动生效？为什么？

✅ **答案：** 是。因为每次打开新的交互式非登录shell（如新终端窗口），bash会自动读取 `~/.bashrc`，所以变量会生效。但如果是通过SSH登录（登录shell），则需确认 `~/.bash_profile` 中是否 `source ~/.bashrc`。

**题5 ⭐⭐⭐高级（代码）**
请写一个**带参数的装饰器** `retry(times=3)`，使被装饰的函数在抛出异常时自动重试指定次数。

✅ **答案：**
```python
import functools

def retry(times=3):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            for attempt in range(times):
                try:
                    return func(*args, **kwargs)
                except Exception as e:
                    print(f"第{attempt+1}次失败: {e}")
            raise Exception(f"重试{times}次后仍失败")
        return wrapper
    return decorator

@retry(times=3)
def unstable_api():
    import random
    if random.random() < 0.7:
        raise ConnectionError("网络超时")
    return "成功"
```

写一个类 `Stack`（栈），实现 `push(item)`、`pop()`、`peek()`、`is_empty()` 方法。`pop()` 在栈空时抛出 `IndexError`。

✅ **答案：**
```python
class Stack:
    def __init__(self):
        self._items = []
    def push(self, item):
        self._items.append(item)
    def pop(self):
        if self.is_empty():
            raise IndexError("pop from empty stack")
        return self._items.pop()
    def peek(self):
        if self.is_empty():
            raise IndexError("peek from empty stack")
        return self._items[-1]
    def is_empty(self):
        return len(self._items) == 0
```

写一个装饰器 `timer`，测量并打印被装饰函数的执行时间（秒），同时不改变原函数的返回值。然后用它装饰一个计算前100万个数平方和的函数。

✅ **答案：**
```python
import time
import functools

def timer(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        elapsed = time.perf_counter() - start
        print(f"{func.__name__} 执行耗时: {elapsed:.4f}s")
        return result
    return wrapper

@timer
def sum_squares(n):
    return sum(x**2 for x in range(n))

print(sum_squares(1_000_000))
```

✅ **答案：B**

**题4 ⭐⭐进阶（计算）**
假设 `Q = [1, 0]`, `K = [0, 1]`, `d_k = 2`，计算注意力分数（未softmax）。

✅ **答案：**
```

```

**题5 ⭐⭐⭐高级（代码）**
请实现一个简单的缩放点积注意力函数：
```python
def scaled_dot_product_attention(Q, K, V, mask=None):
    # Q: (batch, heads, seq_len, d_k)
    # K: (batch, heads, seq_len, d_k)
    # V: (batch, heads, seq_len, d_v)
    pass
```

✅ **答案：**
```python
import math                       # 用于 sqrt(d_k)；若不想加，可改用 d_k ** 0.5
import torch
import torch.nn.functional as F


def scaled_dot_product_attention(Q, K, V, mask=None):
    """
    缩放点积注意力: Attention(Q, K, V) = softmax(Q K^T / sqrt(d_k)) V
    Q: (batch, heads, seq_len_q, d_k)
    K: (batch, heads, seq_len_k, d_k)
    V: (batch, heads, seq_len_k, d_v)
    mask: 可选，形状可广播到 (batch, heads, seq_len_q, seq_len_k)
          约定: 值为 1 / True 的位置【保留】, 值为 0 / False 的位置【遮蔽】
    返回: (output, attn_weights)
    """
    d_k = K.size(-1)

    # 1) 点积 + 缩放  ->  (batch, heads, seq_len_q, seq_len_k)
    scores = torch.matmul(Q, K.transpose(-2, -1)) / math.sqrt(d_k)

    # 2) 应用 mask：把要遮蔽的位置填成 -inf，softmax 后权重趋近 0
    if mask is not None:
        scores = scores.masked_fill(mask == 0, float('-inf'))

    # 3) 在 key 维度上做 softmax，得到注意力权重（每行和为 1）
    attn_weights = F.softmax(scores, dim=-1)

    # 4) 用权重对 V 加权求和  ->  (batch, heads, seq_len_q, d_v)
    output = torch.matmul(attn_weights, V)

    return output, attn_weights
```

✅ **答案：**
*   **BPE的问题：** BPE在编码时通常需要依赖空格来分隔单词。在解码时，需要额外的规则来判断何时应该在子词之间添加空格，这在处理不同语言或格式不规范的文本时容易出错。
*   **SentencePiece的解决：** SentencePiece 将空格也作为一个特殊字符（通常表示为 `_`）来对待，并将其纳入词汇表。这样，模型在解码时可以直接输出空格字符，无需额外的后处理规则，实现了更干净、更通用的解码过程。

    # 请补全代码

✅ **答案：**
```python
def get_sinusoidal_pe(max_len, d_model):
    pe = torch.zeros(max_len, d_model)
    position = torch.arange(0, max_len, dtype=torch.float).unsqueeze(1)
    div_term = torch.exp(torch.arange(0, d_model, 2).float() * (-math.log(10000.0) / d_model))
    
    pe[:, 0::2] = torch.sin(position * div_term)  # 偶数维度
    pe[:, 1::2] = torch.cos(position * div_term)  # 奇数维度
    
    return pe.unsqueeze(0)  # shape: (1, max_len, d_model)
```

**题1 ⭐基础（选择）**

 **答案：** 句子/段落（Sentences/Paragraphs）；语义（Semantic）

**题3 进阶（选择）**
在文本分块时，设置“重叠（Overlap）”的主要目的是？
A. 增加数据库的存储量
B. 防止关键信息在切分边界处被截断，保持上下文连贯性
C. 加快检索速度
D. 减少分块的数量

 **答案：B**

**题4 进阶（代码）**
请使用 Python 编写一个简单的函数，按固定字符数（如 500）和重叠（如 50）对长文本进行分块。

 **答案：**
```python
def chunk_text(text, chunk_size=500, overlap=50):
    chunks = []
    start = 0
    while start < len(text):
        end = start + chunk_size
        chunks.append(text[start:end])
        start += chunk_size - overlap
    return chunks
```

**题5 高级（简答）**
什么是“语义分块（Semantic Chunking）”？它比固定大小分块有什么优势？

 **答案：**
语义分块是指根据文本内容的语义连贯性来进行切分，而不是机械地按照字符数或标点符号。它通常使用嵌入模型计算相邻句子之间的相似度，当相似度低于某个阈值时进行切分。
**优势：** 能够保证每个 Chunk 内部的主题是高度一致的，避免了一个 Chunk 中混杂了两个不相关的话题，从而大幅提升向量检索的准确率和最终生成的质量。

> 塞入过多的上下文不仅会超出大模型的上下文窗口限制，还会引入大量无关的“噪音”，导致“迷失在中间（Lost in the middle）”现象，反而降低回答质量并增加推理延迟。

**题5 高级（架构）**
请简述如何评估一个本地知识库问答助手的性能？（至少说出两个评估维度）

 **答案：**
1.  **检索准确率（Retrieval Metrics）：** 评估检索模块是否找到了真正相关的文档块。常用指标如 Hit Rate（命中率）、MRR（平均倒数排名）。
2.  **生成质量（Generation Metrics）：** 评估大模型最终回答的质量。可以通过人工打分，或使用 LLM-as-a-Judge（如 RAGAS 框架）来评估回答的**忠实度（Faithfulness，是否基于上下文）**和**相关性（Answer Relevancy，是否回答了用户问题）**。

### 知识点12.2：项目二：微调一个特定领域的对话模型

**题1 基础（数据）**
微调特定领域对话模型，最关键的一步是什么？

 **答案：** 准备高质量、格式正确的领域特定指令微调数据集（SFT Data）。

**题2 基础（技术）**
在消费级显卡（如 RTX 3090/4090）上微调 7B 或 8B 参数的模型，通常必须使用什么技术？

 **答案：** 参数高效微调技术（如 LoRA）结合量化技术（如 4-bit QLoRA）。

**题3 进阶（评估）**
微调完成后，如何判断模型是否出现了“灾难性遗忘（Catastrophic Forgetting）”？

 **答案：** 在通用的基准测试集（如 MMLU, C-Eval）或通用对话测试集上评估微调后的模型。如果模型在特定领域表现提升，但在通用常识或基础能力上出现严重下降，说明发生了灾难性遗忘。

**题4 进阶（实操）**
在训练过程中，如果发现 Loss 曲线一直不下降，可能的原因有哪些？（列举两个）

 **答案：**
1.  学习率设置不当（过大导致震荡，过小导致收敛极慢）。
2.  数据预处理错误（如 Label 全部被 Mask 成了 -100，或者 Input 和 Label 错位）。
3.  数据质量极差或格式完全不符合模型预期。

**题5 高级（部署）**
微调完成后，如何将这个特定领域的模型部署为本地 API 供前端调用？

 **答案：**
1.  将训练好的 LoRA 权重合并（Merge）回基座模型，或者准备好基座模型与 LoRA 适配器。
2.  使用 vLLM 或 llama.cpp 等推理框架加载该模型。
3.  启动框架提供的 OpenAI 兼容 API 服务（如 `python -m vllm.entrypoints.openai.api_server`）。
4.  前端或后端代码通过 HTTP 请求（如使用 `openai` Python SDK）向本地 API 发送对话请求。

### 知识点12.3：项目三：大模型应用的性能优化与监控

**题1 基础（优化）**
在大模型推理部署中，提升并发处理能力和吞吐量最常用的技术是？

 **答案：** PagedAttention（如 vLLM 框架中的实现）或 Continuous Batching（连续批处理）。

**题2 基础（监控）**
在监控大模型推理服务时，首字延迟（TTFT, Time To First Token）指的是什么？

 **答案：** 从用户发送请求到模型生成并返回第一个 Token 所经历的时间。它主要受 Prefill（预填充）阶段和排队时间的影响。

**题3 进阶（优化）**
如果用户的提问非常长，导致显存溢出（OOM），在不更换显卡的情况下，有哪些优化手段？

 **答案：**
1.  对模型进行量化（如从 FP16 降至 INT4/INT8）。
2.  开启 FlashAttention 减少注意力计算的显存峰值。
3.  限制最大生成长度（`max_tokens`）或输入截断（`truncation`）。
4.  减小推理时的 Batch Size。

**题4 进阶（监控）**
在评估 RAG 系统的端到端延迟时，主要包含哪两个部分的耗时？

 **答案：**
1.  **检索耗时（Retrieval Latency）：** 包括 Query 向量化和向量数据库搜索的时间。
2.  **生成耗时（Generation Latency）：** 包括大模型处理长上下文（Prefill）和自回归生成文本（Decode）的时间。

**题5 高级（架构）**
在生产环境中，如何监控大模型应用是否出现了严重的“幻觉”或回答偏离了检索到的上下文？

 **答案：**
1.  **日志记录：** 完整记录每次请求的 Query、检索到的 Context 和最终生成的 Answer。
2.  **异步评估：** 引入 LLM-as-a-Judge（如 RAGAS 或 TruLens），在后台异步计算生成回答的“忠实度（Faithfulness）”分数。
3.  **告警机制：** 设定阈值，当忠实度分数低于阈值时触发告警，提示人工介入审查或优化检索策略。

✅ **答案：B**
> VLM通常由一个预训练的视觉编码器（如ViT）提取图像特征，再通过投影层（Projector）映射到LLM的词嵌入空间，最后由LLM进行理解和生成。

**题3 ⭐⭐进阶（选择）**
以下哪个模型是典型的VLM（视觉语言模型）？
A. LLaMA-2
B. GPT-4o / Qwen-VL
C. Whisper
D. Stable Diffusion

✅ **答案：B**
> LLaMA-2是纯文本LLM；Whisper是语音模型；Stable Diffusion是文生图模型；GPT-4o和Qwen-VL支持图文输入。

**题4 ⭐⭐进阶（判断）**

✅ **答案：正确。**

**题5 ⭐⭐⭐高级（简答）**

**题4 ⭐⭐进阶（选择）**
VLM推理时，图像Token的数量通常远大于文本Token，这会导致什么问题？
A. 推理速度变快
B. 显存占用急剧增加，推理延迟变高
C. 模型精度提高
D. 没有任何影响

✅ **答案：B**

**题5 ⭐⭐⭐高级（简答）**
在处理高分辨率图像时，Qwen2-VL 采用了什么机制来平衡精度和计算效率？

✅ **答案：**
Qwen2-VL 采用了 **Naive Dynamic Resolution**（原生动态分辨率）机制。它不再强制将所有图像缩放到固定尺寸（如 $224 \times 224$），而是根据图像原始长宽比和分辨率，动态计算切分后的Patch数量，同时设置最大和最小Token数量限制。这使得模型既能看清细节（高分辨率），又不会因为Token过多导致计算爆炸。

> 基准测试（Benchmark）通常只覆盖特定类型的题目，可能存在数据污染或无法反映模型在垂直领域（如医疗、法律）或复杂指令遵循上的真实表现。

**题5 ⭐⭐⭐高级（简答）**
请简述什么是“数据污染（Data Contamination）”及其对评测的影响。

✅ **答案：**
数据污染是指评测集（Test Set）中的数据意外地出现在了模型的训练数据（Training Data）中。这会导致模型“背诵”了答案，使得评测分数虚高，无法真实反映模型的泛化能力。

**题5 ⭐⭐⭐高级（代码）**
请写出使用 FastAPI 封装一个简单的大模型推理接口的代码（假设已有 `model` 和 `tokenizer`）。

✅ **答案：**
```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class RequestModel(BaseModel):
    prompt: str
    max_tokens: int = 100

@app.post("/generate")
async def generate_text(request: RequestModel):
    inputs = tokenizer(request.prompt, return_tensors="pt").to(model.device)
    outputs = model.generate(**inputs, max_new_tokens=request.max_tokens)
    text = tokenizer.decode(outputs[0], skip_special_tokens=True)
    return {"generated_text": text}
```
