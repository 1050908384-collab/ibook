## 一、为什么需要参数高效微调？（①②）
### 1.1 全参数微调的问题
传统大模型训练：

```text
输入数据

↓

整个模型参数更新

↓

保存完整模型
```

例如：

7B参数模型：

```text
70亿参数
```

训练时需要：

* 保存参数；
* 保存梯度；
* 保存优化器状态。

显存需求非常高。

普通消费级GPU难以完成。

---

### 1.2 参数高效微调（PEFT）
PEFT：

Parameter-Efficient Fine-Tuning

中文：

参数高效微调。

核心思想：

> 不修改整个大模型，只训练少量新增参数。

流程：

```text
原始大模型

        +
        
LoRA适配器参数

        ↓

只训练LoRA参数

        ↓

保存小规模Adapter
```

优势：

| 方式    | 训练参数      | 显存需求 |
| ----- | --------- | ---- |
| 全参数微调 | 全部参数      | 非常高  |
| LoRA  | 少量参数      | 较低   |
| QLoRA | 量化模型+LoRA | 更低   |

## 二、LoRA与QLoRA基础概念（①②）
### 2.1 LoRA是什么？（①）
LoRA：

Low-Rank Adaptation

低秩适配。

原模型：

```text
W
```

不更新。

新增：

```text
W + ΔW
```

其中：

```text
ΔW = B × A
```

> 说明：本课程统一采用 `ΔW = B × A` 的符号约定（与后续《理解 LoRA 的低秩分解原理》一章一致）。其中 `A`、`B` 是两个低秩小矩阵：若原权重 `W` 形状为 `d_out × d_in`、秩为 `r`，则 `A` 形状约为 `r × d_in`、`B` 形状约为 `d_out × r`，相乘后 `B × A` 得到与 `W` 同形状的 `ΔW`。不同资料可能写成 `A × B`，只是符号顺序不同、含义一致；关键是矩阵形状要能相乘并还原成 `W` 的形状。

只训练：

```text
A

B
```

两个小矩阵。

---

### 2.2 LoRA训练特点
优点：

* 参数量少；
* 训练速度快；
* 显存占用低；
* Adapter文件小。

训练完成：

保存：

```text
adapter_model

adapter_config
```

通常只有几十MB到几百MB。

## 三、QLoRA是什么？（①③）
### 3.1 LoRA的问题
虽然LoRA减少训练参数。

但是：

基础模型仍然需要加载。

例如：

7B模型：

FP16：

约：

```text
14GB显存
```

---

### 3.2 QLoRA解决方案
QLoRA：

Quantized LoRA

量化版LoRA。

核心：

```text
FP16模型

↓

4bit量化

↓

减少显存

↓

加载LoRA训练
```

结构：

```text
4bit基础模型

+

LoRA参数

↓

训练
```

---

### 3.3 QLoRA依赖bitsandbytes
QLoRA需要：

```text
transformers

+

peft

+

bitsandbytes

+

支持的量化后端（本教程以 NVIDIA CUDA GPU 为准）
```

其中：

`bitsandbytes`

负责：

* 低精度量化；
* 4bit加载；
* 8bit加载。

> 说明：本教程的实训与验证**统一以 NVIDIA CUDA GPU** 为准（这是**项目支持范围**，也是当前最常见、资料最全的路径）。但"QLoRA/4-bit 量化只能用 NVIDIA CUDA"并不是**技术必然**——bitsandbytes 近年已在扩展对其它后端（如 CPU 以及 AMD ROCm、Intel 等）的支持，具体以你所用 `bitsandbytes` 版本的官方说明为准。如果你的硬件不是 NVIDIA GPU，请查阅官方文档确认对应后端与安装方式，本文示例命令未必适用。
>
> **各后端支持程度差异很大，务必核对官方硬件支持矩阵**：截至本文，NVIDIA CUDA 是**完整支持**且经过最广泛验证的路径；对 AMD ROCm、Intel（CPU/XPU）等后端，不同 `bitsandbytes` 版本可能只是**实验性/部分支持**，功能覆盖、性能与稳定性都可能与 CUDA 有差距，甚至某些量化特性尚未落地。请勿默认"任何后端都能无差别运行本文示例"。官方硬件支持矩阵与安装指引见：
> - bitsandbytes 官方文档（安装/后端支持）：https://huggingface.co/docs/bitsandbytes/main/en/installation
> - bitsandbytes 仓库：https://github.com/bitsandbytes-foundation/bitsandbytes
> - PyTorch 安装选择器（选择对应后端）：https://pytorch.org/get-started/locally/

## 四、环境要求
### 电脑配置批注
本章节涉及 LoRA / QLoRA 本地训练环境。

#### LoRA最低配置：
CPU：

* 4核以上

内存：

* 16GB+

磁盘：

* 50GB以上

GPU：

推荐：

* NVIDIA GPU

显存：

* 最低：

  * 8GB

推荐：

* 12GB+

---

#### QLoRA要求：
GPU：

本教程实训范围：

* NVIDIA CUDA GPU（**项目支持范围**；如前所述，QLoRA 并非在技术上只能用 NVIDIA，但其它后端请以 bitsandbytes 官方说明为准，本文命令按 NVIDIA CUDA 给出）

显存：

QLoRA 的设计目标正是**在更小的显存上微调大模型**（通过 4-bit 量化基础模型，其显存占用通常低于同规模的 LoRA 全精度加载）。具体可运行的显存下限取决于模型规模、序列长度、batch 大小与量化配置，下面的数值仅为常见 7B 级别模型的**经验参考**（不是"最低配置"的硬保证），请以实际运行情况为准：

参考下限：

```text
约 8~12GB（7B 级别，短序列、小 batch）
```

推荐：

```text
16GB+
```

> 显存条件说明（避免把上面的数值当成固定门槛）：同一个模型的实际显存占用受多项**测试条件**影响，上面的"参考下限"只在以下**假设条件**下大致成立，条件不同结论就不同：
> - **模型规模**：7B 级别；更大模型（13B/70B）显存需求显著上升；
> - **序列长度**：短序列（如 ≤512）；序列越长，激活值显存增长明显；
> - **batch 大小**：小 batch（如 1~2）；batch 越大占用越高；
> - **是否启用梯度检查点（gradient checkpointing）**：开启可用时间换显存、进一步降低峰值占用；
> - **量化配置**：4-bit（NF4）+ 是否双重量化、`bnb_4bit_compute_dtype` 等；
> - **LoRA 目标模块数量 / rank**：注入的可训练参数越多，优化器状态与激活越多。
>
> 因此请把上表当作**经验起点**，实际以你的模型/序列长度/batch/量化与是否开启梯度检查点的真实运行为准。

原因：

QLoRA虽然降低显存，但是仍需要：

* 量化后的基础模型；
* LoRA参数；
* 激活值；
* batch数据。

### 5.2 PyTorch检查
> 前置：LoRA/QLoRA 依赖 PyTorch，且 `bitsandbytes` 的 CUDA 量化路径要求安装**与本机 CUDA 匹配的 GPU 版 PyTorch**。直接 `pip install torch` 通常装到 CPU 版，QLoRA 会无法使用。请以 [PyTorch 官方安装选择器](https://pytorch.org/get-started/locally/) 为准，例如 NVIDIA CUDA 12.1：
>
> ```bash
> pip install torch --index-url https://download.pytorch.org/whl/cu121
> ```

查看：

```python
import torch

print(torch.__version__)

print(
    torch.cuda.is_available()
)

print(torch.version.cuda)   # 查看 torch 编译使用的 CUDA 版本
```

正常：

```text
True
```

表示 PyTorch 能看到 CUDA GPU。

> 注意：`torch.cuda.is_available()` 返回 `True` 只说明 **PyTorch 侧**能用 GPU，**并不足以证明 bitsandbytes 的 4-bit 量化路径可用**（后者还依赖 bitsandbytes 是否正确编译/匹配到本机 CUDA）。是否真能跑 4-bit，请以第八章、第十三章对 `bitsandbytes` 的检查为准。

## 九、Windows用户特别注意事项（新增）
Windows环境运行QLoRA需要额外注意。

### 9.1 推荐使用WSL2
推荐：

```text
Windows

↓

WSL2 Ubuntu

↓

CUDA环境

↓

bitsandbytes
```

原因：

Linux环境兼容性更好。

---

### 9.2 Windows原生可能问题
可能遇到：

#### 问题1：
bitsandbytes无法加载CUDA动态库。

常见原因（可能不止一种）：

* 所装 `bitsandbytes` 版本与本机 CUDA / GPU 版 PyTorch 不匹配；
* 缺少或找不到对应的 CUDA 运行库；
* Windows 原生对某些 `bitsandbytes` 版本的支持不如 Linux 完善（不同版本差异较大）。

因此这不是单一的"Windows 不支持"问题，而是受 **PyTorch、bitsandbytes 版本与本机 CUDA/硬件**共同影响。推荐优先用 WSL2 获得更接近 Linux 的兼容性；若坚持 Windows 原生，请对照官方说明确认版本组合。

---

#### 问题2：
CUDA版本不匹配。

检查：

```bash
nvidia-smi
```

确认：

* NVIDIA驱动；
* CUDA版本；
* PyTorch版本。
