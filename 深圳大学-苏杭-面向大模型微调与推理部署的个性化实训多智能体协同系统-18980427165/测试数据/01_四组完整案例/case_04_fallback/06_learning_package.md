## 一、先搞清楚三个问题（看完再动手，避免常见踩坑）

### 1. 选择合适的环境
- 安装 Linux 系统（如 Ubuntu 24.04 LTS）或使用 WSL2（Windows Subsystem for Linux 2）或云服务器。选择云服务器时，确保你有相应的云计算账号和基础操作知识。Ubuntu 22.04 LTS 的用户也可参考，步骤基本一致，但建议新装用户直接选择 24.04 以获得更长的支持周期。

### 2. 熟悉终端基础操作
- **cd**：切换目录，如 `cd /home`。
- **ls**：列出目录内容，如 `ls -l`。
- **mkdir**：创建目录，如 `mkdir newdir`。
- **cp**：复制文件或目录，如 `cp file.txt newdir/`。
- **mv**：移动或重命名文件或目录，如 `mv file.txt newdir/`。

### 3. 确保能执行 Shell 命令
- 打开终端，输入 `pwd` 查看当前路径，确保能正确执行命令。

### 最小示例回顾
- 在你的 Linux 环境中执行以下命令并验证结果：
  ```bash
  cd /home
  ls -l
  mkdir newdir
  cp file.txt newdir/
  mv file.txt newdir/
  ```
  执行完，你能在终端里看到 `newdir` 目录及其内容。


## 二、安装 Linux 系统（或 WSL2/云服务器）

### 1. 安装 Ubuntu 24.04 LTS
- 下载 Ubuntu 24.04 LTS ISO 文件。
- 使用虚拟机软件（如 VirtualBox）安装 ISO 文件，按照向导完成安装。
- 安装完成后，登录并熟悉基础操作。

### 2. 使用 WSL2
- 打开 PowerShell，运行 `wsl --list --online` 查找可用的 Ubuntu 发行版。
- 安装 Ubuntu，运行 `wsl --install -d Ubuntu`。
- 安装完成后，运行 `wsl -d Ubuntu` 启动 Ubuntu。

### 3. 使用云服务器
- 登录云计算平台（如阿里云、AWS），创建 Ubuntu 24.04 LTS 实例。
- 安装完成后，通过 SSH 连接并进行基础配置。


## 三、常用 Shell 命令

### 1. `cd`：切换目录
- 例如，`cd /home` 会切换到 `/home` 目录。

### 2. `ls`：列出目录内容
- 例如，`ls -l` 会以详细格式列出当前目录下的文件和目录。

### 3. `mkdir`：创建目录
- 例如，`mkdir newdir` 会在当前目录下创建一个名为 `newdir` 的新目录。

### 4. `cp`：复制文件或目录
- 例如，`cp file.txt newdir/` 会将 `file.txt` 复制到 `newdir` 目录中。

### 5. `mv`：移动或重命名文件或目录
- 例如，`mv file.txt newdir/` 会将 `file.txt` 移动到 `newdir` 目录中。


确保你已熟悉这些命令并能正确执行，这将帮助你在后续学习中更好地使用 Shell。

## 什么是 Linux？我为什么要装它？（①）

Linux 是一种操作系统，不同于 Windows 或 macOS。它被广泛用于服务器和云服务中，学编程时可能会用到。本教程使用的是 Ubuntu 24.04 LTS，长期支持版，适合入门。

### 选择方案

| 方案 | 一句话解释 | 优点 | 缺点 | 推荐谁用 |
|---|---|---|---|---|
| 虚拟机 | 在你现在的电脑里"模拟"出一台新电脑 | 最像真服务器，完全隔离 | 占内存（建议至少 4GB）、电脑配置低会卡 | 电脑内存 ≥ 8GB 的用户 |
| WSL2 | Windows 自带的"Linux 子系统"，像装了个 App | 轻量、启动快、和 Windows 无缝互通 | 仅限 Win10/11，部分高级功能受限 | 用 Win10/11 且不想折腾的用户 |
| 云服务器 | 租一台阿里云/腾讯云的远程电脑 | 有公网 IP，随时随地连，不占自己电脑资源 | 需要付费（学生通常可享受优惠，以官网当前价格为准）、需要网络 | 想随时远程开发、电脑配置低的人 |

> 建议：通常建议优先选择 WSL2，安装通常几分钟即可完成。只有 WSL2 装不上、或者想体验完整 Linux 桌面，才选虚拟机。

## 2.1 下载 VirtualBox（虚拟化软件）（①）

### 什么是 VirtualBox？
VirtualBox 是一款开源的虚拟机软件，能在你的 Windows 系统中创建一个虚拟的计算机环境，这个虚拟机可以安装任何操作系统。这将帮助你搭建一个运行 Linux 系统的环境，以便后续进行 LoRA 微调和 vLLM 部署的实践。

1. 打开浏览器，地址栏输入：https://www.virtualbox.org/wiki/Downloads
2. 找到 **"VirtualBox 7.x.x platform packages"** 下的 **Windows hosts** 版本，点击下载
3. 下载完成后，双击安装包
4. 安装过程：
   - 点"下一步" → 一路保持默认选项
   - 到"安装"按钮时点一下，等待进度条跑完
   - 最后点"完成"

> **常见坑预警**：安装过程中如果弹出"是否允许此应用更改你的设备"，点"是"。如果杀毒软件拦截，选择"允许"或"信任"。

本次安装 VirtualBox 的目的是为了在 Windows 系统上搭建一个虚拟的 Linux 环境，为后续的 LoRA 微调和 vLLM 部署做好准备。通过安装 VirtualBox，你可以在一个隔离的环境中进行实验，而不会影响到你的主系统。

### 2.2 下载 Ubuntu 24.04 镜像文件（①）

**什么是镜像文件（.iso）？** 你可以把它理解成一个"操作系统安装光盘的电子版"，VirtualBox 通过这个文件来安装系统。

1. 打开浏览器，访问：https://releases.ubuntu.com/24.04/
2. 找到文件名类似 `ubuntu-24.04.x-desktop-amd64.iso`（x 为具体小版本号），点击下载
3. 文件大小约为 5GB，下载时间取决于网速，可能需要几分钟到十几分钟
4. 下载完成后，**不要双击打开它**，直接保存在下载文件夹里就好

> **常见坑预警**：很多人下错版本。确认你下的是 `desktop-amd64.iso`，不是 `server` 版（server 版没有图形界面，纯黑色命令行，对新手不友好）。

#### 本块内容与学习目标的关系
下载 Ubuntu 24.04 镜像文件是后续安装虚拟机和配置环境的基础步骤。这个步骤虽然看似简单，但对于 LoRA 微调、权重合并和 vLLM 部署等高级任务来说，确保使用正确的镜像版本非常重要。在实际操作中，确保使用 `desktop-amd64.iso` 版本，因为 LoRA 微调和模型推理部署需要图形界面的支持。

### 在 VirtualBox 里创建虚拟机

1. 双击桌面上的 **"Oracle VM VirtualBox"** 图标打开软件。
2. 点击窗口上方的 **"新建"（New）** 按钮。
3. 在弹出窗口中，填写：
   - **名称**：`Ubuntu-24.04`
   - **文件夹**：选择安装位置（**不要放 C 盘**，建议选 D 盘或 E 盘）
   - **类型**：`Linux`
   - **版本**：`Ubuntu (64-bit)`
   - 点"下一步"。
4. 分配内存大小：
   - 拖动滑块到 **4096 MB**（也就是 4GB）
   - 点"下一步"。
5. 虚拟硬盘：
   - 选 **"现在创建虚拟硬盘"**
   - 文件位置默认即可，大小填 **60 GB**
   - 类型选 **VDI**，存储选 **动态分配**
   - 点"完成"。
6. 调整处理器核心数：
   - 选中刚创建的虚拟机，点 **"设置"（Settings）**
   - 左侧选 **"系统" → "处理器"**
   - **处理器数量**：`1`，**每个处理器的核心数**：`2`（总共分配 2 核）
   - 左侧选 **"存储"**，在"控制器"下点击光盘图标，选择 **"选择虚拟盘"**，找到你下载的 `ubuntu-24.04.x-desktop-amd64.iso`
   - 点"确定"。

执行完，你能在终端里看到虚拟机创建的确认信息。

#### 与当前学习目标的关系
创建虚拟机是实现 LoRA 微调和 vLLM 部署的基础环境。通过配置虚拟机，我们可以确保在安全可控的环境中进行后续的学习和实践，避免对主系统造成影响。

### 术语解释
- **VDI**：虚拟磁盘文件，一种虚拟磁盘格式，支持动态分配存储空间。
- **动态分配**：虚拟硬盘空间根据实际使用情况动态增长或收缩，节省存储资源。

在创建虚拟机时，注意不要将文件夹放在 C 盘，以避免资源竞争和潜在的数据安全问题。此外，分配的内存和处理器核心数应根据实际需求进行调整，确保虚拟机运行流畅。

#### 学习任务
1. 请确认虚拟机创建后，内存和处理器核心数是否正确设置。
2. 检查虚拟机的硬盘是否已正确分配 60GB 且采用动态分配模式。

### 2.4 安装 Ubuntu 系统（①）

1. 在 VirtualBox 窗口里，选中虚拟机，点 **"启动"（Start）** 按钮。
2. 等几十秒，会出现 Ubuntu 安装界面：
   - 左边选语言，选 **"中文(简体)"** 或 **"English"** → 点"安装 Ubuntu"。
   - 键盘布局：默认不用改，点"继续"。
   - 更新和其他软件：选 **"正常安装"**，勾上"安装 Ubuntu 时下载更新"和"安装第三方软件" → 点"继续"。
   - 安装类型：选 **"清除整个磁盘并安装 Ubuntu"** → 点"现在安装" → 弹窗点"继续"。
   - 时区：在地图上点一下中国的位置，或输入"Shanghai" → 点"继续"。
   - 用户信息：填名字、计算机名、用户名、密码 → 点"继续"。
3. 现在开始自动安装，大约 10~20 分钟。
4. 安装完后会提示"安装完成，您需要重启计算机"，点"现在重启"。
5. 重启后如果提示移除安装介质，在 VirtualBox 菜单栏点 **"设备" → "光学驱动器" → "移除虚拟盘"**，然后按回车。
6. 输入密码登录，看到桌面就完成了！

> **常见坑预警**：如果安装过程卡住超过 30 分钟不动，关掉虚拟机重新来一次，一般第二次就顺利了。

### 2.5 安装 SSH 远程连接工具（①）

**什么是 SSH？** SSH 就是 "远程桌面命令行版"。安装 SSH 之后，你可以在 Windows 的终端里直接操控虚拟机里的 Ubuntu，不用来回切换窗口。

1. 打开终端：
   - 在 Ubuntu 桌面空白处右键 → 选 "在终端中打开"。
   - 或者按 `Ctrl + Alt + T`。

2. 依次输入以下命令：

```bash
# 更新软件列表
sudo apt update

# 安装 SSH 服务和 net-tools
sudo apt install -y openssh-server net-tools

# 设置 SSH 开机自动启动
sudo systemctl enable ssh

# 启动 SSH 服务
sudo systemctl start ssh
```

> **sudo 是什么？** `sudo` 代表 "以管理员身份执行"。输入 `sudo` 命令后会让你输入密码，屏幕不会有任何显示，这是正常的安全设计。

3. 查看虚拟机的 IP 地址：

```bash
# 显示网络信息，找到你的 IP 地址
ifconfig
```

4. 找到类似这一行：`inet 192.168.xxx.xxx`，那一串数字就是 IP 地址。**记下来！** 例如：`192.168.126.128`。

5. 验证 SSH 是否可用：

   - 回到 Windows，按 `Win + R`，输入 `cmd` 回车，打开命令提示符，输入：

```bash
# 用 SSH 连接你的虚拟机
ssh 你的用户名@192.168.xxx.xxx
```

6. 如果提示输入密码，输入 Ubuntu 里的密码并回车。看到 `Welcome to Ubuntu` 之类的欢迎信息，说明成功！

> **常见坑预警**：
> - 如果提示 `connection refused`：回到 Ubuntu 终端，输入 `sudo systemctl status ssh` 看看 SSH 是否在运行。绿色 `active (running)` 才对。
> - 如果连不上，可能是 VirtualBox 网络设置问题。点 VirtualBox 的"设置" → "网络"，确认"连接方式"选的是 **"网络地址转换(NAT)"**。

安装 SSH 之后，我们可以通过 SSH 远程连接虚拟机，这对于后续进行 LoRA 微调和 vLLM 部署非常重要。在实际操作中，确保 SSH 服务正常运行，可以避免在部署过程中遇到连接问题。

### 4.2 创建普通用户（安全第一步）（①）

为什么不能一直用 root？`root` 是 Linux 里的"超级管理员"，权限太高，误操作可能删掉系统文件。日常操作应该用普通账户。

购买后，先通过云厂商控制台提供的 **"远程连接"** 或 **VNC** 功能（网页版终端）登录服务器，执行以下操作：

```bash
# 创建新用户（把 yourname 换成你想要的用户名，全英文小写）
adduser yourname
# 会提示设置密码，输入两次即可。其他信息（全名、电话等）全部直接回车跳过

# 给这个用户添加 sudo 权限（相当于给这个账号"管理员资格"）
usermod -aG sudo yourname
```

执行完，你能在终端里看到新用户的创建信息，可以使用 `whoami` 命令确认当前用户身份。

#### 本块内容与学习目标的关系

本块内容帮助我们创建了一个普通用户，并赋予了该用户管理员权限。这对于后续的 LoRA 微调和 vLLM 部署非常重要，因为我们需要在普通用户权限下进行操作，以确保系统的安全性。在实际操作中，我们会在普通用户权限下进行模型的训练和推理部署，以避免不必要的风险。

#### 术语解释

- `sudo`：允许普通用户执行具有管理员权限的操作。在后续的 vLLM 部署中，我们将使用 `sudo` 命令来运行需要管理员权限的命令。

### 4.3 配置 SSH 密钥登录（安全第二步）（①）

**为什么优先用密钥？** 密码登录容易被暴力破解。配置 SSH 密钥后，既安全又方便。

2. 执行以下命令生成密钥对：

```bash
# 生成 SSH 密钥对
ssh-keygen -t rsa -b 4096 -C "your_email@example.com"
```

3. 出现 `Enter file in which to save the key` → 直接按 **回车**（使用默认路径）
4. 出现 `Enter passphrase` → 直接按 **回车**（不设密码短语）
5. 出现 `Enter same passphrase again` → 再按一次 **回车**
6. 看到 randomart image，说明密钥生成成功
7. 通过云厂商的 VNC/远程连接，在服务器上创建 authorized_keys 文件：

```bash
# 切换到新创建的用户
su - yourname

# 创建 .ssh 目录
mkdir -p ~/.ssh

# 用 nano 编辑 authorized_keys（将 Windows 上生成的公钥粘贴进去）
nano ~/.ssh/authorized_keys
```

8. 在 Windows 上查看公钥内容：

```bash
type %USERPROFILE%\.ssh\id_rsa.pub
```

把输出的内容全部复制，粘贴到服务器 nano 编辑器中，然后 `Ctrl+O` 保存，`Ctrl+X` 退出。

9. 设置权限：

```bash
chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys
```

执行完，你能在终端里看到 randomart image 字段，可以再用 `ssh -T yourname@yourserver` 确认一下。

配置 SSH 密钥登录是安全设置的重要一步，虽然它与当前的 LoRA 微调和 vLLM 部署目标直接关联不大，但它确保了后续操作的安全性。良好的安全习惯对于整个项目至关重要，尤其是在使用云服务器时。在完成 SSH 密钥配置后，我们能够更安全地远程访问服务器，为后续的 LoRA 微调和模型推理部署做好准备。

### 6.1 文件与目录操作：最基础也最常用（新增②）

这类命令是 Linux 操作的核心，用于导航、创建、删除、复制、移动文件 / 目录。

- `ls`：列出目录下的文件 / 目录
  - `ls`：列出当前目录：`ls`
  - `ls -l`（简写 `ll`）：详细列出（含权限、大小）：`ls -l`
  - `ls -a`：显示隐藏文件：`ls -a`
- `cd`：切换目录
  - `cd ..`：进入上级目录
  - `cd /`：进入根目录
  - `cd ~`：回到当前用户主目录
  - `cd /home/user/Documents`：进入指定目录
- `pwd`：显示当前所在目录的绝对路径
  - `pwd`：示例：当前在 Documents 目录，执行后输出 `/home/user/Documents`
- `mkdir`：创建目录
  - `mkdir test`：创建单个目录
  - `mkdir -p test/aaa/bbb`：递归创建多级目录
- `touch`：创建空文件
  - `touch file1.txt file2.log`：示例：创建 2 个空文件
- `cp`：复制文件 / 目录
  - `cp file1.txt /home/user/Desktop`：复制文件
  - `cp -r test/ /home/user/Desktop`：复制目录（需加 -r 递归）
- `mv`：移动文件 / 目录（或重命名）
  - `mv file1.txt test/`：移动文件
  - `mv file1.txt newfile.txt`：重命名文件
  - `mv test/ /home/user/newtest`：移动并改名
- `rm`：删除文件 / 目录（谨慎使用！）
  - `rm file1.txt`：删除文件
  - `rm -f file1.txt`：强制删除（不提示）

### 权限管理：Linux 系统的安全核心

Linux 中文件和目录有三类权限：所有者、所属组和其他用户。权限分为读（r=4）、写（w=2）和执行（x=1）。

| 命令 | 功能说明 | 语法格式 | 实战示例 |
|---|---|---|---|
| `chmod` | 修改文件 / 目录权限 | `chmod [权限值] 文件名` 或 `chmod [用户+/-权限] 文件名` | 1. 数字法（推荐）：给所有者读+写+执行，其他只读：`chmod 744 file1.txt`（7=4+2+1，4=4）<br> 2. 符号法：给所属组添加写权限：`chmod g+w file1.txt` <br> 3. 给所有用户添加执行权限：`chmod a+x test.sh` |
| `chown` | 修改文件 / 目录的所有者（需 root 权限） | `chown [用户] 文件名` | 示例：将文件所有者改为 root：`sudo chown root file1.txt`（sudo 获取临时管理员权限）|

> **sudo 回顾**：前面安装环境时你已经用过 `sudo`。它表示"以管理员身份执行"，是权限管理中最常用的前缀。输入 `sudo` 命令后会让你输密码，输的时候 **屏幕不会有任何显示**，这是正常的安全设计。

**实践说明**：掌握这些命令后，你可以通过 `chmod` 和 `chown` 来调整文件权限，确保你的代码文件在执行时不会因为权限问题出错。在进行 LoRA 微调和权重合并时，合理的权限设置有助于保护敏感数据，避免不必要的风险。


### 本次学习与目标的关系

### 了解 Linux 运行状态

这类命令帮助你查看系统信息、进程、资源使用情况。

- `uname`：查看系统内核信息
  - 语法格式：`uname [选项]`
  - 实战示例：查看详细系统信息（常用）：`uname -a`（输出内核版本、主机名、系统架构等）

- `top`：实时查看系统进程和资源占用（类似 Windows 任务管理器）
  - 语法格式：`top`

### 6.7 新手避坑指南（新增②）

**1. 区分大小写**：Linux 命令严格区分大小写！例如 `ls` 是正确的，`LS` 会报错。

**2. 路径问题**：切换目录、复制文件时，路径写错会提示 "No such file or directory"，可先用 `ls` 查看路径是否存在。

**4. 权限不足**：操作系统文件或其他用户的文件时，会提示 "Permission denied"，在命令前加 `sudo` 获取临时管理员权限（需输入当前用户密码）。

**5. 命令记不住？**：输入命令前按 `Tab` 键自动补全（文件 / 目录名）；忘记命令语法时，用 `命令 --help` 查看帮助（如 `ls --help`），或 `man 命令` 查看详细手册（如 `man cp`）。

## 一、Linux 命令的基本格式（新增②）

在正式学习命令之前，先记住 Linux 命令的**标准格式**：

```bash
# 指令主体 [选项] [操作对象]
```

- **指令主体**：你要做什么，比如 `ls`、`cd`、`mkdir`
- **选项**（可选）：以 `-` 或 `--` 开头，用来修饰指令的行为，比如 `-l` 表示"详细列表"
- **操作对象**（可选）：指令作用的目标，比如一个文件夹路径、一个文件名

一个指令可以包含**多个选项**和**多个操作对象**。选项的顺序通常不影响结果，例如 `ls -ahl` 和 `ls -lha` 效果相同。（①+②）

### 2.2 绝对路径 vs 相对路径（新增②）

这是新手最容易混淆的概念，务必理解：（②）

- 绝对路径：从根目录 `/` 开始，不依赖当前位置，例如 `/home/zhangsan/Documents`。
- 相对路径：相对于你当前所在的位置，例如 `./file.txt`、`../backup`。

相对路径中两个重要符号：

- `./`：表示**当前目录**（可省略）
- `../`：表示**上一级目录**
- `~`：表示**当前用户的家目录**（如 `/home/zhangsan`）

> **举例**：假设你在 `/home/zhangsan/Documents` 目录下：
> - `cd /home/zhangsan` 是绝对路径，去哪都管用
> - `cd ..` 是相对路径，表示回到上一级（即 `/home/zhangsan`）
> - `cd ~` 直接回到家目录

## 五、mkdir：创建目录（①+②）

`mkdir` = **M**a**k**e **Dir**ectory，用来创建文件夹。（①+②）

   ```bash
   mkdir myproject
   ```
   执行完，你能在终端里看到 `myproject` 文件夹。

   ```bash

   mkdir -p myproject/src/models
   ```

## 九、rm：删除文件与目录（①）

`rm` = **R**e**m**ove，用来删除文件或文件夹。**此命令不可逆，请谨慎使用！**（①）

1. 删除单个文件：
   ```bash
   rm hello.py
   执行完，你能在终端里看到文件已被删除。
   ```
2. 删除多个文件：
   ```bash
   rm file1.txt file2.txt
   执行完，用 `ls` 确认文件已被删除。
   ```
3. 删除文件名以 - 开头的文件（必须用 -- 告诉 rm 后面是文件名而非选项）：
   ```bash
   rm -- -file.txt
   执行完，检查文件是否还存在。
   ```
4. 删除文件夹（必须加 -r，递归删除其中的所有内容）：
   ```bash
   rm -r myproject/
   执行完，确认目标文件夹已被删除。
   ```
5. 只删除空文件夹：
   ```bash
   rm -d empty_dir/
   执行完，检查空文件夹是否已被删除。
   ```
6. 强制删除，不提示确认：
   ```bash
   rm -f hello.py
   执行完，确认文件已被删除。
   ```
7. 强制递归删除文件夹及其中所有内容（⚠️ 极度危险，务必确认路径正确！）：
   ```bash
   rm -rf myproject/
   执行完，务必再次确认路径是否正确。
   ```

> **⚠️ 生命警告**：`rm -rf /` 会删除你的整个系统！`rm -rf ~` 会删除你的家目录！执行 `rm -rf` 前，务必先用 `ls` 确认目标路径，确保没有多打空格、没有写错路径。（①）

## 十一、新手避坑指南（①+②）

### 1. 区分文件和文件夹
`ls -l` 命令的第一列是 `d` 表示文件夹，是 `-` 表示文件。对文件夹操作时别忘了加 `-r`（如 `cp -r`、`rm -r`）。（①+②）

### 2. 路径写错
切换目录或复制文件时，路径写错会提示 "No such file or directory"，可先用 `pwd` 和 `ls` 确认当前位置和目录内容。（②）

### 3. 路径中包含空格必须用引号包裹
如果文件夹或文件名包含空格，命令行会把它当成多个参数。务必用双引号包裹：（②）

```bash
# 错误：mkdir my folder 会创建两个文件夹 my 和 folder
# 正确：
mkdir "my folder"
cd "my folder"
touch "my file.txt"
cp "my file.txt" ./backup/
rm "my file.txt"
```

### 4. 文件名以 `-` 开头时使用 `--`
Linux 命令中 `-` 开头通常表示选项。如果文件名本身以 `-` 开头，命令会误把文件名当选项解析。用 `--` 告诉命令"后面都是文件名，不是选项"：（②）

```bash
# 错误：rm -file.txt 会把 -file.txt 当成选项，报错
# 正确：
rm -- -file.txt
touch -- -data.csv
mv -- -old.txt new.txt
```

### 5. rm 命令慎用
`rm -rf` 没有回收站，删除即永久消失。删除前务必用 `ls` 确认目标。（①）

### 6. 复制目录忘加 `-r`
新手常犯 `cp mydir ./backup/` 然后报错。记住：**文件夹复制必须加 `-r`**。（①+②）

### 7. 命令记不住？
输入命令前按 `Tab` 键自动补全（文件/目录名）；忘记命令语法时，用 `命令 --help` 查看帮助，或 `man 命令` 查看详细手册。（②）

# 环境变量配置

## 一、环境变量是什么？（①）

环境变量是一些配置信息，用于存储系统或应用的路径、配置参数等信息，这些信息可以在系统启动时或运行过程中动态地改变。在Python编程中，我们经常需要配置环境变量来指定程序的运行路径或依赖库的位置。例如，设置 `PATH` 变量来指定Python解释器的位置，或者设置 `LD_LIBRARY_PATH` 来指定Python依赖库的位置。

### 1. 临时设置环境变量

在命令行中，可以使用 `export` 命令临时设置环境变量。例如，设置 `PATH` 变量：

```bash
export PATH=/home/user/lora:$PATH
```

执行完，你能在终端里看到 `PATH` 字段已经更新。

### 2. 永久设置环境变量

要永久设置环境变量，可以编辑用户的环境配置文件，如 `.bashrc` 或 `.bash_profile`。例如，编辑 `.bashrc` 文件添加：

```bash
echo 'export PATH=/home/user/lora:$PATH' >> ~/.bashrc
```

保存文件后，执行 `source ~/.bashrc` 使更改生效。

### 3. 配置CUDA环境变量

在进行深度学习开发时，需要配置CUDA环境变量。例如，设置 `LD_LIBRARY_PATH` 和 `PATH`：

```bash
export LD_LIBRARY_PATH=/usr/local/cuda/lib64:$LD_LIBRARY_PATH
export PATH=/usr/local/cuda/bin:$PATH
```

执行完，可以使用 `echo $LD_LIBRARY_PATH` 和 `echo $PATH` 验证设置是否成功。

### 4. 总结

环境变量的配置对于Python编程和深度学习开发非常重要。通过临时和永久设置环境变量，我们可以确保程序能够正确地找到所需的资源和库。这些配置在每次启动程序时都会被读取，因此确保其正确设置至关重要。

本块内容为LoRA微调、权重合并和vLLM部署提供了必要的基础知识。在配置环境变量时，我们需要注意路径的正确性，这直接影响到后续的微调和部署操作。在实际操作中，确保环境变量配置正确是成功进行LoRA微调和vLLM部署的前提。

### 1.1 通俗理解（①）

环境变量是操作系统或应用程序运行时使用的动态键值对，用于传递配置信息。你可以把它理解为操作系统的"备忘录"——系统启动时加载这些备忘录，所有程序都能读到里面的内容，并据此调整自己的行为。（①）

**常见例子**：（①+④）
- `PATH`：告诉系统去哪里找可执行程序（比如你输入 `python3`，系统就是靠 PATH 找到它的位置）
- `HOME`：当前用户的家目录路径（如 `/home/zhangsan`）
- `USER`：当前登录的用户名
- `SHELL`：当前使用的 Shell 程序路径（如 `/bin/bash`）
- `LANG`：系统语言和字符编码（如 `en_US.UTF-8`）
- `PWD`：当前工作目录路径（随 `cd` 命令自动更新）
- `EDITOR`：默认文本编辑器（影响 `git commit` 等操作）

### 1.2 为什么需要环境变量？（①）

环境变量用于控制程序行为、简化配置和实现跨进程通信。（①）

- **控制程序行为**：例如通过 `JAVA_HOME` 指定 JDK 路径，让依赖 Java 的程序知道去哪找它。
- **简化配置**：避免在每次运行程序时都手动输入长长的路径。
- **跨进程通信**：子进程会自动继承父进程的环境变量，实现配置的无缝传递。

### 2.1 临时变量：当前终端会话有效（①）

关闭终端窗口或退出 SSH 连接后，临时变量就消失了。适合快速测试。（①）

```bash
# 设置一个临时变量
export MY_VAR="hello_linux"

# 查看它的值
echo $MY_VAR
# 输出：hello_linux

# 删除这个变量
unset MY_VAR

# 再查看
echo $MY_VAR
# 输出：（空，因为已经删除了）
```

> **`export` 是什么？** 如果不加 `export`，变量只对当前 Shell 有效，子进程（比如你启动的另一个程序）读不到。加了 `export`，子进程也能继承这个变量。通常设置环境变量时都加 `export`。（①）

### 2.2 永久变量：写入配置文件，持久生效（①）

想让变量每次打开终端都存在，就需要把它写入**配置文件**。（①）

| 级别 | 配置文件 | 影响范围 | 是否需要 sudo |
|---|---|---|---|
| **用户级（推荐）** | `~/.bashrc` | 仅当前用户 | 否 |
| **用户级** | `~/.bash_profile` 或 `~/.profile` | 仅当前用户（登录时生效） | 否 |
| **系统级** | `/etc/profile` 等 | 所有用户 | 是 |

> **该选哪个？** 日常开发中，建议优先使用 `~/.bashrc`（用户级），只影响你自己，改错了也不会影响系统。系统级配置（如 `/etc/profile`）需要 `sudo`，且会影响所有用户，日常开发不建议修改。（①+④）

### 3.1 用户级配置：修改 ~/.bashrc（推荐）

`~/.bashrc` 是 Bash Shell 的配置文件，每次打开新的交互式终端时自动加载。这是日常开发中最常用的配置位置。

**操作步骤**：

1. 用 `nano` 打开配置文件：
   ```bash
   nano ~/.bashrc
   ```
2. 滚动到文件末尾，添加一行：
   ```bash
   export MY_VAR="hello_permanent"
   ```
3. 按 `Ctrl + O` 保存，`Ctrl + X` 退出。
4. 让修改立即生效：
   ```bash
   source ~/.bashrc
   ```
5. 验证：
   ```bash
   echo $MY_VAR
   ```
   输出：`hello_permanent`

> `source` 命令相当于"重新执行一遍这个配置文件"，让修改在当前终端立刻生效，不用关掉重开。

### 3.2 用户级配置：~/.bash_profile 或 ~/.profile

这两个文件在登录 Shell 时生效（比如 SSH 远程登录、系统开机登录）。如果同时存在 `~/.bash_profile` 和 `~/.profile`，系统优先读取 `~/.bash_profile`。日常开发中 `~/.bashrc` 更常用，因为每开一个终端它都会加载。只有在需要"登录时才生效"的特殊场景，才考虑这两个文件。

### 5.1 PATH：命令的"搜索路径"（①+②）

`PATH` 是最重要的环境变量，它定义了系统查找可执行文件的目录列表。（①+②）

#### 5.1.1 查看 PATH（①+②）

```bash
echo $PATH
```

执行完，你能在终端里看到类似多个路径用冒号 `:` 分隔的输出，如 `/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin`。（②）

#### 5.1.2 查看命令具体位置（②）

```bash
which python3
# 输出：/usr/bin/python3

which conda
# 输出：/home/zhangsan/miniconda3/bin/conda
```

`which` 命令能告诉你某个命令到底是从 PATH 的哪个目录里找到的。（②）

#### 5.1.3 修改 PATH（①+②）

**追加路径**（添加到末尾，优先级较低）：

```bash
export PATH=$PATH:/new/path
```

执行完，你能在终端里确认 PATH 里新增了 `/new/path`。（①）

**前置路径**（添加到开头，优先级更高，系统会先搜这里）：

```bash
export PATH=/new/path:$PATH
```

执行完，你能在终端里确认 `/new/path` 被前置了。（①）

> **安全提示**：不要把 `.`（当前目录）加入 PATH。如果你在某个目录里下载了一个名为 `ls` 的恶意脚本，而当前目录又在 PATH 里，那么你执行 `ls` 时可能运行的是恶意脚本而非真正的系统命令。（①）

> **避免重复添加**：多次 `source ~/.bashrc` 或在 `~/.bashrc` 中重复写入同一行，可能导致 PATH 里出现重复路径。建议定期检查 `~/.bashrc`，确保每条 PATH 修改只出现一次。（④）

### 5.2 LD_LIBRARY_PATH：运行时动态库路径

`LD_LIBRARY_PATH` 用于指定程序在运行时查找动态链接库（`.so` 文件）的额外路径。在安装 CUDA、PyTorch 时经常需要配置它。（②+③）

```bash
# 查看当前值
echo $LD_LIBRARY_PATH

# 临时添加 CUDA 的动态库路径
export LD_LIBRARY_PATH=$LD_LIBRARY_PATH:/usr/local/cuda/lib64
```

典型场景：你编译了一个程序，它依赖某个 `.so` 文件，但这个 `.so` 不在系统的默认搜索路径（`/usr/lib`、`/lib`）里。这时把 `.so` 所在的目录加入 `LD_LIBRARY_PATH`，程序就能正常运行了。（②）

#### 本块与学习目标的关系

### 5.3 LIBRARY_PATH：编译时库文件路径（②）

`LIBRARY_PATH` 用于指定编译器在编译阶段查找库文件的路径，主要影响静态库（`.a` 文件）和动态库（`.so` 文件）的链接。（②）

```bash
export LIBRARY_PATH=$LIBRARY_PATH:/path/to/your/libraries
```

执行完，你能在终端里看到 `LIBRARY_PATH` 变量已设置。

**三者区别总结**：（②）

| 变量名 | 作用阶段 | 查找目标 | 典型用途 |
|---|---|---|---|
| `PATH` | 执行命令时 | 可执行文件 | 让命令在任何位置都能运行 |
| `LD_LIBRARY_PATH` | 程序运行时 | 动态链接库（`.so`） | 运行依赖自定义动态库的程序 |
| `LIBRARY_PATH` | 编译链接时 | 静态库/动态库 | 编译时链接第三方库 |

> **对大模型开发者的建议**：PATH 和 LD_LIBRARY_PATH 是你后续最常打交道的两个变量。安装 Miniconda、CUDA、PyTorch 时，都需要正确配置它们。（②+③）

## 8.1 变量未生效（①）

- 终端或 IDE 没有加载 `~/.bashrc`（见 3.1 节说明）

**排查步骤**：（①+④）

1. 确认配置文件语法正确
   ```bash
   cat ~/.bashrc | grep "你的变量名"
   ```
   执行完，你能在终端里看到变量的定义字段。

2. 重新加载配置文件
   ```bash
   source ~/.bashrc
   ```
   执行完，你可以在终端输入 `echo $你的变量名` 来确认变量是否生效。

3. 检查是否有重复定义
   ```bash
   grep -r "PATH=" ~/.bashrc
   ```
   通过搜索路径定义，确认没有重复定义。

env MY_VAR=hello python3 my_script.py

### A. 系统级配置文件（①）

系统级配置会影响所有用户，修改需要 `sudo` 权限。日常开发不建议使用，但在配置公共服务器时需要了解。

#### A.1 /etc/environment（①）

这个文件的特点是不需要 `export` 关键字，直接写 `KEY=value` 即可。但它只支持简单的键值对，不支持 Shell 脚本语法（如 `$PATH` 引用）。（①）

```bash
# 需要 sudo 权限
sudo nano /etc/environment

# 添加：
JAVA_HOME=/usr/lib/jvm/java-11-openjdk

# 保存后，需要重启系统或重新登录才能生效
```

执行完，你能在终端里看到 `JAVA_HOME` 的值。

#### A.2 /etc/profile（①）

适用于全局 Bash 配置，需要 `export` 关键字。（①）

```bash
sudo nano /etc/profile

# 添加：
export PATH=$PATH:/usr/local/custom/bin

# 保存后，source 使当前会话生效，或重启系统
source /etc/profile
```

执行完，你可以在当前会话中看到 `PATH` 的变化。

### C. 清理 PATH 中的重复项（④）

多次修改 PATH 后，可能会出现重复路径。可以这样清理：

```bash
export PATH=$(echo $PATH | awk -v RS=: '!a[$0]++' | paste -sd: -)
```

执行完，你能在终端里看到 PATH 字段，确认重复项被移除。

### D. 根据环境加载不同配置（④）

```bash
# 在 ~/.bashrc 中添加
if [ "$ENVIRONMENT" = "production" ]; then
    source ~/.env.prod
else
    source ~/.env.dev
fi
```

这个脚本可以根据环境变量加载不同的配置文件，确保开发和生产环境的设置不同。

### E. 脚本调试模式（④）

```bash
# 以详细模式运行脚本，会打印每一行执行前的变量值
bash -x your_script.sh

# 或者在当前 Shell 中开启追踪
set -o xtrace
source ~/.bashrc
set +o xtrace
```

开启调试模式可以追踪脚本的执行过程，帮助调试问题。


这些技巧有助于保持环境变量和脚本配置的整洁与高效。清理 PATH 中的重复项可以避免潜在的冲突，根据环境加载不同配置文件确保了正确的运行环境，而脚本调试模式则帮助我们更好地理解脚本的执行过程。
