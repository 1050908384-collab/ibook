# 人工审核要求

本清单用于完成 50 组主评测的最终人工复核。审核只读取已经保存的真实输出，不重新调用云端模型，不修改原始输出文件。

## 一、审核前准备

- [ ] 确认 `02_50组个性化主评测/raw_outputs/` 下有 `case_001` 至 `case_050`。
- [ ] 确认每个案例的 `input.json`、`stage_planning_output.json`、`learning_package.md`、`assessment_questions.json`、`learner_answers.json`、`stage_decision.json` 存在。
- [ ] 准备知识库原文、岗位规范、官方技术文档作为事实核验依据。
- [ ] 复制并保留原始 CSV 备份；只填写复核表，不修改 raw_outputs。

原因：指标必须可追溯到固定输入和固定输出，避免人工改动结果后无法复核。

## 二、画像适配审核

填写：`06_指标统计/personalization_review.csv`

对每个案例逐项审核以下条件：

- [ ] `target_path`：阶段规划的 `block_id`/`subtopic_ids` 是否命中画像的预期学习路径。
- [ ] `difficulty`：难度是否符合画像；不一致时，必须在备注中写明前置补偿理由。
- [ ] `time_budget`：计划时长是否不超过每日学习时长，并符合案例目标周期。
- [ ] `hardware`：学习包是否考虑 GPU、显存、CPU 或部署环境限制。
- [ ] `learning_style`：内容组织是否符合理论型、实操型或混合型偏好。
- [ ] `prior_knowledge`：已掌握内容是否避免重复，缺失前置知识是否被补全。

填写规则：

- `actual_evidence`：引用实际输出中的字段、标题或原文片段，不写主观印象。
- `verdict`：只能填写 `pass`、`fail` 或 `error`。
- `reviewer_id`：填写审核人编号。
- `notes`：记录不通过原因和证据位置。

原因：比赛要求的是“画像-资源难度适配准确率”，不能用 Agent4 自动判断代替人工判定。

## 三、领域事实审核

填写：`06_指标统计/fact_check_review.csv`

对每个学习包逐条提取可核验事实，优先检查：

- [ ] API、库、框架和命令的版本及行为。
- [ ] LoRA/QLoRA、PyTorch、Transformer、vLLM 等技术概念。
- [ ] 显存、量化、训练参数和部署限制。
- [ ] 安全、合规、工程规范和岗位操作要求。
- [ ] 带有数字、阈值、性能结论或因果关系的陈述。

每条事实填写：

- `claim_text`：完整复制学习包中的事实句。
- `evidence_source`：填写知识库文件、官方文档或行业规范及章节。
- `verdict`：`pass` = 可由来源支持；`fail` = 与来源冲突；`error` = 无法核验或来源不足。
- `notes`：说明冲突点、来源链接/文件和核验日期。

原因：正式幻觉率必须基于人工核验的事实声明，不能把 Agent4 标记的问题数直接当作幻觉数。

## 四、题目与判分审核

不修改题目内容，只记录复核结果或补充判分证据：

- [ ] 每个阶段知识点的目标题量是否为 2 道。
- [ ] 题目的 `subtopic_id` 是否与阶段规划一致；兜底题单独标记。
- [ ] 选择、判断、填空题是否有可执行的标准答案。
- [ ] 简答、开放实操题是否有 rubric/参考要点。
- [ ] 主观题是否有 Agent6/LLM 判分结果、分数或等级及判分依据。
- [ ] 实操题是否有执行结果，或有明确的 LLM 评价记录。

原因：主观题没有唯一答案，但必须可判分；“有 correct_answer 且有 explanation”不能作为所有题型的统一标准。

## 五、阶段策略审核

对 `stage_decision.json` 逐条检查：

- [ ] 根据实际答题成绩和行为规则确认 `next_strategy`。
- [ ] 高分是否推进（advance）。
- [ ] 中等分数是否巩固（reinforce）。
- [ ] 低分是否降维或补前置（simplify/reteach）。
- [ ] 连续低分是否没有错误推进。
- [ ] 已掌握内容是否合理跳过。
- [ ] 用户修改目标或学习时长后，下一阶段是否发生相应调整。

原因：`assessment_accuracy` 只是答题结果，比赛真正关注的是系统是否据此做出正确的后续决策。

## 六、计算与封存

- [ ] 两名审核人独立完成后，处理分歧并在备注中记录最终依据。
- [ ] 确认复核表中不存在 `not_reviewed`。
- [ ] 运行 `python scripts/calculate_real_metrics.py`。
- [ ] 检查 `06_指标统计/metrics_summary.json` 与 CSV 行数一致。
- [ ] 将最终 CSV、JSON 和审核人签名/日期一起封存。
- [ ] 报告中只引用人工复核后的画像适配率和事实错误率。

## 七、禁止事项

- [ ] 不得修改 `raw_outputs` 中模型原始输出。
- [ ] 不得把 Agent4 自动审核率写成正式幻觉率。
- [ ] 不得把模拟学习者成绩写成系统效果指标。
- [ ] 不得为了达到阈值删除失败案例或手工改写 verdict。
- [ ] 不得在审核过程中重新调用 LLM 生成“更好”的答案。
