# 人工审核与评测操作手册

本手册用于冻结后的 50 组真实结果。它只读取 `02_50组个性化主评测/raw_outputs/`，不改原始输出。指标计算不调用 LLM；只有缺少主观题判分证据时，才按“定向 Agent6 判分”流程调用一次云端模型。

## 1. 冻结与备份

1. 复制整个 `测试数据与评测材料` 文件夹作为只读备份。
2. 确认 `case_001` 至 `case_050` 齐全，50 组均有阶段 1，`case_040` 至 `case_045` 另有阶段 2。
3. 后续不得修改 `raw_outputs`、四组展示案例或原始日志。

原因：原始输出是比赛证据；统计表只能由证据派生，不能反向改证据。

## 2. 主观题判分前检查

运行：`python scripts/build_subjective_grading_queue.py`

打开 `06_指标统计/subjective_grading_queue.csv`，逐行确认：

- `reference_answer` 是题库参考答案或关键要点；
- `submitted_answer` 是学习者实际回答；
- `simulated_is_correct` 只作对照，不能作为最终判分；
- `review_status=needs_agent6_grading` 的题目需要补判分。

当前状态：69 道主观题均已完成独立 Agent6 定向判分。复核时运行该脚本，确认 69 行均为 `review_status=evidence_present`，并在 `subjective_agent6_grading.jsonl` 中核对实际模型、评分 JSON 与哈希记录。

## 3. 定向 Agent6 判分

每道题使用固定输入：题目、参考答案/要点、评分标准、学习者回答。要求模型只返回结构化结果：

```json
{"score": 0, "max_score": 1, "verdict": "pass|partial|fail", "reason": "...", "missing_points": []}
```

必须保存：题目 ID、请求模型、实际模型、调用时间、成功状态、判分 JSON、提示词哈希和输出哈希。不要重新生成学习包、画像或学习者答案。

判分规则：

- `pass`：核心要点正确，允许表述不同；
- `partial`：方向正确但缺少关键步骤或存在小错误；
- `fail`：核心概念错误、关键步骤错误或无法回答；
- 实操题按可执行性、关键步骤、安全性和结果完整性评分。

原因：主观题没有唯一文字答案，但必须有可审计的 rubric 和判分理由。

## 4. 画像与学习路径审核

填写 `06_指标统计/personalization_review.csv`。每个 case 有 9 条审核项：前 8 条是正式的 Agent1/Agent3 画像-资源难度适配（目标路径、前置知识、阶段难度、时间预算、学习包难度、硬件可执行性、学习风格、实训可执行性）；这 400 条用于比赛的 `>=85%` 指标。第 9 条 `stage_strategy` 单独审核 Agent6 是否按答题结果、掌握状态与历史作出合理的推进/巩固/简化/回退决策，单独报告，不混入 `>=85%` 分母。`actual_evidence` 必须引用文件字段或原文，`verdict` 只能为 `pass/fail/error`。

原因：前 8 条回答“给这个画像的学习阶段和资源难度是否合理”，是画像-资源难度适配率的依据；`stage_strategy` 回答“学习后是否进行了合理的动态个性化调整”。

## 5. 领域事实审核

填写 `06_指标统计/fact_check_review.csv`。每个 case 固定抽取 3 条可核验事实：优先各选 1 条参数/版本或数值事实、命令或代码行为事实、性能/硬件/安全或因果事实；若某类不存在，用另一类替代并在 `notes` 说明。对照知识库原文、官方文档或岗位规范，填写来源和 `pass/fail/error`。

原因：该表回答“学习包是否存在技术幻觉”，正式事实错误率只由人工核验结果计算，不能使用 Agent4 的自动问题数。

## 6. 题目与覆盖审核

- 每个阶段知识点目标为 2 道专属题；统计“每知识点 2 题达标率”，不把兜底题计入专属题。
- 客观题按标准答案和自动判分判断可判分。
- 简答题、开放实操题按 rubric 和真实 Agent6 判分判断可判分。
- 阶段知识点覆盖使用规划中的 `subtopic_ids` 与题目 `subtopic_id` 求交集。

## 7. 计算与封存

1. 确认两个人工复核表不存在 `not_reviewed`。
2. 运行 `python scripts/calculate_real_metrics.py`。
3. 检查 `metrics_summary.json`、各 CSV 行数和审核记录一致。
4. 记录审核人、日期和分歧处理结果，封存最终指标。

## 8. 禁止事项

- 不得修改 raw_outputs 或删除失败案例；
- 不得把模拟 `is_correct` 当作 Agent6 判分；
- 不得把 Agent4 自动审核率当作正式幻觉率；
- 不得为了达到阈值重新生成答案或手工改 verdict；
- 不得在指标计算阶段调用 LLM。
