## 3. 多 Agent 闭环流程（每组测试内部执行顺序）

每组 case 严格按以下顺序执行（数据独立 → 不会污染下一组）：

```
 [输入] evaluation_cases.csv 的 case_id
    ↓
 0. clean_personal_data.py --yes 清空运行时 sqlite sessions/learner_profiles 等 → 5s 冷却
    ↓
 1. Agent1-学情诊断 → stage_1/diagnostic_output.json（背景技能抽取、缺失点识别）
    ↓
 2. Agent1-画像+阶段规划 → stage_1/learner_profile.json + stage_1/stage_planning_output.json
       （决定 block_id / subtopic_ids / difficulty / estimated_hours / hardware_notes / learning_style_notes）
    ↓
 3. Agent3-生成学习包 → stage_1/learning_package.md（结构化章节、扩展网址、视频卡片、习题）
    ↓
 4. Agent4-审核（最多3轮迭代）→ stage_1/review_trace.json
       （technical / pedagogy / personalization 三维审核，若有错 → 发回 Agent3 重写修复 → 审核修复率指标）
    ↓
 5. Agent3-抽题 × 2 题/知识点 → stage_1/assessment_questions.json
    ↓
 6. 仿真答题（用 evaluation_cases.answer_script_stage_1 作为正确/错误分布参数）→ stage_1/learner_answers.json
    ↓
 7. Agent6-阶段决策（三条件：acc≥0.70 / acc≥0.50 / 简化 / 全掌握+acc≥0.85+覆盖≥0.9→finish）→ stage_1/stage_decision.json
       若 case.run_stage_2=True 且策略非 finish → 继续 stage_2 重复 1~7 流程（输出到 stage_2/...）
    ↓
 8. run_summary.json + run_manifest.json 归档
```

**闭环合规校验（50 组全部通过；此为自动结构完整性校验，不等价于人工合理性复核，后者见 §6.4）**：
- 阶段1 7 个必要文件齐全率：`50/50`；
- 6 个多阶段 case（045~050）阶段2 7 个必要文件齐全率：`6/6`；
- 策略决策合法枚举：`57/57`；
- 闭环响应（Agent6→Agent1重规划/Agent3重生包/Agent4复审）：`21/21`。
