## 2.1 最简命令：先跑起来再说

你的目标是 LoRA 微调，而微调的第一步，是确保 GPU 环境是“活”的。最直接的办法，就是在终端里敲下这个命令：

```bash
nvidia-smi
```

敲下回车，屏幕上会弹出一个表格。别急着看细节，先认识它长什么样就行——这个表格就是 NVIDIA 官方提供的“GPU 仪表盘”，告诉你显卡此刻的状态。

### 这个表格里，你最该盯住哪几行？

1. **显存占用**：看“Memory-Usage”那一列。它显示“已用 / 总量”，比如 `2GB / 24GB`。如果已用接近总量，说明显存快满了，训练时容易触发 **OOM（Out Of Memory）**——这是 LoRA 微调时最常见的报错之一。
2. **GPU 利用率**：看“Util”那一列，百分比越高，说明 GPU 越在“干活”。如果训练时利用率一直很低，可能是数据加载太慢，GPU 在“摸鱼”。
3. **进程列表**：表格下方会列出占用 GPU 的进程，包括 PID（进程号）和占用的显存。如果发现某个“僵尸进程”占着显存不放，记住它的 PID，后面可以用命令把它“杀掉”来释放显存。

## 块 7

### 4.1 查看显存详情（①）

先记住一个原则：**训练 LoRA 时，显存是命根子**。你不需要每次都看满屏的监控数据，只需盯住显存这一项。

直接运行：

```bash
nvidia-smi -q -d MEMORY
```

这会输出四样关键信息：**总显存、已用显存、空闲显存、显存类型**（比如 GDDR6 或 HBM2）。

**怎么用**：训练前看一眼总显存，确认你的模型放得下；训练中看已用和空闲，判断是否接近爆显存边缘。

---

### 4.2 精准查询特定字段（①+④）

`-q -d MEMORY` 输出还是太啰嗦。用 `--query-gpu` 搭配 `--format=csv`，只提取你关心的字段，输出成表格，方便脚本处理：

```bash
nvidia-smi --query-gpu=name,temperature.gpu,memory.used,memory.total,utilization.gpu --format=csv
```

输出示例：

```
name, temperature.gpu, memory.used [MiB], memory.total [MiB], utilization.gpu [%]
Tesla V100-PCIE-32GB, 33, 128 MiB, 32510 MiB, 0 %
```

**LoRA 训练最常用的字段**：

| 字段名 | 说明 |
|---|---|
| `memory.used` | 已用显存（判断是否快爆） |
| `memory.total` | 总显存（确认硬件上限） |
| `utilization.gpu` | GPU 利用率（判断是否在计算） |
| `name` | GPU 型号（确认环境） |

## 块 8

## 5.1 查看 GPU 进程：为 LoRA 微调扫清障碍

在开始 LoRA 微调前，先学会“看住”显存。`nvidia-smi` 命令输出底部有一个 **Processes** 区域，它会列出当前占用 GPU 的所有进程。这对你很重要——训练时如果显存不够，先看看是谁在占位置。

执行 `nvidia-smi` 后，底部会显示类似这样的表格：

```bash
+-----------------------------------------------------------------------------+
| Processes:                                                                  |
|  GPU   GI   CI        PID   Type   Process name                  GPU Memory |
|        ID   ID                                                   Usage      |
|=============================================================================|
|    0   N/A  N/A      12345    C   python3                         10240MiB |
+-----------------------------------------------------------------------------+
```

**四个关键字段，逐个看懂：**

- **PID**：进程的唯一编号。后续如果发现某个进程占用了大量显存需要清理，就要用到这个编号。
- **Type**：进程类型。`C` 代表计算进程（比如 PyTorch 训练任务），`G` 代表图形进程（比如显示界面）。
- **Process name**：进程的名称，比如上例中的 `python3`。
- **GPU Memory Usage**：进程占用的显存量，单位 MiB，用于判断显存占用情况。

## 块 9

### 5.2 杀死僵尸进程，释放显存（①+④）

训练脚本崩溃后，有时进程没彻底退出，继续占着显存——这就是“僵尸进程”。做LoRA微调时，显存本来就紧张，必须手动清理：

```bash
# 1. 先用 nvidia-smi 找到 PID（比如 12345）
nvidia-smi

# 2. 杀死进程
kill 12345

# 3. 如果进程顽固不死，强制终止
kill -9 12345
```

> **安全提醒**：`kill -9` 是强制终止，进程立刻消失，未保存的数据会丢失。优先用 `kill PID`，不行再用 `kill -9`。

## 块 10

### 6.1 导出监控日志（①）

既然你的目标是 **LoRA 微调**，那训练通常要跑很久。手动盯着终端看显存太累了，咱们直接把监控结果**存成文件**，事后慢慢分析。

**方式一：简单粗暴，存成文本**

```bash
# 每 2 秒采样一次，输出到 gpu_log.txt，按 Ctrl+C 停止
nvidia-smi -l 2 -f gpu_log.txt
```

这个命令会一直跑，把每次采样的完整输出写入 `gpu_log.txt` 里。想停就按 `Ctrl+C`。适合临时记录一小段。

**方式二：结构化输出，存成 CSV（推荐）**

```bash
# 用 query 模式导出 CSV（更适合分析）
nvidia-smi --query-gpu=timestamp,name,memory.used,memory.total,utilization.gpu --format=csv -l 1 -f gpu_log.csv
```

这个更高级：它只挑你关心的字段（时间、显存占用、利用率等），存成 CSV 表格。之后用 Excel 或 Python 打开，一眼就能看出显存波动趋势。`-l 1` 表示每秒采样一次。

---

### 6.2 后台持续监控（④）

上面的命令有个问题：关掉终端，记录就停了。长时间训练时，我们想要的是**后台默默记录**，不占终端。

```bash
# 放到后台运行，即使关闭终端也继续记录
nohup nvidia-smi --query-gpu=timestamp,memory.used,utilization.gpu --format=csv -l 5 -f ~/gpu_monitor.csv > /dev/null 2>&1 &
```

拆解一下：
- `nohup`：让命令在后台运行，关终端也不怕。
- `-l 5`：每 5 秒记录一次（频率低点，文件不会太大）。
- `-f ~/gpu_monitor.csv`：存到用户主目录下的 `gpu_monitor.csv`
