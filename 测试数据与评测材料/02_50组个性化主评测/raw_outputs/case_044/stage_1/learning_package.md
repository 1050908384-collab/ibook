## 块 8

你的目标很明确：**LoRA微调 + 权重合并 + vLLM部署**。这整套流程都需要在Linux环境下操作，而你现在要做的，就是先把“远程操控Linux”的通道打通。SSH就是这条通道——装好它，你就能在Windows终端里直接指挥虚拟机里的Ubuntu，为后续跑微调脚本、部署模型省去来回切换窗口的麻烦。

下面按步骤操作，每步都有明确目的：

**1. 打开Ubuntu终端**  
在桌面空白处点右键，选“在终端中打开”；如果没有，按 `Ctrl + Alt + T` 快捷键。

**2. 安装SSH服务**  
依次输入以下命令（每行输完按回车）：

```bash
# 第1步：更新软件列表（相当于刷新应用商店的货架）
sudo apt update

# 第2步：安装SSH服务端和网络工具
#     openssh-server：让别的电脑能远程连过来
#     net-tools：提供ifconfig命令，用来查看IP地址
sudo apt install -y openssh-server net-tools

# 第3步：设置SSH开机自动启动
sudo systemctl enable ssh

# 第4步：立刻启动SSH服务
sudo systemctl start ssh
```

> **sudo是什么？** 相当于“以管理员身份执行”。Linux里普通用户不能随便装软件，加sudo就是临时获取最高权限。输入后会让你输密码，**屏幕不会显示任何字符**（不会出现`***`），这是正常的安全设计，盲打完按回车即可。

**3. 查看IP地址**  
输入 `ifconfig`，在输出中找到类似 `inet 192.168.xxx.xxx` 的一行，那一串数字就是你的IP地址。**记下来！** 例如：`192.168.126.128`

**4. 从Windows连接**  
回到Windows，按 `Win + R`，输入 `cmd` 回车，打开命令提示符，输入：

```bash
# 把“你的用户名”换成Ubuntu里的用户名，IP换成刚才记下的
ssh 你的用户名@192.168.xxx.xxx
```

如果提示输入密码，输入Ubuntu的密码并回车。看到 `Welcome to Ubuntu` 之类的欢迎信息，就说明连接成功了。

### 4.3 配置 SSH 密钥登录（安全第二步）

**为什么优先用密钥？** 密码登录容易被暴力破解。配置 SSH 密钥后，既安全又方便——这正是你后续在云服务器上跑 LoRA 微调与 vLLM 部署时，需要反复 SSH 连接的基础保障。

**操作步骤（Windows 本机 + 云服务器）：**

1. 在 **Windows** 上，按 `Win + R`，输入 `cmd`，打开命令提示符。
2. 执行以下命令生成密钥对：

```bash
ssh-keygen -t rsa -b 4096 -C "your_email@example.com"
```

3. 出现 `Enter file in which to save the key` → 直接按 **回车**（使用默认路径）。
4. 出现 `Enter passphrase` → 直接按 **回车**（不设密码短语）。
5. 出现 `Enter same passphrase again` → 再按一次 **回车**。
6. 看到 randomart image，说明密钥生成成功。

7. 通过云厂商的 VNC/远程连接，在服务器上创建 `authorized_keys` 文件：

```bash
su - yourname
mkdir -p ~/.ssh
nano ~/.ssh/authorized_keys
```

8. 在 Windows 上查看公钥内容：

```bash
type %USERPROFILE%\.ssh\id_rsa.pub
```

9. 把输出的内容全部复制，粘贴到服务器 nano 编辑器中，然后 `Ctrl+O` 保存，`Ctrl+X`

### 一、环境变量是什么？

**通俗理解**：环境变量是操作系统或应用程序运行时使用的**动态键值对**，用于传递配置信息。你可以把它理解为操作系统的“备忘录”——系统启动时加载这些备忘录，所有程序都能读到里面的内容，并据此调整自己的行为。

**常见例子**：

| 变量名 | 作用 |
|---|---|
| `PATH` | 告诉系统去哪里找可执行程序（比如你输入 `python3`，系统就是靠 PATH 找到它的位置） |
| `HOME` | 当前用户的家目录路径（如 `/home/zhangsan`） |
| `USER` | 当前登录的用户名 |
| `SHELL` | 当前使用的 Shell 程序路径（如 `/bin/bash`） |
| `LANG` | 系统语言和字符编码（如 `en_US.UTF-8`） |
| `PWD` | 当前工作目录路径（随 `cd` 命令自动更新） |
| `EDITOR` | 默认文本编辑器（影响 `git commit` 等操作） |

**为什么需要环境变量？**

1. **控制程序行为**：例如通过 `JAVA_HOME` 指定 JDK 路径，让依赖 Java 的程序知道去哪找它。
2. **简化配置**：避免在每次运行程序时都手动输入长长的路径。
3. **跨进程通信**：子进程会自动继承父进程的环境变量，实现配置的无缝传递。

## 脚本中临时修改变量

env MY_VAR=hello python3 my_script.py
# MY_VAR 仅在这次 python3 运行时有效

## 块 58

### 清理 PATH 中的重复项与配置加载（进阶参考）

你已经掌握了环境变量的核心操作，这里补充几个进阶技巧，它们会在你后续配置深度学习环境时派上用场。

**清理 PATH 重复项**  
多次修改 PATH 后，里面可能堆积重复路径，影响命令查找效率。用下面这行命令去重：

```bash
export PATH=$(echo $PATH | tr ':' '\n' | awk '!seen[$0]++' | paste -sd: -)
```

这条命令把 PATH 按冒号拆成多行、去重、再拼回去。建议在修改 PATH 后顺手执行一次，保持环境干净。

**按环境加载不同配置**  
如果你在不同环境（如生产/开发）切换，可以在 `~/.bashrc` 里写条件判断：

```bash
if [ "$ENVIRONMENT" = "production" ]; then
    source ~/.env.prod
else
    source ~/.env.dev
fi
```

这样每次打开终端，就会根据 `ENVIRONMENT` 变量的值自动加载对应配置。

**脚本调试模式**  
排查配置问题时，用调试模式看脚本实际执行了什么：

```bash
bash -x your_script.sh
```

或者在当前 Shell 中临时开启追踪：

```bash
set -o xtrace
source ~/.bashrc
set +o xtrace
```

这会打印每一行执行前的变量值，方便定位问题。
