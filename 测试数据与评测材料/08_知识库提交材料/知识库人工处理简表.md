# 知识库人工处理简表

## 先记住这一句话

`data/知识库原始数据/` 下的 73 篇 Markdown 是比赛数据包中的知识库切片主体。文章开头的来源清单和正文中的圈号引用（如 `①②③`）就是文章来源与段落借鉴关系的主要证据。

`08_知识库提交材料/` 只放说明、索引和人工审核记录，不替代文章正文，也不需要把 `data` 里的文章搬到本目录。

## 你只需要做三件事

### 1. 抽查文章内容

文件：`data/知识库原始数据/`

每个知识板块抽查 2 至 3 篇；LoRA、QLoRA、vLLM、PyTorch、DeepSpeed 等核心板块优先多看。检查：

- 文章标题、内容和知识点是否一致；
- 圈号能否对应到文章顶部的来源；
- 关键参数、版本、显存、命令和代码有没有明显错误；
- 有没有 API Key、账号、Cookie、个人信息或本机敏感路径。

发现错误就直接修改原 Markdown；没有问题就不需要改写文章。

### 2. 填写文章审核结果

文件：`knowledge_article_review.csv`

每篇文章审核后，填写：`content_review`、`source_channel_review`、`citation_review`、`privacy_review`、`reviewer`、`review_date`、`review_note`。

可使用三种简单状态：`通过`、`已修改`、`待处理`。

### 3. 抽查题目

文件：`data/seeds/test_questions.json`

每个板块抽查 3 至 5 题，确认题目确实对应知识点、答案没有明显错误、选择题只有一个正确答案。无需重新统计覆盖率，程序已确认 73/73 个知识点均有题目且每个至少 2 题。

## 不需要现在做

- 不需要把 `knowledge_source_registry.csv` 再做成一套独立人工任务；文章审核时顺手处理异常网址和核心来源即可；
- 不需要逐条人工填写 356 个网址的作者和发布时间；
- 不需要再制作逐段自动引用明细表；文章顶部来源清单和正文圈号已经是主要引用证据；
- 不需要为了凑数把 68 条运行时资料补成 73 条；73 个知识点和 73 篇文章才是知识库完整性口径；
- 不需要把 `data/知识库原始数据/` 移动或复制到 `08`。

## 最终提交时

将 `data/知识库原始数据/` 与 `08_知识库提交材料/` 一起放入比赛数据包。前者是知识库正文，后者是说明、来源索引和审核证据。
