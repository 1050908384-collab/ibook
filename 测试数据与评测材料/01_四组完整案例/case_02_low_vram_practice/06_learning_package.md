## 块 1

### 第一章：先搞清楚——我们到底在装什么？

很多新手一上来就下载安装包，点完"下一步"后一脸茫然。先花 2 分钟理解三个核心概念，后面每一步你都知道自己在做什么。

**第一个概念：Python 解释器本身。** 这是运行 Python 代码的"发动机"。你写的 `.py` 文件只是文本，真正让这些文本变成程序执行结果的，是解释器。你已经有 Python 编程基础，这里只需记住：我们装的是能让代码跑起来的那个核心程序。

**第二个概念：包管理器（pip）。** 装完解释器后，你会发现还需要各种第三方库——比如你之后做 QLoRA 微调时要用到的 `transformers`、`peft`、`bitsandbytes`。pip 就是帮你下载、安装、管理这些库的工具。它就像手机应用商店，只不过装的是 Python 库。

**第三个概念：虚拟环境。** 这是最容易忽略但极其重要的一环。不同项目可能需要不同版本的库——比如项目 A 要 `torch 2.0`，项目 B 要 `torch 1.13`，如果都装在同一处，版本冲突会让你头疼不已。虚拟环境就是给每个项目一个独立的"小房间"，互不干扰。

> **思考题**：你打算做 QLoRA 微调，需要装 `transformers`、`peft`、`bitsandbytes` 等库。如果不用虚拟环境，直接全局安装，之后另一个项目需要不同版本的 `transformers` 时会发生什么？想清楚这个问题，你就明白虚拟环境的价值了。

**安装方式的选择**：你可以直接去 python.org 下载安装包，也可以使用 Anaconda——后者自带 Python 解释器和大量常用库，还集成了 conda 这个更强大的包管理器。对于你这种有明确目标（QLoRA 微调）且硬件是 RTX 3060 12GB 的情况，建议优先考虑 Anaconda，因为后续配置 CUDA 相关依赖时，conda 处理依赖关系更省心。


**完成本块后的小任务**：用自己的话说明——"环境准备"和你最终要做的 QLoRA 微调之间是什么关系？简单说就是：QLoRA 微调需要跑 Python 代码、需要调用 PyTorch 等深度学习库、需要管理多个依赖版本，而环境准备就是把这些基础设施搭好。如果你在阅读中遇到无法解释的术语（比如"依赖"、"CUDA"），先记录下来，之后提问时带上。

## 块 2

### 1.1 Python 解释器：程序的"翻译官"

你写的 Python 代码是人类能看懂的文字，但电脑只认 0 和 1。**Python 解释器**的作用就是把你的代码翻译成电脑能执行的指令。没有它，你写的 `.py` 文件只是一堆文本。

你已经掌握 Python 编程基础，这里只需记住一个关键点：解释器是你写的代码与硬件之间的唯一桥梁。后续做 QLoRA 微调时，你运行的每一条训练命令，最终都是通过解释器翻译后才被 GPU 执行的。

### 1.2 代码编辑器（IDE）：你的"工作台"

记事本也能写代码，但效率极低。**IDE（集成开发环境）**提供语法高亮、自动补全、运行调试等功能，让你写代码像用 Word 写文档一样舒服。本文推荐两款：**VS Code**（轻量免费）和 **PyCharm**（专业强大）。

考虑到你的 RTX 3060 12GB 显存主要用于跑微调脚本而非日常编码，建议选 VS Code——它启动快、内存占用低，能把更多资源留给训练进程。

### 1.3 虚拟环境：项目的"独立房间"

想象你同时在做两个项目：A 项目需要 `numpy 1.0`，B 项目需要 `numpy 2.0`。如果把它们都装到同一个 Python 里，就会冲突报错。**虚拟环境**就是为每个项目创建一个独立的 Python 空间，互不影响。本文使用 **conda** 来管理虚拟环境，它是目前最主流的方案。

这个设计动机很直接：QLoRA 微调依赖特定版本的 transformers、peft、bitsandbytes 等库，虚拟环境能让你为微调项目单独锁定一套依赖，避免与日常开发互相污染。

**与学习目标的关系**：这三样工具是 QLoRA 微调的地基——解释器负责运行微调脚本，IDE 负责编写和调试脚本，虚拟环境负责隔离微调所需的库版本。缺了任何一环，微调流程都无法顺畅跑通。

**记录待提问术语**：如果你在后续学习中遇到 `bitsandbytes`、`peft`、`4-bit 量化` 等术语暂时无法理解，先记录下来，在下一轮提问时一并解决。

**思考题**：为什么虚拟环境用 conda 而不是直接 pip install？提示：conda 不仅能管理 Python 包，还能管理 Python 版本本身——这对微调框架的兼容性意味着什么？

### 2.1 Windows 用户

**第一步：下载安装包**

1. 打开浏览器，访问 https://www.python.org
2. 鼠标移到顶部菜单 **Downloads**，网站会自动推荐 Windows 版本（如 `Python 3.13.x`）。
3. 点击下载 **Windows installer (64-bit)**。

**第二步：运行安装程序（⚠️ 关键步骤）**

双击下载的 `.exe` 文件，弹出安装界面后，**务必做两件事**：

1. **勾选最下方的 "Add python.exe to PATH"**  
   这个选项会把 Python 添加到系统的"环境变量"中。如果不勾选，你打开命令行输入 `python` 时，系统会提示"不是内部或外部命令"，后续所有命令行操作都无法进行。这一步直接决定了你之后能不能在终端里顺畅地调用 Python。

2. 点击 **"Install Now"**（默认安装）即可。  
   默认安装路径在 `C:\Users\你的用户名\AppData\Local\Programs\Python\Python313`（其中 `Python313` 中的 `3` 和 `13` 对应你下载的版本号，如 Python 3.13 即为此路径），不含中文和特殊符号，避免后续路径报错。进阶用户如果想改路径，务必确保路径中**没有中文或空格**。

**第三步：验证安装**

1. 按 `Win + R`，输入 `cmd`，回车打开命令提示符。
2. 输入以下命令并回车：

```bash
python --version
```

3. 如果显示 `Python 3.13.x`（或你下载的具体版本号，如 `Python 3.13.0`），说明安装成功！
4. 再输入：

```bash
pip --version
```

如果也显示版本号，说明 Python 的包管理工具 `pip` 也一并安装成功了。


**完成本块后的小任务**：用自己的话说明本块内容与当前学习目标（QLoRA 微调）的关系。简单来说，QLoRA 微调依赖 Python 环境来运行训练脚本和调用 HuggingFace 工具链，而本块完成的 Python 与 pip 安装正是搭建这个环境的第一步。如果遇到无法解释的术语（比如"环境变量"或"包管理工具"），先记录下来，在后续学习中再提问。

### 2.2 macOS 用户

较老的 macOS 曾预装 Python 2.7，但**现代 macOS（Catalina 10.15 起）已不再预装 Python 2**；部分系统可能带有供系统脚本使用的旧版 `python3`。无论哪种情况，都**强烈建议自行安装最新版 Python**，避免直接依赖系统自带版本。

**方法一：官方安装包（推荐新手）**

1. 访问 https://www.python.org，下载 **macOS 64-bit universal2 installer**（`.pkg` 文件）。
2. 双击运行，一路点击 "Continue" → "Install" 完成安装。
3. 打开终端（Terminal），输入验证：

```bash
python3 --version
pip3 --version
```

**为什么用 `python3` 而不是 `python`**：在现代 macOS 上，命令行默认**并不提供** `python` 命令（早期版本曾指向系统自带的 Python 2，现已移除），系统与官方安装包统一使用 `python3`。因此请始终用 `python3` / `pip3`，避免踩到"命令不存在"或误用系统版本的坑。

**方法二：Homebrew（适合已有 Homebrew 的开发者）**

如果你已经安装了 Homebrew（macOS 的包管理器），在终端执行：

```bash
brew install python
```

安装完成后，同样用 `python3 --version` 验证。


**与当前学习目标的关系**：你正在为 QLoRA 微调搭建环境，而 Python 是运行 HuggingFace 生态工具链（如 transformers、peft、bitsandbytes）的基础解释器。确保 `python3` 和 `pip3` 可用，是后续安装依赖库、执行微调脚本的前提。如果你在安装过程中遇到任何无法解释的术语（如 universal2、Homebrew 的具体行为），先记录下来，稍后统一提问即可。

### 2.3 Linux 用户（Ubuntu/Debian）

Linux 通常预装 Python，但版本可能较老。对于后续要做 QLoRA 微调的你来说，这一步的价值在于：确保系统里有一个干净、可用的 Python 3 环境，避免后续装依赖时被系统自带的旧版本干扰。

以下是 Ubuntu/Debian 系列的安装命令：

```bash
# 更新软件源
sudo apt update

# 安装 Python 3 和 pip
sudo apt install python3 python3-pip python3-venv -y

# 验证
python3 --version
```

**为什么这样写**：`-y` 参数表示自动确认安装，不需要你手动输入 `y`。`python3-venv` 是创建虚拟环境所需的模块，一起安装避免后续补装。虚拟环境在微调场景下几乎是必需品——不同项目对依赖版本的要求经常冲突，隔离是省心省力的做法。

一个值得留意的点：这里的 `python3` 是 Ubuntu/Debian 的默认 Python 3 入口，版本可能不是最新的 3.10+。如果你的 QLoRA 工具链对 Python 版本有明确要求，后续可能需要通过其他方式升级，但当前这一步先把基础环境搭好即可。

**与学习目标的关系**：本块属于环境准备阶段。QLoRA 微调依赖 HuggingFace 生态工具链（如 transformers、peft、bitsandbytes），这些库都跑在 Python 之上。先把 Python 3 和虚拟环境模块装好，等于给后续安装这些依赖铺好了地基——地基不稳，上层工具装得再快也会在运行时出问题。如果你在安装过程中遇到任何无法解释的术语或报错，先记录下来，带着问题进入下一步。

## 块 7

### 2.4 操作系统与实训环境该怎么选

你的目标是 QLoRA 微调，而 QLoRA 属于 GPU 密集型实训。这一节的环境选择，直接决定你后面能不能顺利跑起训练脚本。

不同学习阶段对环境的要求不同，选对环境能少走很多弯路：

- **日常写 Python、练命令行（Windows 用户）**：推荐启用 **WSL2 + Ubuntu LTS**（如 Ubuntu 22.04/24.04 LTS）。WSL2 本质上是基于虚拟化技术的轻量级虚拟机，但提供接近原生的 Linux 体验，命令、路径、包管理都和后续的服务器一致，比在 Windows 原生 CMD 里练命令更贴近实战。安装只需管理员 PowerShell 执行 `wsl --install` 即可。你已有 Python 基础，这里只需知道：WSL2 的命令体验与服务器高度一致，但并非完全等同。

- **日常写 Python（macOS / Linux 用户）**：直接使用本机终端即可，本身就是类 Unix 环境。

- **LoRA / QLoRA 微调、vLLM 部署等 GPU 实训**：应使用**装有 Ubuntu LTS 的 NVIDIA GPU 云服务器，或本地实体 Linux（Ubuntu LTS）机器**。这类任务依赖 NVIDIA 驱动、CUDA 与显卡直通，Ubuntu LTS 对深度学习生态的支持最成熟、文档最全。你手头是 RTX 3060 12GB，本地跑 QLoRA 是可行的——QLoRA 的量化设计正是为了在消费级显卡上做微调，12GB 显存属于可接受范围，但要注意 batch size 和序列长度需要相应调小。

> **⚠️ 不推荐的做法**：不要把 **"CentOS + VirtualBox 虚拟机"当作最佳方案**。CentOS 8 已停止维护、生态逐渐落后（CentOS 7 虽维护至 2024 年 6 月 30 日，但整体生态已不如 Ubuntu LTS 活跃）；而 VirtualBox 这类桌面虚拟机**默认无法直通 NVIDIA GPU**，虽然通过特定配置可能实现 GPU 直通，但通常不推荐用于 GPU 训练，只适合做纯 CPU 的隔离小实验。命令练习用 WSL2/Ubuntu LTS，GPU 实训用云上或实体的 Ubuntu LTS，才是稳妥路线。

**思考题**：为什么 GPU 实训不推荐用虚拟机，而命令练习用 WSL2 就够了？提示：从 GPU 直通和生态成熟度两个角度想。

**与学习目标的关系**：QLoRA 微调依赖 CUDA 和 GPU 直通，本节帮你确认"在哪个环境里做这件事"——答案是 Ubuntu LTS 实体机或云服务器。你的 RTX 3060 本地跑得动，但前提是系统选对。遇到"CUDA""显卡直通"这类术语如果解释不清，先记下来，后续章节会展开。

## 块 9

### 3.1 什么时候才需要镜像源

`pip` 是 Python 的包管理工具，用来安装第三方库（比如 `numpy`、`pandas`）。默认情况下，`pip` 从官方 PyPI 服务器（`pypi.org`）下载——这是最权威、最完整、最应保留的默认源。

只有当你处在网络受限环境、访问官方源明显变慢或经常超时时，才考虑临时切换到国内镜像。**镜像是"网络不好时的临时加速手段"，不是必须永久替换的默认设置**——官方源始终应作为首选。

### 3.2 首选做法：临时指定镜像源（推荐）

如果只是某次安装慢，最干净的做法是**只对这一次安装临时指定镜像**，不改动任何全局配置：

```bash
pip install numpy -i https://pypi.tuna.tsinghua.edu.cn/simple
```

**为什么推荐这种方式**：它不会影响你平时的默认行为，官方 PyPI 仍是默认源；哪天网络恢复正常或镜像出问题，你无需再去清理配置。


**与当前学习目标的关系**：你要做 QLoRA 微调，后面安装 `transformers`、`peft`、`bitsandbytes` 等库时，如果官方源下载慢，这条临时指定镜像的命令就能派上用场——它只影响那一次安装，不会污染你后续的默认环境。

**记录疑问**：如果你对"镜像源"具体是什么、为什么清华的服务器也能提供 PyPI 的包感到困惑，先记下来，后面章节会涉及。

### 3.3 进阶：将镜像设为默认（仅在长期网络受限时）

只有当你**长期处于网络受限环境**、几乎每次都要用镜像时，才考虑把它写入配置作为默认源。配置后请记得：官方 PyPI 仍是最可靠的来源，网络恢复后建议改回或删除该配置。

**Windows 用户：**

1. 按 `Win + R`，输入 `%APPDATA%`，回车。这会打开一个类似 `C:\Users\你的用户名\AppData\Roaming` 的文件夹。
2. 在该文件夹下**新建一个名为 `pip` 的文件夹**。
3. 在 `pip` 文件夹内**新建一个名为 `pip.ini` 的文本文件**。
4. 用记事本打开 `pip.ini`，写入以下内容：

```ini
[global]
index-url = https://pypi.tuna.tsinghua.edu.cn/simple
```

**为什么这样写**：`index-url` 告诉 pip 默认从这个地址下载包。

> **⚠️ 关于 `trusted-host`**：网上很多教程会顺手加一行 `trusted-host = ...`。**除非镜像确实无法通过 HTTPS 证书验证，否则不要加**——`trusted-host` 会让 pip 跳过对该域名的 TLS 校验，等于放弃了传输安全。清华、阿里等主流镜像都提供合法的 HTTPS 证书，正常使用**无需** `trusted-host`。只有在企业内网自建源、或确实遇到证书报错且已确认来源可信时，才临时加它。

**macOS / Linux 用户：**

1. 打开终端，执行：

```bash
mkdir -p ~/.config/pip
```

2. 创建配置文件：

```bash
nano ~/.config/pip/pip.conf
```

3. 写入同样的内容：

```ini
[global]
index-url = https://pypi.tuna.tsinghua.edu.cn/simple
```

4. 按 `Ctrl + O` 保存，`Ctrl + X` 退出。

### 3.4 验证配置是否生效

在命令行输入：

```bash
pip config list
```

如果看到 `global.index-url='https://pypi.tuna.tsinghua.edu.cn/simple'`，说明配置成功。

### 3.5 改回官方源

如果你想恢复默认的官方 PyPI，删除上面创建的 `pip.ini` / `pip.conf` 文件即可，或执行：

```bash
pip config unset global.index-url
```

### 5.1 为什么用 Conda

前面提到，虚拟环境可以为每个项目创建独立的 Python 空间。**Conda** 是目前最主流的虚拟环境管理工具，它不仅能创建虚拟环境，还能管理不同版本的 Python 解释器本身。对于后续学习深度学习（需要 PyTorch、CUDA 等复杂依赖），conda 几乎是必备工具。

结合你的 QLoRA 微调目标，这一点尤其关键——PyTorch 和 CUDA 这类依赖的版本组合非常挑剔，用 conda 隔离环境可以避免不同项目之间的依赖冲突，让实验环境可复现。

### 5.2 安装 Conda：Anaconda vs Miniconda

有两个选择：

| 选项 | 特点 | 推荐人群 |
|------|------|----------|
| **Anaconda** | 体积大（约 500MB+），预装了大量数据科学库（numpy、pandas、jupyter 等） | 做数据分析、不想手动装包的用户 |
| **Miniconda** | 体积小（约 50MB），只包含 conda 和基础 Python，按需安装 | 希望环境干净、做项目开发的用户 |

**本文推荐 Miniconda**，因为环境更干净，后续需要用什么包装什么包。对 QLoRA 微调来说，你只需要 PyTorch、transformers、peft 等特定包，用 Miniconda 按需安装更合适，不会有一堆用不上的预装库占空间。

**安装步骤：**

1. 访问 https://docs.conda.io/en/latest/miniconda.html。
2. 下载对应系统的安装包（Windows 选 `.exe`，macOS 选 `.pkg` 或 `.sh`，Linux 选 `.sh`）。
3. 运行安装程序：
   - **Windows**：一路下一步，**保持默认、不要勾选 "Add Miniconda3 to my PATH environment variable"**（该选项被安装器标为"不推荐"）。把 Miniconda 直接塞进系统 PATH 容易和系统已有的 Python / 其他工具冲突，导致 `python`、`pip` 指向不明。日常改用开始菜单里的 **"Anaconda Prompt (Miniconda3)"** 来使用 conda 即可。
   - **macOS/Linux**：运行 `.sh` 文件后，按提示输入 `yes` 同意协议、选择安装路径，并在最后一步选择 `yes` 让安装器执行 **`conda init`**（完成 shell 初始化）。这样每次打开终端时 conda 会通过初始化脚本正确接管，而不是靠把目录硬加进 PATH。

4. **验证安装**：打开一个**新的**终端（Windows 用 **"Anaconda Prompt (Miniconda3)"**；macOS/Linux 关闭并重开终端使 `conda init` 生效），输入：

```bash
conda --version
```

如果显示类似 `conda 24.x.x`，说明安装成功。

QLoRA 微调需要一套完整的 Python 深度学习环境，包括 PyTorch、CUDA 支持、transformers 库等。Conda 是这套环境的管理底座——它让你能创建独立的项目环境，避免依赖冲突，也为后续安装 PyTorch 等复杂依赖做好准备。完成本块后，你的机器上就有了管理这些环境的基础工具。

### 第八章：常见问题排查

环境搭建阶段最容易卡住人的往往不是某个高深概念，而是几个反复出现的“小毛病”。下面这张排查表把最常见的现象、原因和解决办法列在一起，你遇到问题时直接对照即可。

| 问题现象 | 可能原因 | 解决方案 |
|----------|----------|----------|
| 输入 `python` 提示"不是内部或外部命令" | 安装时未勾选 "Add to PATH" | 重新运行 Python 安装程序，选择 "Modify"，勾选 "Add Python to environment variables" |
| `pip install` 速度极慢或超时 | 网络受限，访问官方 PyPI 慢 | 按第三章临时加 `-i` 指定国内镜像（如清华源）；长期受限再考虑设为默认源 |
| `conda` 命令找不到 | 未使用 Anaconda/Miniconda Prompt（Windows）/ 未执行 `conda init`（macOS/Linux） | Windows 用户使用开始菜单的 `Anaconda Prompt (Miniconda3)`；macOS/Linux 运行 `conda init` 后重开终端 |
| VS Code 提示"未选择 Python 解释器" | 未配置解释器路径 | 按 `Ctrl + Shift + P` → `Python: Select Interpreter` 手动选择 |
| 激活 conda 环境后，`python` 版本不对 | 系统里存在多个 Python | 使用 `where python`（Windows）或 `which python`（Mac/Linux）查看路径，确保指向 conda 环境 |
| pip 安装后，Python 里 `import` 报错 | pip 装到了错误的环境 | 激活目标 conda 环境后，使用 `python -m pip install 包名` 安装 |

几个值得留意的点：

- 第一行的 PATH 问题，本质是系统不知道去哪里找 `python` 这个可执行文件。勾选环境变量就是把这个路径告诉系统，属于一次性配置。
- 镜像源那行，`-i` 参数只是临时指定下载源，不改动全局配置，适合偶尔用一次；如果你经常装包，再考虑设为默认。
- 最后两行都指向同一个坑：**多个 Python 并存时，命令和包可能装到不同环境**。用 `python -m pip install` 而不是裸 `pip install`，能确保装进当前激活的环境——这是你之后做 QLoRA 微调时反复要用的习惯。


**本块与当前学习目标的关系**：QLoRA 微调依赖一个干净、可控的 Python 环境。上面这些排查手段，本质是保证你后续安装 `transformers`、`peft`、`bitsandbytes` 等库时，装得对、装得快、import 不报错。换句话说，这块内容是你进入微调实操前的“地基加固”。
