## 块 1

## 一、为什么需要LoRA？（①②③）

### 1.1 大模型微调的问题

现代大语言模型（如LLaMA、Qwen、Baichuan、Mistral）通常拥有数十亿甚至上百亿参数。以7B模型为例，就是70亿参数。

如果采用传统方式微调——预训练模型 → 更新全部参数 → 保存新模型——你需要：

- **巨大的GPU显存**：训练时不仅要存模型参数W，还要存梯度∂W和优化器状态（如Adam moment），实际显存需求远大于模型本身。
- **大量训练时间**：更新全部参数意味着每步都要计算和回传海量梯度。
- **巨大的存储空间**：每个微调任务都要保存一份完整的新模型副本。

### 1.2 全参数微调的问题

假设模型有100亿参数，训练时不仅保存模型参数W，还需要保存梯度∂W和优化器状态。实际显存需求远大于模型大小。

---

## 二、LoRA核心思想（①②）

**核心洞察**：微调时不需要更新全部参数。

LoRA的出发点很简单：虽然模型参数很多，但微调时真正需要的“变化量”其实很小。这个变化量（记为ΔW）可以用**低秩矩阵**来近似表达。

**ΔW = BA** 到底代表什么？

- 原始模型权重是W，微调后的权重是 W + ΔW。
- LoRA冻结原始权重W，仅训练低秩矩阵A和B形成增量更新ΔW=(α/r)BA

---

传统微调是直接改原权重：`W → W'`。

LoRA 的做法完全不同：**原权重 W 保持冻结，不动它**。我们额外新增一个参数 `ΔW`，最终模型用的是：

`W' = W + ΔW`

也就是说，LoRA 不碰原来的 W，只训练新增的 ΔW。

**为什么只训练 ΔW？** 因为大模型已经通过海量数据学会了语言规律、世界知识和推理能力。微调通常只是对已有能力做“方向调整”，不必重新学全部参数，只学任务相关的变化量往往就够了。

> 注意：这是一种教学直觉，不是严格结论。能否用 LoRA 替代全参数微调，取决于任务与预训练能力的差距、数据规模、目标模块与秩的设置等。差距大或数据充足时，全参数微调仍可能更好。

如果微调时要修改`ΔW`，它同样需要`4096 × 4096`个参数。这就是低效的根源。

## 四、LoRA低秩分解核心思路

LoRA提出：**不要直接学习完整矩阵**，而是把它**拆成两个小矩阵**。原始权重`W`保持冻结不动，新增的`ΔW`由`B × A`组成——用两个小矩阵的乘积来近似替代完整的大矩阵更新。

## 5.2 类比理解：为什么LoRA用少量参数就够了？

想象一张**4000×4000像素**的高清图片，完整保存需要**1600万个数据**。但假如这张图片的主要变化只是**亮度**、**对比度**和**少量结构变化**，你根本不需要存下每一个像素——用少量参数就能描述这些变化。

LoRA的思路完全一样：**用少量参数描述模型的变化方向**。

预训练模型本身已经很强大了，微调时我们不需要重学所有知识，只需要描述“模型该往哪个方向变一点点”。这个“变化方向”用低秩矩阵就能表达，参数少、效果好。

> **澄清**：上述类比仅用于帮助理解参数效率。LoRA**不是**对原始权重进行分解（如SVD），而是**冻结原权重**，额外训练一个低秩增量矩阵ΔW=BA，最终更新为W+ΔW。

**r 是什么？——一个控制“容量”的旋钮**

`r` 就是低秩矩阵的“维度”，代码里写成 `r=8`。你可以把它理解为微调时给模型加的“小插件”的粗细：**r 越大，插件越粗，能记的东西越多，但代价也越大。**

**r 的取舍：**

- **r 大**：表达能力更强（能学更复杂的模式），但参数更多、显存占用更高。
- **r 小**：省显存、参数少，但表达能力受限。

**从哪开始试？**（只是起点，不是定死的规则）

| 任务类型 | r 起点参考 |
|---------|-----------|
| 简单任务 | 4 ~ 8 |
| 普通微调 | 8 ~ 32 |
| 复杂任务 | 64+ |

**别背表，用验证集说话**——这才是选 r 的可靠方法：

1. **留出验证集**：比如 8:2 或 9:1 划分数据，后续比较都看验证集指标。
2. **固定其它变量**：`target_modules`、学习率、`lora_alpha`（或固定 alpha/r 比例）、训练步数都不变，只改 `r`。
3. **小范围搜索**：从 `r ∈ {4, 8, 16, 32}` 开始，逐个训练，记录验证集上的 loss/accuracy/F1、显存和耗时。

## 块 8

## 8.2 lora_alpha：控制LoRA更新强度

`lora_alpha` 是一个数值参数，例如 `lora_alpha=16`。它的作用是**控制LoRA更新强度**——也就是告诉模型“你希望LoRA带来的改变有多大”。

实际使用中，LoRA会冻结原始权重W，只训练低秩矩阵A和B，增量ΔW=(α/r)BA。这里的 `r` 就是你在前面学过的秩（rank）。比如 `r=8`、`alpha=16` 时，缩放比例就是 `16/8 = 2`。这个比例越大，LoRA对模型参数的更新幅度就越大。

**动手理解**：你可以把 `alpha` 想象成“音量旋钮”，`r` 是“声道数”。旋钮开得越大，LoRA的声音（影响）就越明显。

---

## 8.3 lora_dropout：防止过拟合

```python
lora_dropout=0.05
```

`lora_dropout` 的作用是**防止LoRA参数过拟合**。它会在训练时对LoRA层的输入或激活进行随机置零（如0.05表示5%概率），让模型不能过度依赖某几个参数，从而提升泛化能力。

**一句话理解**：Rank就是LoRA中那个“低秩矩阵”的中间维度大小，它决定了你要训练多少新参数。

**为什么叫“秩”？**

“秩”是线性代数里的概念，中文叫**矩阵的秩**。在LoRA里，我们不直接改原模型权重，而是用两个小矩阵相乘来模拟权重的变化。

### 4.1 Rank太小的问题

假设你把 `r` 设成 `2`，比如：

```python
r=2
```

这会带来什么后果？简单说，模型能“学进去”的东西太少了。具体表现为：

- **学习能力不足**：低秩矩阵能表达的模式有限，复杂规律装不下。
- **欠拟合**：训练集上的表现都不好，更别说泛化到新数据。
- **新任务知识无法充分表达**：你想让模型学会的新技能，它“记不住”。

直观感受就是：

```text
训练loss下降慢
效果提升有限
```

**动手验证（hands-on）**：如果你在跑LoRA微调，试着把 `r` 从 `8` 改成 `2`，对比一下训练loss的下降速度。你会发现loss曲线明显“拖沓”，最终效果也差一截。这就是rank太小最直接的信号。

---

### 4.2 Rank太大的问题

反过来，如果把 `r` 设得很大，比如 `r=256`：

```python
r=256
```

虽然学习能力上去了，但代价也很明显：

- **参数增加**：要训练的东西变多了。
- **显存增加**：显卡内存占用更高。
- **训练速度下降**：每一步计算更慢。

更重要的是，**LoRA的优势被削弱了**。LoRA的核心价值就是“参数高效”——冻结原权重，仅训练低秩矩阵A和B形成增量更新，用少量参数达到接近全量微调的效果

## 6.1 控制LoRA影响强度

我们直接上手感受一下 `alpha` 是怎么“拧”LoRA影响强度的。

**场景一：放大影响**

假设你设了 `r=8`，同时 `alpha=16`。缩放计算是：

```text
16/8 = 2
```

这意味着LoRA的更新会被**放大2倍**。直观理解：你希望LoRA对模型改动更明显，就把 `alpha` 调得比 `r` 大。

**场景二：保持原样**

如果 `alpha=8`，那么：

```text
8/8 = 1
```

缩放系数为1，LoRA更新保持原始比例，不放大也不缩小。

**场景三：减弱影响**

如果 `alpha=4`，那么：

```text
4/8 = 0.5
```

LoRA影响减半，模型改动更温和。

## 七、Alpha与Rank的关系（重点）

核心公式就一个：

```text
alpha / r
```

这个比值就是控制LoRA更新“强度”的**关键缩放系数**。

**但注意**：别把 `alpha/r` 当成“唯一开关”。它只是缩放系数，实际落到权重上的更新量还受这些因素影响：

- **学习率**：直接决定每步更新步长。`alpha/r` 调大又不下调学习率，容易一起放大导致震荡。很多实践里，调学习率比频繁改 `alpha` 更常用。
- **初始化**：常见实现中 `A` 用小随机值、`B` 初始化为0，训练开始时

**一、LoraConfig是什么？（①）**

PEFT（Parameter-Efficient Fine-Tuning）是 Hugging Face 提供的参数高效微调库。LoRA 训练流程如下：

```text
加载基础模型 → 创建LoraConfig → 指定LoRA插入位置 → 生成LoRA Adapter → 训练LoRA参数
```

其中，`LoraConfig` 负责告诉 PEFT 四件事：LoRA 放在哪里、规模多大、训练强度如何、是否使用 dropout。

---

## 块 20

## 3.1 target_modules是什么？

一句话理解：**target_modules 就是告诉 LoRA“你要往模型的哪些地方动手脚”**。LoRA 不会默认修改所有层，你必须明确指定。

### Transformer 里的常见结构

一个标准的 Attention 模块通常包含四个投影层：

```text
Attention
├── q_proj   （Query 投影）
├── k_proj   （Key 投影）
├── v_proj   （Value 投影）
└── o_proj   （Output 投影）
```

### 怎么指定？

用列表把想注入 LoRA 的层名写出来，例如：

```python
target_modules=[
    "q_proj",
    "v_proj"
]
```

这段代码的含义是：**只给 Query 投影层和 Value 投影层增加 LoRA**，其他层保持原样。

---

## 四、为什么选 q_proj 和 v_proj？

看 Attention 的计算公式：

```text
Attention(Q,K,V) = softmax(QKᵀ/√d)V
```

拆开理解两个角色的分工：

- **Q（Query）**：决定模型“**关注什么信息**”
- **V（Value）**：决定模型“**传递什么信息**”

所以，调整 Q 和 V，通常就能有效改变模型的行为——这就是它们成为常见起点的原因。

> ⚠️ **重要提醒**：`q_proj`/`v_proj` 只是**常见起点**，不是所有模型通用的“标准配置”。不同模型的模块命名可能不同，**配置前务必先查看模型实际的模块名**（用 `model.named_modules()`），再决定 `target_modules` 写什么。

### 偷懒方案：`"all-linear"`

较新版本的 PEFT 支持一个便捷写法，让 LoRA 自动匹配所有线性层：

```python
from peft import LoraConfig, get_peft_model
from transformers import AutoModelForCausalLM

# 模型许可证：Llama 2 Community License（商用月活>7亿需Meta授权）
model = AutoModelForCausalLM.from_pretrained("your/base-model")

lora_config = LoraConfig(
    r=8,
    lora_alpha=16,
    lora_dropout=0.05,
    bias="none",
    task_type="CAUSAL_LM",
    target_modules="all-linear",   # 匹配所有 nn.Linear 层，包括 lm_head；若需排除请手动指定 target_modules
)

model = get_peft_model(model, lora_config)
model.print_trainable_parameters()   # 打印可训练参数量/占比，确认 LoRA 已注入
```

**用 `"all-linear"` 的权衡**：省去手工枚举模块名的麻烦，但覆盖模块变多会**增加可训练参数与显存**。是否用它，要在**参数量/显存**与**效果**之间权衡，最终以验证集结果为准。如果你的 PEFT 版本较旧不支持该字符串，就退回显式列出模块名的写法。

## LLaMA系列：`target_modules` 怎么配？

你正在学 LoRA 微调，目标是把大模型“轻量改造”成适合你任务的模型。在 `LoraConfig` 里，`target_modules` 决定**哪些层**会被插入低秩矩阵——也就是你要“动刀”的地方。

**LLaMA 系列模型**（比如 LLaMA、Llama 2、Llama 3）最常用的配置是：

```python
target_modules = ["q_proj", "v_proj"]
```

这里 `q_proj` 是查询（Query）投影层，`v_proj` 是值（Value）投影层。只改这两个层，是 LoRA 微调里非常经典的做法——**改动小、显存占用低，同时效果通常不错**。

> **为什么只选 q 和 v？** 简单理解：注意力机制里，Q 决定“看哪里”，V 决定“看到什么”。很多实验表明，只微调这两个投影，就能让模型适应新任务，而不用动全部权重。

---

### 对比：GPT-2 的 `target_modules` 长什么样？

GPT-2 的配置可能完全不同：

---

### ⚠️ 关键坑：`fan_in_fan_out=True`

GPT-2 的注意力层用的是 `Conv1D`（不是常见的 `nn.Linear`）。它的权重形状是 `(in_features, out_features)`——和 `nn.Linear` 的 `(out_features, in_features)` **正好转置**。

```python
fan_in_fan_out=True
```

## 块 24

## 6.1 r是什么？——LoRA的“瘦身”核心

r就是**rank（秩）**，它控制LoRA低秩矩阵的维度。简单说，r决定了你要把原始大矩阵“压缩”到多小的中间维度。

公式：`ΔW = (α/r)BA`

其中α是缩放系数，r是秩。r决定的是A、B矩阵的**中间维度**大小。

**直观例子**：原始矩阵是`4096×4096`，设置`r=8`后：
- A：`8×4096`（维度为r×d_in）
- B：`4096×8`（维度为d_out×r）

这样就把一个巨大的矩阵拆成两个小矩阵

## 7.1 alpha 作用：控制 LoRA 的“影响力”

先记住一个关键公式——LoRA 最终更新时，**不是**直接使用 `BA`，而是使用：

```text
(alpha/r)BA
```

也就是说，`alpha` 控制的是 **LoRA 更新的幅度**——它决定 LoRA 对模型参数的影响有多大。

**动手算一算：**

假如你配置了：

```python

lora_alpha=16
```

那么缩放系数就是：

```text
16/8 = 2
```

这意味着：LoRA 的影响被**增强**了 2 倍。

这段代码的核心是**用LoRA微调一个BERT模型做二分类**。我们一步步看。

**第一步：加载基础模型**

**第二步：配置LoRA（核心）**

```python
lora_config = LoraConfig(
    r=8,
    lora_alpha=16,
    lora_dropout=0.05,
    bias="none",
    task_type="SEQ_CLS",
    target_modules=["query", "value"],
    modules_to_save=["classifier"],

```

这是整个配置的灵魂，我们逐个看：

- `r=8`：这是LoRA的“秩”。简单说，它决定了微调时引入的额外参数矩阵的大小。`r`越小，可训练的参数越少，训练越快，但模型表达能力可能受限；`r`越大，效果可能越好，但显存占用和训练时间也会增加。8是一个常用且平衡的起始值。
- `lora_alpha=16`：这是一个缩放因子，实际缩放比例为`alpha/r`（这里为16/8=2）。它控制LoRA权重在最终模型中的影响程度。初始输出不变是因为B矩阵初始化为0，而非alpha与r的比例关系。
- `lora_dropout=0.05`：Dropout比率，用于防止过拟合。在训练时，会随机“丢弃”一部分LoRA层的输出，让模型更鲁棒。0.05是一个比较小的值，意味着只丢弃5%的节点。
- `bias="none"`：指定是否训练偏置项。这里设为`none`，表示不训练任何偏置，只训练LoRA引入的矩阵和后面要说的`modules_to_save`里的模块。

- `target_modules=["query", "value"]`：**这是最关键的一步**。它指定了我们要在BERT的哪些层上应用LoRA。这里选择的是注意力机制中的`query`（查询）和`value`（值）矩阵。这是LoRA论文中验证过的、效果较好的微调位置。
