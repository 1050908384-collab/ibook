# SKILL名称：knowledge_graph_mapping

## 1. 能力描述
- 功能：按技能标签/板块ID查询**知识图谱节点与先修依赖**，递归推导学习先后顺序。定义"技能间的依赖关系如何映射"：节点匹配、依赖传递性、循环检测、分层提示。为旧框架 Agent1/Agent2 的图谱查询提供规则
- 适用场景（3个）：
  1. **先修依赖查询**：给定技能名，递归查询其全部前置依赖板块，推导学习先后顺序
  2. **依赖链分层**：依赖链超3层时生成分层提示，建议拆分多阶段学习
  3. **循环依赖检测**：检测并截断图谱中的循环依赖，返回部分有效依赖链
- **休眠状态说明**：新框架（v2.0+）已移除知识图谱子系统，`graph_query_tool` 不再被任何 Agent 调用，本SKILL当前未被 `load_skills` 加载。规则保留备查，将来若恢复图谱子系统可直接启用
- 前置依赖：
  - 本地 SQLite 知识图谱数据库（`knowledge_blocks` 表的 `prerequisites` 字段）
  - 标准化技能标签映射表（新框架均未启用）

## 2. 核心方法论
- **步骤1：匹配图谱节点**——接收技能名称/板块ID，在 `knowledge_blocks` 表中匹配唯一节点（按 `block_name` 或 `block_id`）
- **步骤2：递归查询先修依赖**——读取节点 `prerequisites` 字段，对每个前置板块递归查询其先修，提取全部传递依赖
- **步骤3：校验依赖传递性与过滤**——校验依赖传递性，过滤循环依赖与重复板块
- **步骤4：分层提示与输出**——依赖链超3层时生成分层提示（建议拆分多阶段），输出结构化依赖数组

## 3. 知识/规则定义

### 规则1：节点匹配规范
| 检查项 | 要求 | 违规处置 |
|:---|:---|:---|
| 标准板块 | 先修依赖必须是图谱中已存在的标准板块 | 不生成临时节点，缺失则返回空并记录 |
| 唯一匹配 | 按 `block_name` 或 `block_id` 精确匹配 | 多匹配时取 difficulty 最低者 |
| 标签标准化 | 技能名须先经标准化映射表归一 | 未映射则记录缺失标签 |

### 规则2：依赖传递性
| 检查项 | 要求 | 违规处置 |
|:---|:---|:---|
| 传递性 | 若 A 依赖 B，B 依赖 C，则 A 隐含依赖 C | 递归展开全部传递依赖 |
| 去重 | 输出依赖列表自动去重 | 重复板块仅保留一次 |
| 层级标记 | 每个依赖标注所属层级（直接依赖/间接依赖） | 便于后续分层提示 |

### 规则3：循环依赖检测
| 检查项 | 要求 | 违规处置 |
|:---|:---|:---|
| 循环检测 | 递归查询时维护已访问栈 | 检测到回边则判定循环 |
| 循环截断 | 命中循环时截断循环路径 | 返回部分有效依赖并警告 |
| 警告标注 | 循环依赖在输出中标注 `"warning": "circular_dependency"` | 提示人工修正图谱 |

### 规则4：分层提示
| 依赖链深度 | 处置 | 说明 |
|:---|:---|:---|
| 1~3层 | 直接输出依赖列表 | 正常学习路径 |
| >3层 | 生成分层提示，建议拆分多阶段 | 避免单阶段认知超载 |

## 4. 输入输出规范

### 输入
- 技能名称字符串（如 `"LoRA"`）或知识板块唯一ID（如 `"KB-LORA0001"`）

### 输出
先修依赖列表JSON：
```json
{
  "skill": "LoRA",
  "dependencies": [
    {"block_id": "KB-TRANSF01", "block_name": "Transformer", "difficulty": "中级", "estimated_hours": 2.5, "level": 1},
    {"block_id": "KB-ATTN0001", "block_name": "注意力机制", "difficulty": "中级", "estimated_hours": 2.0, "level": 2},
    {"block_id": "KB-DL000001", "block_name": "深度学习", "difficulty": "中级", "estimated_hours": 3.0, "level": 3}
  ],
  "max_depth": 3,
  "warning": null
}
```

**字段说明**：
- `dependencies`：先修依赖列表，每项含 `block_id`、`block_name`、`difficulty`、`estimated_hours`、`level`（层级）
- `max_depth`：依赖链最大深度
- `warning`：循环依赖警告（无循环时为 null）

## 5. 异常处理
| 异常场景 | 处置方式 |
|:---|:---|
| 无匹配节点 | 返回空 dependencies 列表，记录缺失标签 |
| 检测到循环依赖 | 截断循环，返回部分有效依赖，warning 标注 `"circular_dependency"` |
| 数据库读取失败 | 返回空 dependencies 列表，记录错误日志 |
| `prerequisites` 字段为空 | 仅返回该节点自身，dependencies 为空数组 |
| 依赖链超3层 | 正常返回全部依赖，附加分层提示建议拆分 |

## 6. 附录

### 附录A：知识图谱理论参考
| 编号 | 理论名称 | 作者 | 年份 | 核心观点 | 在本SKILL中的应用 |
|:---|:---|:---|:---|:---|:---|
| A-1 | 知识空间理论（Knowledge Space Theory） | Doignon & Falmagne | 1985 | 知识结构建模为状态空间，学习路径是状态间的合法转移序列，先修关系定义合法路径 | 规则1/2依赖关系的理论基础——prerequisites 定义技能间的合法学习顺序 |
| A-2 | 拓扑排序（Topological Sort） | Knuth（《TAOCP》） | 1968 | 对有向无环图（DAG）进行线性排序，使每条边的起点排在终点之前 | 规则2依赖传递性与规则3循环检测的算法依据——DAG才能拓扑排序，有环则报错 |
| A-3 | 认知负荷理论（Cognitive Load Theory） | John Sweller | 1988 | 工作记忆容量7±2，单次学习内容过多导致认知超载 | 规则4分层提示的依据——依赖链超3层建议拆分多阶段，避免单阶段超载 |
| A-4 | 最近发展区理论（ZPD） | Lev Vygotsky | 1978 | 学习内容应处于最近发展区，先修依赖确保不跨越未掌握的前置 | 先修依赖查询的依据——确保学习者先掌握前置再学当前技能 |

### 附录B：完整场景示例

#### 场景1：正常依赖查询（3层链）
**输入**：`"LoRA"`

**处理过程**：
1. 步骤1：匹配节点 LoRA（block_id=KB-LORA0001）
2. 步骤2：读取 prerequisites=["Transformer","注意力机制"]，递归查询：
   - Transformer → prerequisites=["注意力机制"]（level 1）
   - 注意力机制 → prerequisites=["深度学习"]（level 2）
   - 深度学习 → prerequisites=["Python"]（level 3）
3. 步骤3：去重，标注层级
4. 步骤4：max_depth=3，未超3层，直接输出

**输出**：
```json
{
  "skill": "LoRA",
  "dependencies": [
    {"block_id": "KB-TRANSF01", "block_name": "Transformer", "difficulty": "中级", "estimated_hours": 2.5, "level": 1},
    {"block_id": "KB-ATTN0001", "block_name": "注意力机制", "difficulty": "中级", "estimated_hours": 2.0, "level": 2},
    {"block_id": "KB-DL000001", "block_name": "深度学习", "difficulty": "中级", "estimated_hours": 3.0, "level": 3}
  ],
  "max_depth": 3,
  "warning": null
}
```

#### 场景2：循环依赖检测
**输入**：`"技能A"`（假设图谱中 A→B→A 循环）

**处理过程**：
1. 步骤1：匹配节点 A
2. 步骤2：递归查询——A 依赖 B，B 依赖 A（回边，命中已访问栈）
3. 步骤3：检测到循环，截断 A→B→A 的回边，保留 A→B
4. 步骤4：输出部分有效依赖，warning 标注循环

**输出**：
```json
{
  "skill": "技能A",
  "dependencies": [
    {"block_id": "KB-B", "block_name": "技能B", "difficulty": "中级", "estimated_hours": 2.0, "level": 1}
  ],
  "max_depth": 1,
  "warning": "circular_dependency: 技能A ↔ 技能B 形成循环，已截断，建议人工修正图谱"
}
```

**说明**：场景2体现规则3循环检测——递归查询维护已访问栈，命中回边即判定循环，截断后返回部分有效依赖并警告，避免无限递归。
