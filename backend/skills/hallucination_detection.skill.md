# SKILL名称：hallucination_detection

## 1. 能力描述
- 功能：定义冲突裁决规则与证据打包规范，解决多工具审核结果矛盾时的判定逻辑
- 适用场景：Agent④综合多工具审核结果进行最终裁决时
- 前置依赖：各审核工具的输出结果（code_parser、dependency_check、knowledge_verify、standard_answer_check、rule_check）

## 2. 核心方法论
- 步骤1：检查硬性阻断项——若 code_parser_tool 或 dependency_check_tool 报错，直接判定"不通过"
- 步骤2：处理语义冲突——若 knowledge_verify_tool 与 standard_answer_check_tool 结果冲突，以标准答案库为准
- 步骤3：检查规范红线——rule_check_tool 发现的任何违规，直接标记"不通过"
- 步骤4：证据打包——为每条问题附带证据来源，生成完整审核报告

## 3. 知识/规则定义
- 规则1：第一优先级（硬性阻断）——若 code_parser_tool 或 dependency_check_tool 报错，无论事实检查结果如何，主状态判定为"不通过"，但需在报错清单中同时附加已执行的事实检查结果供人工参考
- 规则2：第二优先级（语义冲突）——若硬性检查通过，但 knowledge_verify_tool 与 standard_answer_check_tool 结果冲突，以标准答案库为准，置信度降级为"存疑"
- 规则3：第三优先级（规范红线）——rule_check_tool 发现的任何违规，无论其他检查结果如何，直接标记"不通过"
- 规则4：证据打包规范——每条问题必须附带"证据来源"（知识库ID / 标准答案片段 / AST错误行 / 违规条款编号）

## 4. 输入输出规范
- 输入：各审核工具的输出结果对象（含检查结果、置信度、错误详情）
- 输出：结构化审核报告，包含最终状态（通过/不通过）、错误清单（含级别、描述、证据来源）、置信度评估

## 5. 异常处理
- 所有工具都未返回有效结果 → 判定为"审核失败"，记录日志并通知人工介入
- 证据来源缺失 → 标记为"证据不足"，降低置信度等级

## 6. 附录
- 附录A：参考标准——证据链完整性规范、冲突解决方法论
- 附录B：示例——某代码语法检查通过，但知识库相似度0.55（低于阈值），标准答案库有依据，最终以标准答案为准，置信度降级为"存疑"
