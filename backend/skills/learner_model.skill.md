# SKILL名称：learner_model

## 1. 能力描述
- 功能：定义学习者特征基准库，明确"不同人适合什么"，评估学习内容对特定用户的适配性
- 适用场景：Agent⑤评估内容的难度、风格是否匹配用户画像时
- 前置依赖：用户画像（学习基础、学习风格、专业背景、环境条件）

## 2. 核心方法论
- 步骤1：识别用户类型——区分在校学生、工程师、研究者三类用户基准
- 步骤2：难度适配——根据用户水平映射内容难度基准
- 步骤3：环境容忍度检查——验证用户环境是否满足学习要求
- 步骤4：风格匹配——对照learning_style与内容风格的匹配映射表

## 3. 知识/规则定义
- 规则1：三类用户基准——在校学生：偏好结构化、循序渐进的讲解，对新概念接受速度中等；工程师：偏好案例驱动、直接可运行的代码，对原理讲解容忍度低；研究者：偏好公式推导和论文溯源，对实操细节容忍度低
- 规则2：难度适配映射——画像中"初级"对应内容概念密度≤3个/千字，"中级"对应4~7个/千字，"高级"对应≥8个/千字
- 规则3：环境容忍度规则——无Docker经验的用户，必须提供容器化替代方案（如conda环境）；GPU资源不足的用户，必须提供CPU运行方案或降低显存要求
- 规则4：风格适配规则——learning_style为"理论讲解"时内容应侧重原理分析，"动手操作"时应侧重代码实操，"学术型"时应侧重论文溯源，"直白型"时应侧重简洁实用

## 4. 输入输出规范
- 输入：用户画像（grade、professional_background、learning_style、docker_experience、gpu_resource等）、学习内容特征
- 输出：适应性评估结果，包含用户类型判定、难度匹配度、环境可行性、风格匹配度、改进建议

## 5. 异常处理
- 用户类型无法判定（画像信息不足）→ 默认按"在校学生"基准评估，标记为"信息不足"
- 环境条件严重不满足（如需要GPU但用户无GPU资源）→ 标记为环境不可行，直接不通过
- 风格完全不匹配 → 标记为严重问题，建议重新调整内容风格
