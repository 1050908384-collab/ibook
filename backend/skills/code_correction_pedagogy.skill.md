# SKILL名称：code_correction_pedagogy

## 1. 能力描述
- 功能：为个性化学习资源生成 Agent（ContentGeneratorAgent）提供**代码纠错教学法**——定义"如何向用户解释代码错误并指导修改"。当用户输入代码问题时，个性化学习资源生成 Agent依据本SKILL的策略，先通过 code_executor_tool 获取真实执行反馈，再结合知识库进行分析，最后以结构化方式输出纠错结果。
- 适用场景（2个）：
  1. **代码报错纠错**：用户提供问题代码+报错信息，个性化学习资源生成 Agent分析错误原因并给出修改方案
  2. **代码优化建议**：用户提供代码但无报错，个性化学习资源生成 Agent执行代码验证后给出优化建议
- 前置依赖：
  - code_executor_tool（获取代码真实执行反馈）
  - 当前阶段 StageInfo（判断问题与当前阶段相关性）
  - code_style.skill.md（代码规范参考）

## 2. 核心方法论
- **步骤1：执行验证**——先调用 code_executor_tool 执行用户代码，获取真实报错信息或运行输出，严禁凭空猜测
- **步骤2：错误定位**——根据执行结果，定位错误类型（语法错误/运行时错误/逻辑错误）和具体位置
- **步骤3：肯定尝试**——先肯定用户的代码尝试和正确部分，建立积极学习氛围
- **步骤4：分析问题**——分点解释错误原因，结合当前阶段知识点
- **步骤5：分步修改**——给出清晰的修改步骤，每步说明修改原因
- **步骤6：完整代码**——提供修改后的完整可运行代码
- **步骤7：修改说明**——总结修改要点和注意事项

## 3. 知识/规则定义

### 规则1：解释风格规范
| 检查项 | 要求 | 违规处置 |
|:---|:---|:---|
| 先肯定后指出 | 先肯定用户的尝试和正确部分，再指出问题 | 标记 `no_positive_feedback` |
| 友好语气 | 使用鼓励性语言，避免批评性措辞 | 标记 `harsh_tone` |
| 结合当前阶段 | 错误分析应联系当前学习阶段的知识点 | 标记 `not_stage_relevant` |
| 不凭空猜测 | 必须先执行代码获取真实反馈，再分析原因 | 标记 `guess_without_execution` |

### 规则2：输出结构硬性规定
**回答必须包含以下四个板块，缺一不可：**

| 板块 | 要求 | 缺失处置 |
|:---|:---|:---|
| **错误分析** | 定位错误类型、具体位置和根本原因 | 标记 `missing_error_analysis` |
| **修改步骤** | 分步骤说明修改方案，每步说明原因 | 标记 `missing_fix_steps` |
| **修改后完整代码** | 提供完整可运行的修改后代码 | 标记 `missing_fixed_code` |
| **修改说明** | 总结修改要点、注意事项和学习建议 | 标记 `missing_explanation` |

### 规则3：错误类型识别
| 错误类型 | 特征 | 处理策略 |
|:---|:---|:---|
| 语法错误 | SyntaxError，代码无法解析 | 指出具体行号和语法问题，给出正确语法 |
| 运行时错误 | ValueError/TypeError等，代码能解析但运行出错 | 解释异常原因，提供修复方案 |
| 逻辑错误 | 代码运行无报错但结果不符合预期 | 通过执行输出分析逻辑问题，给出优化建议 |
| 性能问题 | 代码运行慢或内存占用高 | 分析性能瓶颈，提供优化方案 |

## 4. 输入输出规范

### 输入
`CodeCorrectionInput` 对象：
- `session_id`
- `code`: str（用户提供的问题代码）
- `error`: str（用户提供的报错信息，可选）
- `stage`: StageInfo（当前阶段信息）

### 输出
`CodeCorrectionOutput` 对象：
```json
{
  "correction": {
    "error_analysis": "错误分析内容...",
    "fix_steps": [
      "步骤1：修改XXX",
      "步骤2：调整XXX"
    ],
    "fixed_code": "# 修改后的完整代码\n...",
    "explanation": "修改说明和学习建议..."
  },
  "execution_result": {
    "output": "",
    "error": "原始报错信息",
    "return_code": 1,
    "timeout": false
  }
}
```

**字段说明**：
- `correction`: 结构化纠错内容，包含四个板块
- `execution_result`: 代码执行结果（用于验证修改效果）

## 5. 异常处理
| 异常场景 | 处置方式 |
|:---|:---|
| code_executor_tool 执行失败 | 回退使用用户提供的报错信息进行分析，并提示"代码执行环境异常，分析基于您提供的报错信息" |
| 用户仅提供问题无代码 | 提示用户提供相关代码片段，或提供通用解决方案 |
| 代码无报错但结果异常 | 在"错误分析"中说明逻辑问题，提供优化建议 |
| 修改后的代码仍报错 | 在"修改说明"中标注，并提供进一步调试建议 |

### 附录B：完整场景示例

#### 场景1：代码报错纠错
**输入**：
```json
{
  "code": "def add(a, b)\n    return a + b\n\nprint(add(1, 2))",
  "error": "SyntaxError: invalid syntax",
  "stage": {"block_name": "Python基础"}
}
```

**处理过程**：
1. 步骤1：调用 code_executor_tool 执行代码，获取真实报错
2. 步骤2：定位错误——第1行缺少冒号 `:`
3. 步骤3：肯定用户尝试定义函数的思路正确
4. 步骤4：分析问题——Python函数定义需要冒号结尾
5. 步骤5：分步修改——在函数定义行末尾添加冒号
6. 步骤6：提供修改后完整代码
7. 步骤7：总结修改要点

**输出**：
```json
{
  "correction": {
    "error_analysis": "语法错误：第1行 `def add(a, b)` 缺少冒号 `:`。Python函数定义语法要求函数头以冒号结尾，用于标识函数体开始。",
    "fix_steps": [
      "步骤1：在 `def add(a, b)` 后面添加冒号 `:`",
      "步骤2：确保函数体正确缩进（4个空格）"
    ],
    "fixed_code": "def add(a, b):\n    return a + b\n\nprint(add(1, 2))",
    "explanation": "本次修改学习要点：\n1. Python函数定义必须以冒号结尾\n2. 函数体需要正确缩进\n3. 这是Python基础语法，后续所有函数定义都要遵守此规则"
  },
  "execution_result": {
    "output": "3",
    "error": "",
    "return_code": 0,
    "timeout": false
  }
}
```
