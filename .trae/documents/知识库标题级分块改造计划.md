# 知识库标题级分块改造计划

## Context（为什么做这件事）

当前 Agent3-Agent4 学习包辩论的瓶颈在数据层：
1. **分块质量差**：`import_local_learning_materials.py` 的 `_chunk_markdown` 纯按 1500 字符切分，不考虑标题语义，导致块跨章节、代码被截断。
2. **修改效率低**：Agent3 把整篇全部块一次性给 Agent4，Agent4 返回问题后 Agent3 又把全部内容重发——非并行、非定点。
3. **文章标题不统一**：73 篇中 8 篇缺 H1、11 篇多 H1、6 篇无 H3、9 篇用 H4，无法按标题分块。

**关键发现**：Agent3/Agent4 的块级并行管道代码**已完整存在**（`deterministic.py` L1861-L3091），已在读取 `heading_path`、`heading_level`、`source_line_start`、`source_line_end` 等字段；`vector_search_tool.py` 和 `knowledge_verify_tool.py` 已有防御式 SELECT（自动检测新列是否存在）。**消费侧全部就绪，只差数据层**。

本次改造的目标：让 knowledge_chunks 表中的块按标题层级切分，并填充新字段，使已有的块级管道真正运转起来。

## 任务拆分

### 任务 1：新增数据库字段（`backend/db/sqlite_client.py`）

在 `_migrate_tables()` 中用 `_ensure_column` 添加 6 个新列（idempotent，已有则跳过）：

**knowledge_chunks 表（5 列）**：
- `heading_path TEXT NOT NULL DEFAULT ''`
- `heading_level INTEGER NOT NULL DEFAULT 0`
- `source_line_start INTEGER NOT NULL DEFAULT 0`
- `source_line_end INTEGER NOT NULL DEFAULT 0`
- `chunk_strategy TEXT NOT NULL DEFAULT ''`

**knowledge_docs 表（1 列）**：
- `source_file_path TEXT NOT NULL DEFAULT ''`

同时在 `CREATE TABLE IF NOT EXISTS knowledge_chunks` 和 `knowledge_docs` 建表语句中补上这些列（新库首次建表时生效）。

> 注意：`_ensure_column` 不支持 `NOT NULL` 约束（ALTER TABLE ADD COLUMN 对已有行需要 DEFAULT），所以用 `DEFAULT ''`/`DEFAULT 0` 保证旧行有值。

### 任务 2：统一 73 篇文章标题层级

编写一次性脚本 `scripts/normalize_markdown_headings.py`，自动检测并修复：

| 问题 | 修复方式 |
|------|---------|
| 缺少 H1 | 从目录名/种子文件取子知识点名，在文件开头补 `# {subtopic_name}` |
| 多个 H1 | 保留第一个 H1；后续每个 H1 降为 H2，其下子标题层级同步 +1（H2→H3, H3→H4），H4 封顶不升 H5 |
| H5/H6 | 降为 H4，输出 warning |
| 标题跳级（H1→H3 无 H2） | 输出 warning，不自动修复（需人工判断） |

脚本规则：
- 严格忽略 fenced code block（``` 包裹）内的 `#`
- 不识别引用行 `>`、列表项 `-`/`*` 中的 `#` 为标题
- 不删除/修改任何正文、代码、表格、链接
- 输出修复报告：每篇文章改了什么（缺 H1 补了 / 多 H1 降了几个 / H5 降了几个 / 是否有跳级 warning）
- 脚本可安全重复运行（已修复的文件再跑不会变）

运行后用审计报告的逻辑重新扫描，确认 73 篇均有且仅有一个 H1、无 H5/H6。

### 任务 3：重写导入脚本分块逻辑（`scripts/import_local_learning_materials.py`）

**替换 `_chunk_markdown`** 为 `_chunk_by_headings`，算法：

```
1. 逐行解析，跟踪 code block 状态（``` 切换）
2. 识别 ATX 标题（# 到 ######，仅 code block 外），记录行号和级别
3. 构建标题路径栈：heading_path = "H1标题 > H2标题 > H3标题"
4. 确定块边界：
   - 文章有 H3 → 每个 H3 及其内容到下一个同级/更高级标题 = 候选块（chunk_strategy=heading_h3）
   - 文章无 H3 → 每个 H2 及其内容 = 候选块（chunk_strategy=heading_h2_fallback）
5. 后处理：
   - 候选块 < 300 字符 → 与下一个同父级候选块合并
   - 候选块 > 1800 字符 → 优先按 H4 拆分（chunk_strategy=heading_h4_split）；仍超长再按段落拆分（chunk_strategy=paragraph_overflow）
   - 代码围栏不可被截断
6. 每个最终块记录：
   - heading_path, heading_level, source_line_start, source_line_end, chunk_strategy
   - chunk_index 按 source_line_start 递增
```

**修改 INSERT 语句**：
- `knowledge_chunks` INSERT 增加 `heading_path, heading_level, source_line_start, source_line_end, chunk_strategy`
- `knowledge_docs` INSERT 增加 `source_file_path`（值为文章相对项目根的路径）

**保留现有行为**：
- `DELETE FROM knowledge_chunks WHERE doc_id = ?`（重新导入时清旧块）
- `ON CONFLICT(doc_id) DO UPDATE`（knowledge_docs upsert）
- doc_id 仍为 `LOCAL-{subtopic_id}`，chunk_id 仍为 `{doc_id}-C{index:03d}`

### 任务 4：重新导入并验证

python scripts/normalize_markdown_headings.py

# 2. 运行导入

```
