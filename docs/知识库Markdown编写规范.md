# 知识库 Markdown 编写规范

## 目标

本规范适用于 `data/知识库原始数据` 内参与学习资料导入的 73 篇文章。目标是让文章标题既能表达教学结构，也能成为稳定、可追溯的检索分块边界。

这里的“块”首先指原始学习资料块，即 `knowledge_chunks`。它不是 个性化学习资源生成 Agent 生成的个性化内容块：个性化学习资源生成 Agent 读取原始块后，结合用户画像重新组织和解释，再产生供 专业知识与教学质量审核 Agent 审核的个性化内容块；个性化内容必须保留原始 `source_chunk_id`。

当前 73 篇文章并未完全统一：54 篇已有一个 H1，8 篇缺少 H1，11 篇存在多个 H1，6 篇没有 H3，9 篇使用了 H4。导入新分块前必须先完成标题层级归一化。

## 标题层级

| 层级 | 唯一性/数量 | 编辑语义 | 入库作用 |
| --- | --- | --- | --- |
| `#` | 每篇且仅一条 | 文档标题，应与子知识点主题一致 | 文档级元数据，不单独成为知识块 |
| `##` | 一条或多条 | 能独立学习的大章节，如“原理”“配置步骤”“常见问题” | H3 缺失时的块边界；也是 H3 块的父上下文 |
| `###` | 按需要使用 | 单一概念、公式推导、操作步骤或可验证结论 | 常规首选知识块边界 |
| `####` | 仅在必要时使用 | H3 内不可独立检索的细节、参数解释或子步骤 | 仅用于拆分过大 H3 块 |

禁止使用 `#####`、`######`。标题不得跳级，例如 `#` 后直接使用 `###`；没有 H3 的短文允许停在 H2。

## 标题归一化规则

1. 缺少 H1 的文章，补充一个与子知识点名称一致的 H1。
2. 多个 H1 的文章，只保留文档标题为 H1；其余原“大章”统一降为 H2，其下标题按相对层级同步下调。
3. 不允许通过删除正文来消除层级问题；标题调整必须保持原文顺序、代码、表格和链接不变。
4. 没有 H3 的文章不强行制造空洞标题：如果 H2 已经是独立学习单元，使用 H2 作为块；如果 H2 内包含多个独立问题，再补充语义明确的 H3。
5. H4 只用于拆分过大的 H3。H4 不应成为默认块级别。
6. 标题编号可以保留原文编号，但编号不能替代标题层级；块身份使用 `heading_path` 和 `chunk_index`，不依赖标题中的数字。

## 编辑规则

1. 一个 Markdown 文件对应一个子知识点，因此首个且唯一的 `#` 必须是该文章标题。
2. 原文中作为“大章”的多个 `#` 必须降为 `##`；原有下属标题按相对层级相应下调。
3. 不要为“参考资料”“适合人群”“前置说明”“小结”等固定前后置内容创建 H3。它们应置于标题下或归入最近的 H2，避免被检索成孤立知识块。
4. `###` 标题必须说明该块要解决的具体问题，不应使用“补充”“说明”“示例”等无语义标题。推荐“`### 2.1 低秩矩阵如何减少可训练参数`”。
5. 代码示例必须位于解释它的 H3 或 H4 下；代码围栏中的 `#` 是代码注释，不是 Markdown 标题。

## 导入分块规则

导入器应采用以下规则，而不是纯字符累计切分：

1. 先按 Markdown 标题解析，并为每个块保留完整标题路径，例如“`LoRA 原理 > 低秩分解 > rank 对可训练参数量的影响`”。
2. 有 H3 的文章：每个 H3 及其内容形成候选块；H2 标题不重复作为正文大块，但写入标题路径和检索文本前缀。
3. 无 H3 的文章：每个 H2 及其内容形成候选块。
4. 候选块少于 300 字符时，与紧随的同父级候选块合并；首尾的引言、参考资料等小段并入相邻主体块，而不是单独入库。
5. 候选块在 300 至 1,800 字符之间时，原样入库。
6. 候选块超过 1,800 字符时，优先按 H4 拆分；若仍超长，再按段落拆分。代码围栏不可被截断。拆分子块必须保留同一完整标题路径并增加“第 N 部分”标记。

字符数是性能与上下文控制的兜底约束，不是首要边界。对表格、公式、代码和列表，应以完整语义单元为先。

7. 标题解析必须忽略 fenced code block 内的 `#`，也不能把引用行、列表项中的 `#` 识别为标题。
8. 块应尽量保持一个完整的教学问题、概念、公式推导或操作任务。不得为了达到字符数，把定义和解释、命令和输出、代码和代码说明拆开。
9. 导入器应记录块的原始文本；不得在 `knowledge_chunks` 中直接写入 个性化学习资源生成 Agent 的个性化改写内容。个性化内容应在学习包运行时单独保存，并通过 `source_chunk_id` 回溯原始块。

## 入库元数据

每个 `knowledge_chunks` 记录应至少保存：

- `heading_path`：从 H1 到块标题的完整路径；
- `heading_level`：实际作为块边界的标题级别；
- `source_line_start`、`source_line_end`：在 Markdown 源文件中的行范围；
- `chunk_strategy`：如 `heading_h3`、`heading_h2_fallback`、`heading_h4_split`、`paragraph_overflow`；
- 现有的 `doc_id`、`block_id`、`subtopic_id` 和 `chunk_index`。

如果发生段落兜底拆分，还应保存 `parent_chunk_id` 和 `part_index`。如果块被 个性化学习资源生成 Agent 用于个性化生成，运行时消息还应携带 `source_chunk_id`、`content_version` 和 `revision_note`；这些字段属于学习包协作协议，不应覆盖原始知识库内容。

这使 个性化学习资源生成 Agent 生成学习包和 专业知识与教学质量审核 Agent 审核结论都能引用到准确文章小节，而不是只引用一个无上下文的字符块。

## 验收标准

1. 73 篇文章均有且仅有一个 H1，且没有标题跳级和 H5/H6。
2. 每篇文章至少有一个 H2；需要细分的文章具有语义明确的 H3。
3. 导入后不存在少于 300 字符的孤立正文块，也不存在未按 H4/段落兜底处理的超过 1,800 字符块。
4. 任意检索结果均能显示完整标题路径和源文件行范围。
5. 对 个性化学习资源生成 Agent-专业知识与教学质量审核 Agent 的学习包辩论做回归测试，确认引用块可定位、生成内容与源资料不发生跨章节混杂。

## 实施前检查清单

- 先完成 73 篇文章的标题归一化，再重新运行导入脚本。
- 导入器改为标题优先分块，并输出标题路径、行号和分块策略。
- 抽样检查每个知识板块至少一篇文章，确认代码、表格、公式和列表没有被截断。
- 重新生成向量索引，确保 Chroma/SQLite 使用的是新块数据。
- 用 `source_chunk_id` 做 个性化学习资源生成 Agent 个性化内容到原始资料的可追溯回归测试。
