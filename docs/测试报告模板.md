#### 2.1.1-A 学情诊断与阶段规划 Agent 映射与召回回归

这些用例验证当前实际运行的 `HybridDiagnosticAgent` / `DeterministicDiagnosticAgent`，不验证已停用的旧 `agent_01_diagnostic.py`。每条用例应记录 `block_id`、`mapping_confidence`、首个直接先修和首阶段 `subtopic_id`。

| 用例ID | 测试场景 | 输入要点 | 预期输出 |
|--------|----------|----------|----------|
| A1-001 | 结构化 LoRA 目标 | 已有 PyTorch，目标 LoRA/QLoRA 微调 | 目标映射 `KB-12`，不把已掌握技能重复列为盲区 |
| A1-002 | 中文模糊低显存表达 | 想让模型更小、占用显存更少 | 首选 `KB-12`，必要时同时保留 `KB-15`，不得落到 `KB-09` |
| A1-003 | 生产部署表达 | 想把大模型部署到生产环境 | 目标映射 `KB-15`，阶段选路使用该板块的可学习子知识点 |
| A1-004 | 多卡训练表达 | 想做多卡/分布式训练加速 | 目标映射 `KB-14` |
| A1-005 | 规范技术术语 | QLoRA 4bit 量化微调 | 目标映射 `KB-12`，召回结果包含真实子知识点 ID |
| A1-006 | 直接先修插入 | 零基础学习 LoRA，缺少其直接板块前置 | 目标 gap 保留，未掌握直接前置另插入为 `mapping_confidence=0.85` 的前置 gap |
| A1-007 | 子知识点直接先修 | 目标子知识点依赖另一子知识点 | 首阶段优先未掌握直接先修，不按错误的传递闭包扩展 |
| A1-008 | 领域歧义 | “我想学 LoRa 无线通信” | 不强行选择 `KB-12`，置信度低于追问阈值并询问无线 LoRa 与大模型 LoRA 的区别 |
| A1-009 | 目录外目标 | 目标与 15 个知识板块均无可靠匹配 | 返回低置信度追问，不编造 `block_id`，不生成阶段 |
| A1-010 | 学情评估与动态决策 Agent 透明性 | 完成阶段后更新画像 | `status/progress/skill/prerequisites` 可更新；`block_id`、`block_name`、`target_subtopic_ids`、`mapping_confidence` 保持不变 |

学情诊断与阶段规划 Agent 索引回归命令：

```bash
python scripts/evaluate_agent1_retrieval.py
```

首次执行索引前需由开发/部署者运行 `python scripts/init_agent1_semantic_index.py`；普通用户发行包不应要求下载模型或运行初始化。
