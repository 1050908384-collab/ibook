# AI Agent Trainer 部署说明

## 一、环境要求

### 1.1 硬件要求

| 组件 | 最低配置 | 推荐配置 |
|------|----------|----------|
| CPU | 4核 | 8核+ |
| 内存 | 8GB | 16GB+（包含 Agent1 轻量语义模型运行余量） |
| GPU | 无 | NVIDIA GPU (8GB显存+) |
| 存储 | 5GB | 20GB+ |

### 1.2 软件要求

| 软件 | 版本 | 说明 |
|------|------|------|
| Python | 3.12+ | 后端运行环境 |
| Node.js | 18+ | 前端运行环境 |
| Ollama | 最新版 | 本地 LLM 部署，并为 Agent3 的 Chroma 语义检索提供 embedding 服务；Agent1 embedding 不依赖它 |
| FastEmbed | 由 `requirements.txt` 安装 | Agent1 轻量中文语义召回，CPU 运行 |

## 二、后端部署

### 2.1 安装依赖

```bash
pip install -r requirements.txt
```

### 2.2 配置环境变量

```bash
cp .env.example .env
```

编辑 `.env` 文件：

```env
# 应用配置
APP_NAME=AI Agent Trainer
APP_HOST=0.0.0.0
APP_PORT=8000

# Ollama 配置（本地模型）
OLLMA_BASE_URL=http://localhost:11434
OLLMA_MODEL=deepseek-r1:7b
EMBEDDING_MODEL=qwen3-embedding:0.6b

# DeepSeek配置（云端模型，可选）
DEEPSEEK_API_KEY=your-api-key
DEEPSEEK_API_BASE=https://api.deepseek.com

# 数据库配置
DATABASE_URL=sqlite:///../data/sqlite_data/project.db
CHROMA_PATH=../data/chroma_db
GRAPH_PATH=../data/graph_data/runtime/knowledge_graph.gpickle

# 审核配置
MAX_REVIEW_ITERATIONS=3
CONFIDENCE_THRESHOLD=0.7
```

### 2.3 初始化数据

```bash
# 初始化主库
python scripts/init_db.py

# 重建 Agent3 的 Chroma 语义索引（先确保已下载 EMBEDDING_MODEL）
python scripts/init_knowledge_base.py

# 导入其余知识库与测试数据
python scripts/init_agent1_semantic_index.py
python scripts/build_knowledge_graph.py
python scripts/seed_test_data.py
python scripts/evaluate_agent1_retrieval.py
```

### 2.4 Agent1 轻量语义索引与发行包

`init_agent1_semantic_index.py` 首次执行会下载 FastEmbed 的 `BAAI/bge-small-zh-v1.5`（模型文件约 90MB，CPU 运行时通常额外占用约 200MB 内存），以 CPU 方式建立 `agent1_knowledge_docs` collection。首次下载一般是几十秒级，具体取决于网络。该 collection 专供 Agent1 召回知识板块与子知识点。

- 源码开发或部署机器：执行一次初始化与评测脚本；模型缓存写入 `data/fastembed_models/`，索引写入 `data/chroma_db/`
- 普通最终用户：发行包必须预置上述缓存与索引；不需要下载模型、不需要运行初始化脚本，也不需要为 embedding 启动 Ollama
- 更新 `data/seeds/knowledge_docs.json`、`knowledge_blocks.json` 或 `knowledge_subtopics.json` 后：在部署侧重新运行索引初始化和评测

Agent1 在运行时不会隐式下载模型。索引或模型缓存缺失时，系统保留别名精确匹配与低置信度追问，不应把缺失索引当作普通用户的安装步骤。

### 2.5 启动服务

```bash
# 开发模式
python main.py

# 生产模式（使用uvicorn）
uvicorn main:app --host 0.0.0.0 --port 8000
```

### 2.5 验证服务

```bash
curl http://localhost:8000/health
```

预期响应：
```json
{"status": "healthy"}
```

## 三、Ollama 部署

### 3.1 安装 Ollama

参考官方文档：https://ollama.com/download

### 3.2 下载模型

```bash
# 推荐模型（7B版本）
ollama pull deepseek-r1:7b

# 轻量模型（1.5B版本，适合低配置）
ollama pull deepseek-r1:1.5b

# 备选模型
ollama pull qwen2.5:7b

# Agent3 的 Chroma 中文语义检索模型（必需）
ollama pull qwen3-embedding:0.6b
```

`qwen3-embedding:0.6b` 用于将知识片段和技术问题编码为向量，不负责生成对话回答。
Agent3 在技术类问答中使用它检索当前阶段的相关资料；日常问候、闲聊和情绪表达不触发该检索。该模型当前约 639 MB，首次下载后由 Ollama 本地缓存。

下载完成后可检查模型是否已注册：

```bash
ollama list
```

如果修改了 `EMBEDDING_MODEL`，或更新了 `knowledge_chunks` 数据，必须重新执行：

```bash
python scripts/init_knowledge_base.py
```

该脚本会重建 `knowledge_base` collection；运行前会校验 embedding 模型连通性，完成后校验写入数量。

### 3.3 启动 Ollama 服务

```bash
ollama serve
```

验证：
```bash
curl http://localhost:11434/api/tags
```

## 五、Docker部署（可选）

### 5.1 创建Dockerfile

```dockerfile
FROM python:3.12-slim

WORKDIR /app

COPY backend/requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY backend/ .

EXPOSE 8000

CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]
```

### 5.2 构建镜像

```bash
docker build -t ai-agent-trainer .
```

### 5.3 运行容器

```bash
docker run -p 8000:8000 -v $(pwd)/data:/app/data ai-agent-trainer
```

## 七、常见问题

### 7.1 Ollama 连接失败

确保 Ollama 服务已启动：
```bash
ollama serve
```

检查端口：
```bash
netstat -ano | findstr 11434
```

### 7.2 模型下载慢

可以配置代理：
```bash
export HTTP_PROXY=http://proxy:port
export HTTPS_PROXY=http://proxy:port
ollama pull deepseek-r1:7b
```

### 7.3 内存不足

使用更小的模型：
```bash
ollama pull deepseek-r1:1.5b
```

### 7.4 前端无法连接后端

检查CORS配置，确保后端 `main.py` 中的CORS配置正确：

```python
app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```

### 7.5 Agent1 语义索引不可用

开发或部署环境可执行：

```bash
python scripts/init_agent1_semantic_index.py
python scripts/evaluate_agent1_retrieval.py
```

最终用户环境不应要求执行这两个命令；应检查发行包是否遗漏 `data/fastembed_models/` 或已初始化的 `data/chroma_db/`。

## Repo Clone Notes

For teammates who clone this repository:

1. Copy `backend/.env.example` to `backend/.env`
2. Set `LLM_PROVIDER=deepseek`
3. Fill in `DEEPSEEK_API_KEY` with a valid personal DeepSeek API key
4. Keep `DEEPSEEK_API_BASE=https://api.deepseek.com`
5. Keep `DEEPSEEK_MODEL=deepseek-v4-flash`
6. Restart the backend after changing `backend/.env`

Notes:

- The backend reads `backend/.env`, not `backend/config.py`
- Do not commit `backend/.env`
- Do not put a real API key into `.env.example`
