# AI Agent Trainer 前端页面梳理

## 1. 产品主流程

本项目不是传统“一次生成完整课程表”的学习平台，而是一个多 Agent 协同的阶段式 AI 实训导师。前端要围绕一个闭环设计：

用户输入背景与目标 → 生成用户画像 → 生成当前子知识点阶段 → 点击开始学习 → 展示学习包 → 学习中随时答疑 → 做题测试 → 阶段决策 → 更新画像与下一阶段 → 循环直到结业。

核心原则：

- 页面要始终让用户知道“我现在在哪一步、下一步该做什么”。
- 每次只突出当前阶段，不提前展开所有未来课程。
- 画像、当前阶段、学习材料、测试结果、下一阶段之间要保持连贯。
- Agent 审核不是后台黑盒，前端应以轻量状态展示“技术审核/质量评审/迭代次数”。

## 2. 推荐页面结构

现有前端已有 3 个路由：

- `/`：学习对话
- `/dashboard`：学习仪表盘
- `/settings`：设置

建议扩展成 6 个用户可理解的页面/视图：

- `/` 学习对话与诊断页
- `/stage` 当前阶段学习页
- `/stage/test` 阶段测试页，也可做成右侧抽屉或弹窗
- `/stage/result` 阶段结果与下一阶段页
- `/dashboard` 学习仪表盘
- `/settings` 设置页

如果比赛时间紧，可以保留 3 个主路由，把“阶段学习、测试、结果”作为 `/` 内部的 tabs 或状态视图实现。

## 3. 全局应用框架

### 页面定位

所有页面共享的外壳：左侧导航、品牌区、当前会话状态、Agent 流程提示。

### 展示内容

- 品牌名称：AI Agent Trainer
- 副标题：个性化学习工作台
- 当前会话状态：未开始 / 诊断中 / 学习中 / 测试中 / 已完成 / 已放弃
- 当前阶段摘要：阶段编号、当前子知识点、阶段状态
- Agent 协同流程：Agent1 学情诊断与阶段选路（逻辑 Agent2）、Agent3 内容生成、Agent4 技术与教学质量审核、Agent6 阶段决策

### 导航按钮

- 学习对话：进入诊断、答疑和当前学习主流程
- 学习仪表盘：查看画像、进度、掌握度和阶段记录
- 设置：调整学习偏好和模型配置

### 全局操作按钮

- 新建学习目标：清空当前本地 session，创建新 session
- 继续上次学习：读取 localStorage 中的 session_id，并拉取当前 session 状态
- 结束当前学习：调用 `PUT /api/session/{session_id}/end`
- 放弃当前学习：调用 `PUT /api/session/{session_id}/abandon`

### 状态提示

- 无 session：提示用户输入学习背景、目标、时长、偏好
- session 失效或 404：提示“当前学习记录不可用”，提供“新建学习目标”
- 后端生成中：显示当前 Agent 阶段，如“正在生成画像”“正在审核学习包”

## 4. 学习对话与诊断页

### 页面定位

这是用户第一次进入产品的起点，也是学习过程中的实时答疑入口。现有 `ChatPage.tsx` 已承担这部分，但需要让“诊断”和“答疑”状态更清楚。

### 页面区域

- 左侧主区域：对话消息流
- 底部：输入框
- 右侧信息栏：用户画像、当前阶段卡片、主操作按钮

### 初始状态功能

用户还没有 session 或没有画像时：

- 显示引导输入，但不要做营销式落地页
- 输入框 placeholder：描述你的学习基础、目标、每天时长和学习偏好
- 支持用户直接输入完整信息
- 支持系统追问补充信息

### 对话消息功能

- 展示用户消息
- 展示系统回复
- 支持 Markdown 文本
- 系统回复下展示审核状态：
  - 技术审核通过
  - 质量评审通过
  - 审核迭代次数
- 出错时显示错误消息，而不是只在控制台打印

### 右侧信息栏功能

未生成画像前：

- 信息填写检查项：
  - 学习基础
  - 学习目标
  - 每日学习时长
  - 学习风格
- 示例输入按钮：
  - 使用示例：微调方向
  - 使用示例：推理部署方向

画像生成后：

- 用户画像卡片：
  - 技能标签
  - 知识盲区
  - 学习目标
  - 每日学习时长
  - 学习风格
  - 画像置信度
- 当前阶段卡片：
  - 阶段编号
  - 当前子知识点
  - 所属知识板块
  - 预计学习时长
  - 前置要求
  - 阶段状态

### 主要按钮

- 发送：调用 `POST /api/chat/` 或 `POST /api/chat/question`
- 开始学习阶段 N：调用 `POST /api/stage/start`
- 查看学习材料：跳转 `/stage`，或切换到材料视图
- 查看测试题：学习包生成后可用，进入 `/stage/test`
- 重新诊断：保留 session，重新发送新的背景描述
- 新建学习目标：清空本地 session 并创建新 session

### 按钮启用规则

- 没有输入内容时，“发送”禁用
- 正在请求后端时，“发送”和“开始学习阶段”禁用
- 没有画像时，“开始学习阶段”禁用
- 没有学习包时，“查看测试题”禁用

### 对接接口

- `POST /api/chat/`：首次输入，返回 `profile` 与 `stage_info`
- `POST /api/chat/question`：学习中提问，返回回答与审核状态
- `GET /api/session/{session_id}`：刷新当前会话状态

## 5. 当前阶段学习页

### 页面定位

这是用户真正学习的主工作台。用户点击“开始学习阶段 N”后进入，集中展示当前阶段的教程、代码、答疑和测试入口。

### 页面区域

- 顶部阶段栏：阶段主题、状态、预计时长、策略
- 中间材料区：教程 Markdown、代码示例、关键知识点
- 右侧学习助手：阶段内提问、审核状态、相关 FAQ
- 底部或右上角：进入测试、完成阶段操作

### 顶部阶段栏内容

- 阶段 N
- 当前子知识点名称
- 所属知识板块
- 预计学习时长
- 前置要求
- 审核状态：已通过 / 未通过 / 审核中
- 生成迭代次数

### 学习材料功能

- Markdown 教程渲染
- 代码示例列表
- 代码复制
- 代码语言标识
- 测试题数量提示
- 学习进度条：
  - 未开始
  - 阅读中
  - 已打开测试
  - 已完成测试

### 阶段内答疑功能

- 输入当前阶段相关问题
- 展示 Agent3 回答
- 展示 FAQ 命中或 LLM 回答来源状态
- 展示技术审核、质量评审状态
- 问答历史保留在当前阶段下

### 主要按钮

- 复制代码：复制单个代码块
- 提问：调用 `POST /api/chat/question`
- 打开测试题：进入 `/stage/test`
- 标记已读：本地记录阅读状态，用于启用测试或提示
- 返回对话：回到 `/`
- 刷新阶段状态：调用 `GET /api/session/{session_id}`

### 按钮启用规则

- 学习包未生成时，只显示“返回诊断页”和“开始学习阶段”
- 学习包审核未通过时，材料区显示审核问题，不建议开放测试
- 没有测试题时，“打开测试题”禁用

### 对接接口

- `POST /api/stage/start`：生成学习包
- `POST /api/chat/question`：阶段内答疑
- `GET /api/session/{session_id}`：获取当前学习包和阶段状态

### 可复用现有组件

- `ResourceViewer.tsx`：教程与代码展示
- `TestQuestion.tsx`：测试入口后复用
- `AgentFlowChart.tsx`：可压缩展示审核流程

## 6. 阶段测试页

### 页面定位

用户完成当前学习材料后进行测试。测试决定当前阶段正确率，并影响 Agent6 的下一阶段策略。

### 页面区域

- 顶部：阶段信息和答题进度
- 主区域：当前题目
- 右侧或底部：答题卡与提交状态
- 完成后：本阶段正确率与错题反馈

### 题目功能

- 选择题：单选按钮
- 填空题：短输入框
- 判断题：二选一
- 简答题：多行文本框
- 提示：点击后显示 hint
- 答题进度：第 x / n 题
- 已提交状态：显示正确 / 错误
- 正确答案：提交后显示，或阶段结束后统一显示

### 主要按钮

- 上一题
- 下一题
- 显示提示
- 提交本题：调用 `POST /api/stage/submit-answer`
- 重新作答：仅本地重置当前题输入
- 完成测试：所有题提交后调用 `POST /api/stage/complete/{session_id}`
- 返回学习材料

### 按钮启用规则

- 未填写答案时，“提交本题”禁用
- 当前题未提交时，“下一题”可以允许跳过，但答题卡要标记未完成
- 有未提交题目时，“完成测试”禁用或弹确认
- 后端返回 `is_correct` 后，当前题输入锁定

### 对接接口

- `POST /api/stage/submit-answer`
- `POST /api/stage/complete/{session_id}`

### 可复用现有组件

- `TestQuestion.tsx`：现有组件已有题目切换、提示、提交按钮，需要补充“正确/错误反馈”和“完成测试调用”。

## 7. 阶段结果与下一阶段页

### 页面定位

测试完成后，承接 Agent6 的阶段决策结果。这个页面很重要，它把“做题结果”转化为“下一阶段为什么这样安排”。

### 展示内容

- 阶段完成报告：
  - 阶段名称
  - 正确率
  - 当前策略：正常推进 / 降维解释 / 进阶挑战 / 重复巩固
  - 阶段总结
- 画像变化：
  - 更新后的知识盲区进度
  - 信心指数变化
  - 学习节奏变化
  - 困惑标记
- 下一阶段卡片：
  - 阶段编号
  - 下一个子知识点
  - 所属板块
  - 预计时长
  - 前置要求

### 主要按钮

- 开始阶段 N+1：调用 `POST /api/stage/start`
- 复盘错题：回到测试页，只读展示错题与正确答案
- 回看学习材料：回到 `/stage`
- 查看仪表盘：跳转 `/dashboard`
- 结束学习：调用 `PUT /api/session/{session_id}/end`

### 按钮启用规则

- 后端返回 `status=completed` 时，不显示“开始下一阶段”，改为“查看结业报告”
- 后端返回 `status=repeat` 时，按钮文案改为“重新学习本阶段”
- 后端返回 `status=continue` 时，按钮文案为“开始阶段 N+1”

### 对接接口

- `POST /api/stage/complete/{session_id}` 的返回值：
  - `status`
  - `accuracy`
  - `updated_profile`
  - `next_stage`
  - `stage_summary`
  - `next_strategy`
  - `final_report`

## 8. 学习仪表盘

全局学情可视化页面。现有 `Dashboard.tsx` 已有正确率、信心指数、学习节奏、掌握状态分布和知识盲区列表，应继续强化“阶段闭环”的可视化。

### 展示内容

- 总览指标：
  - 当前阶段正确率
  - 信心指数
  - 学习节奏
  - 已掌握知识点数量
- 用户画像：
  - 技能标签
  - 目标
  - 每日学习时长
  - 学习风格
  - 画像置信度
- 图表：
  - 知识盲区雷达图
  - 掌握状态分布图
  - 阶段正确率趋势
  - 各板块进度条
- 学习路径：
  - 已完成阶段
  - 当前阶段
  - 下一阶段
- 问答记录：
  - 最近提问
  - 回答审核状态
- 结业报告：
  - 所有知识盲区掌握后展示

### 主要按钮

- 刷新数据：调用可视化接口
- 继续学习：跳转当前阶段或对话页
- 查看当前阶段：跳转 `/stage`
- 查看问答记录：展开最近 QA 列表

### 对接接口

- `GET /api/visualize/progress/{session_id}`
- `GET /api/session/{session_id}`：补充学习包、QA 历史、答题记录

### 可复用现有组件

- `ProfileCard.tsx`
- `LearningPath.tsx`
- `RadarChart.tsx`

## 9. 设置页

### 页面定位

学习偏好和模型设置管理。现有 `SettingsPage.tsx` 已覆盖每日学习时长、学习风格和模型选择。

### 展示内容

- 学习偏好：
  - 每日学习时长
  - 学习风格：理论型 / 实操型 / 混合型
  - 是否偏好代码实战
  - 是否需要公式推导
- 模型设置：
  - 首选模型
  - API 地址
  - 执行模式：hybrid / deterministic
- 会话设置：
  - 当前 session_id
  - 清除本地 session
  - 新建学习目标

### 主要按钮

- 保存设置：写入 localStorage，后续初始化画像时带入用户输入或请求体
- 重置：恢复默认设置
- 测试后端连接：请求 `/api/session/` 或健康检查接口
- 清除当前学习记录：清空 localStorage 中的 session_id

### 按钮启用规则

- 每日学习时长必须在 0.5 到 8 小时之间
- 后端连接测试进行中时，禁用重复点击

## 10. 会话历史页或侧栏增强

### 页面定位

流程文档提到“另外开一个对话时用户身份从 0 开始，旧对话点击进入后可以保持”。这说明前端需要会话历史能力。

### 当前约束

后端已有单个 session 的创建、读取、结束、放弃接口，但没有“列出历史会话”的接口。因此短期只能用 localStorage 保存最近几个 session_id，长期需要后端增加列表接口。

### 展示内容

- 最近学习目标列表
- 每条记录显示：
  - 学习目标
  - 当前阶段
  - 状态
  - 最后更新时间

### 主要按钮

- 打开：切换到该 session_id
- 新建：创建新 session
- 结束：结束该 session
- 放弃：放弃该 session
- 删除本地记录：仅从 localStorage 移除

### 后端建议补充接口

- `GET /api/session/`：列出会话
- `DELETE /api/session/{session_id}/local-cache` 不需要后端，前端本地处理即可

## 13. 当前代码与设计差距

- `ChatPage.tsx` 已能发送消息、开始阶段、展示学习包，但没有完整展示画像卡片和阶段卡片。
- `ResourceViewer.tsx` 已能展示 Markdown 和代码复制，但没有被 `ChatPage.tsx` 使用。
- `TestQuestion.tsx` 已有答题交互，但没有接入 `apiClient.submitAnswer` 和 `completeStage` 的完整流程。
- `Dashboard.tsx` 已有进度图表，但没有复用 `ProfileCard`、`LearningPath`，也没有展示 QA 历史和阶段结果。
- `SettingsPage.tsx` 目前只存 localStorage，未与后端运行模式或新建 session 流程联动。
- `AgentFlowChart.tsx` 仍可展示“质量评审”节点作为 Agent4 的能力分支，但不应把它标记为独立 Agent5；阶段规划节点应标注为 Agent1 的 `generate_stage`（逻辑 Agent2），状态来源与后端返回字段对齐。

## 14. 建议的前端状态模型

前端应集中维护一个 session 状态：

```ts
type LearningStatus =
  | 'empty'
  | 'diagnosing'
  | 'needs_more_info'
  | 'ready'
  | 'generating_package'
  | 'learning'
  | 'testing'
  | 'stage_result'
  | 'completed'
  | 'abandoned'
  | 'error';
```

核心数据：

- `sessionId`
- `profile`
- `currentStage`
- `learningPackage`
- `messages`
- `qaHistory`
- `answerRecords`
- `reviewHistory`
- `progress`
- `stageResult`
- `error`

这样每个页面都从同一个状态读数据，避免“对话页有学习包、仪表盘又单独拉进度”的断裂。
